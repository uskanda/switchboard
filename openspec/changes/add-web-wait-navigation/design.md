# Design

## Context

1件の表示（`IssuePane`）は、送れたら「送りました」の行へフォーカスを移す。一覧（`InboxList`）は、受信箱の項目を「返答待ち」「実行中」「順番待ち」「完了」に分けて並べる。返答したissueは、エージェントが実行を始めるまで「返答待ち」に残る。キーの操作は、返答の欄のCtrl+Enterと、ペインの境目の矢印キーだけがある。

## Goals / Non-Goals

**Goals:**
- 待ちを選ぶ順と、送った待ちを飛ばす判断を、画面から切り離した関数にして単体で試せるようにする

**Non-Goals:**
- サーバーやAPIを変えること。送った印は、このタブのメモリだけに持つ
- 一覧の並び順を変えること

## Decisions

### 送った印は`lib/sent.ts`にメモリだけで持つ

`lib/drafts.ts`と同じく、ブラウザのストレージには書かない。待ちは項目の`ref`、`waiting_since`、`reason`で見分ける。`watchKey`は使わない。返答のコメントが付くと`updated_at`とコメント数が変わり、同じ待ちを別の待ちと見てしまうためである。Reactの状態にはしない。送った直後に`IssuePane`が`sentAt`で描き直し、一覧の更新でも描き直すので、読むたびに今の値が得られる。

### 選ぶ順は`lib/waits.ts`の純粋な関数にする

`nextWait`は回り込み、送った待ちを飛ばす。`stepWait`は端で止まる。`ignoreKey`はキーを受けないときを見分ける。並びは`InboxList`と同じく、受信箱の項目を`isWaiting`で絞ったものを使う。

### キーは`InboxLayout`で`document`の`keydown`を1つ受ける

一覧と1件のどちらにフォーカスがあってもキーを受けるためである。幅1024px未満の画面でも同じルートの部品なので、同じに動く。`r`は`#reply`へフォーカスを移し、既定の動作を止めて欄に`r`が入らないようにする。

### ダイアログは`dialog[open]`で見分ける

新規issueとマージの確認は、どちらも`<dialog>`で開くためである。

## Risks / Trade-offs

- 一覧が更新されると、送ったあとで「次の待ちへ」の行き先が変わる。→ ボタンの名前へ行き先の題を入れ、押す前に行き先が分かる形にする
- `j`と`k`と`r`のキーが、ほかの操作と重なりうる。→ 修飾キーと一緒のとき、入力中、ダイアログの間は受けない
