# Spec Delta

## MODIFIED Requirements

### Requirement: 送ったあとのフォーカス
返答を送れたとき、WUIは、「次の待ちへ」のボタンを出すならそのボタンへ、出さないなら返答の欄の代わりに出る「送りました」の行へ、フォーカスを移さなければならない（MUST）。「送りました」の行は、フォーカスが無くても読み上げられる状態の表示のまま残す。

#### Scenario: 他に待ちがあるときに返答を送る
- **WHEN** 一覧に別の待ちのissueがある状態で、返答の欄に文を書き、「返答を送る」を押す
- **THEN** フォーカスは「次の待ちへ」のボタンにある

#### Scenario: 返答を送る
- **WHEN** 一覧の待ちがこのissueだけの状態で、返答の欄に文を書き、「返答を送る」を押す
- **THEN** フォーカスは「送りました」で始まる行にある

## ADDED Requirements

### Requirement: 次の待ちへ
返答を送れたとき、行き先の待ちがあるなら、WUIは「送りました」の行の直後に「次の待ちへ」のボタンを出さなければならない（MUST）。ボタンは行き先のissueの題を読み上げさせ、押すとそのissueを開く。行き先が無いなら、ボタンの代わりに「他に待ちはありません」と出す。

#### Scenario: 次の待ちへ進む
- **WHEN** 一覧の「返答待ち」に#12、#13がある状態で、#12に返答を送り、続けてEnterを押す
- **THEN** #13が開く

#### Scenario: 他に待ちが無い
- **WHEN** 一覧の待ちが#12だけの状態で、#12に返答を送る
- **THEN** 画面に「他に待ちはありません」と出て、「次の待ちへ」のボタンは出ない

### Requirement: 次の待ちの行き先
WUIは、一覧の「返答待ち」の節で今のissueの1つ下から順に探して最初に見つかった待ちを、「次の待ち」に選ばなければならない（MUST）。末尾まで来たら先頭に戻って探す。探すときは、今のissueと、このタブで返答を送ったあともその同じ待ちに残っているissueを飛ばす。送ったissueが新しい待ちになったときは飛ばさない。

#### Scenario: 末尾から先頭に戻る
- **WHEN** 一覧の「返答待ち」に#12から#14の3件がある状態で、#14に返答を送る
- **THEN** 次の待ちへのボタンを押すと#12が開く

#### Scenario: 送ったばかりの待ちを飛ばす
- **WHEN** 一覧の「返答待ち」に#12から#14の3件がある状態で、#12に返答を送り、#13を開いて返答を送る。#12は同じ待ちのまま一覧に残っている
- **THEN** 次の待ちへのボタンを押すと#14が開く

### Requirement: 待ちの間を移るキー
`j`か`k`が押されたとき、WUIは、一覧の「返答待ち」の節の中で、今のissueの1つ下（`j`）か1つ上（`k`）のissueを開かなければならない（MUST）。端では止まり、反対の端に戻らない。issueを開いていないときは、`j`で先頭の待ちを開き、`k`で末尾の待ちを開く。実行中や順番待ちや完了のissueは通らない。幅1024px未満の画面でも同じに動く。

#### Scenario: 下の待ちへ移る
- **WHEN** 一覧の「返答待ち」に#12、#13がある状態で#12を開き、`j`を押す
- **THEN** #13が開く

#### Scenario: 端で止まる
- **WHEN** 一覧の「返答待ち」の末尾の#13を開き、`j`を押す
- **THEN** #13が開いたままである

#### Scenario: 実行中のissueを通らない
- **WHEN** 一覧に待ちの#12、実行中の#20、待ちの#13がある状態で#12を開き、`j`を押す
- **THEN** #13が開く

### Requirement: 返答の欄へ移るキー
`r`が押されたとき、返答の欄が出ているなら、WUIは返答の欄にフォーカスを移さなければならない（MUST）。返答の欄が出ていないときは何もしない。

#### Scenario: 返答の欄へ移る
- **WHEN** 待ちのissueを開き、`r`を押す
- **THEN** フォーカスは返答の欄にあり、欄に`r`は入らない

### Requirement: キーを受けないとき
次のどれかに当たるとき、WUIは`j`と`k`と`r`のキー操作をしてはならない（MUST NOT）。

- 入力欄やテキストエリア、選択欄、編集できる要素にフォーカスがある
- 修飾キー（Ctrl、Alt、Meta）と一緒に押された
- ダイアログが開いている

#### Scenario: 返答の欄で`j`を打つ
- **WHEN** 返答の欄に`j`を打つ
- **THEN** 欄に`j`が入り、開いているissueは変わらない

#### Scenario: Ctrlと一緒に押す
- **WHEN** Ctrlを押しながら`j`を押す
- **THEN** 開いているissueは変わらない

#### Scenario: ダイアログが開いている
- **WHEN** 新規issueのダイアログを開いた状態で`j`を押す
- **THEN** 開いているissueは変わらない

### Requirement: キーの案内
幅1024px以上の間、WUIは、一覧のペインの下に「j/k：待ちの間を移る　r：返答の欄へ」の1行を目立たない文字で出さなければならない（MUST）。返答の欄には、`r`のキーを支援技術に伝える属性を付ける。

#### Scenario: 案内の1行
- **WHEN** 幅1024px以上で一覧を開く
- **THEN** 一覧のペインの下に「j/k：待ちの間を移る　r：返答の欄へ」と出る
