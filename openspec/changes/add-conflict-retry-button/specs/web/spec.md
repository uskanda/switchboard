# Spec Delta

## MODIFIED Requirements

### Requirement: 再実行のボタン
理由が `error` か `conflict` の待ちの間、1件の画面は、「再実行する」のボタンを主のボタンとして置かなければならない（MUST）。
「再実行する」を押したとき、1件の画面は、確認を挟まずに、待ちの理由に応じた決まった文だけを返答のPOSTで1回投稿しなければならない（MUST）。理由が `error` なら再実行を頼む文、`conflict` ならbaseとの衝突の解消を頼む文とする。
理由が `error` か `conflict` の待ちの間、1件の画面は、「返答を送る」を副のボタンとして「再実行する」と並べなければならない（MUST）。

#### Scenario: 空の欄で再実行のボタンを押す
- **WHEN** 理由が `error` の待ちのissueで、返答の欄が空のまま「再実行する」を押す
- **THEN** 再実行を頼む決まった文だけが1回、issueへのコメントとして投稿され、「送りました」が表示される

#### Scenario: 衝突の待ちで再実行のボタンを押す
- **WHEN** 理由が `conflict` の待ちのissueで、返答の欄が空のまま「再実行する」を押す
- **THEN** baseとの衝突の解消を頼む決まった文だけが1回、issueへのコメントとして投稿され、「送りました」が表示される

#### Scenario: 欄が空の間は返答を送れない
- **WHEN** 理由が `error` か `conflict` の待ちのissueを、返答の欄が空のまま開いている
- **THEN** 画面の「再実行する」は押せ、「返答を送る」は押せない

### Requirement: 欄に文があるときの再実行のボタン
返答の欄に空白以外の文がある間、1件の画面は、「再実行する」を押せなくしなければならない（MUST）。

#### Scenario: 返答の欄に直し方を書く
- **WHEN** 理由が `error` か `conflict` の待ちのissueで、返答の欄に直し方の文を書き、「返答を送る」を押す
- **THEN** 書いている間「再実行する」は押せず、書いた文がそのままissueへのコメントとして投稿される

### Requirement: 待ちでないときの再実行のボタン
issueが待ちでない間、1件の画面は、「再実行する」を押せるように出してはならない（MUST NOT）。

#### Scenario: 実行中になったissueを開く
- **WHEN** 最後の理由が `error` か `conflict` のissueが、実行中か順番待ちになっている
- **THEN** 画面の「再実行する」は表示されないか、押せない

## ADDED Requirements

### Requirement: 衝突の待ちの案内
理由が `conflict` の待ちの間、1件の画面は、返答の欄の近くに衝突の待ちの案内を示さなければならない（MUST）。
案内は、「再実行する」でもう一度衝突を直させられること、直し方は返答の欄に書いて「返答を送る」で伝えること、どちらでも自動で直す回数を数え直すことを示す。

#### Scenario: 衝突の待ちを開く
- **WHEN** 理由が `conflict` の待ちのissueを1件の画面で開く
- **THEN** 返答の欄の近くに、衝突を自動で直せなかったことと、「再実行する」と「返答を送る」の使い分けと、自動で直す回数を数え直すことを示す案内が表示される
