# grilling 記録: add-web-plan-answers

計画の質問の待ち（`plan-questions`）で、受信箱のWeb表示（`switchboard-web`）から、選択肢を選んで答えられるようにする計画である。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 選択肢を読み取る場所 | WUI（TypeScript）だけで、質問のコメントの文字列から読み取る。核とエージェントの宣言のスキーマは変えない | 第1ラウンド Q1 |
| 選択肢とみなす形 | 行頭のラベル（A〜Zの1文字か数字）を持つ1行ずつの選択肢。ラベルの前に `-`、`*`、`**`、`(` があってもよく、後ろに `:`、`：`、`.`、`)`、`）`、`、`、空白が続く。続いた2つ以上を1組とする。加えて、`範囲: A 全体 / B …` のように1行を `/` か `／` で区切った形も、行頭を見出しとする1組とする。1問に何組あってもよい | 第1ラウンド Q2 |
| 既定で選ぶ推奨案 | 組ごとに、推奨の文に最初に出てくるその組のラベル。英字や数字に挟まれたものは数えない。見つからなければ選ばない | 第1ラウンド Q3 |
| 選び方 | ラジオボタン。1組で1つだけ選べる | 第1ラウンド Q4（`/ok q5.ラジオボタンで` を、確認のうえQ4への答えとした） |
| 選択肢を読み取れなかった問い | 本文と推奨をそのまま見せ、自由記述の欄だけを付ける | 第1ラウンド Q5 |
| 選択肢と自由記述の置き場所 | スレッドの中の、最新の `plan-questions` のコメントのカードの中。問いごとに、本文、選択肢、自由記述の欄、推奨の順に描く。古い質問のコメントは改行を残して表示するだけにする。「この内容で返答」は返答の欄に置く | 第1ラウンド Q6 |
| 改行の扱い | すべての本文とコメントで、1つの改行を改行として描く（GitHubと同じ） | 第1ラウンド Q7 |
| 返答の文の書式 | 承認の語を付けず、すべての問いの答えを1行ずつ書く。自由記述は選んだ選択肢の後ろに `補足：` として付ける | 第1ラウンド Q8 |
| 今の返答の欄との関係 | 今の返答の欄と「返答を送る」を残し、「この内容で返答」を足す。「この内容で返答」は、選択と問いごとの自由記述に、返答の欄の文を全体への補足として加えて送る | 第1ラウンド Q9 |
| 送る前の確認 | ボタンの上に、送る文を読み取り専用で表示し、選択に合わせて書き換える | 第1ラウンド Q10 |
| 答えの無い問い | `Q2 <題>: 回答なし` と書く | 第1ラウンド Q11 |
| 計画の実行の指示 | 「選択肢は1行に1つ、`A:` のようにラベルを付けて書く」という1文を足す。WUIの読み取りの幅は変えない | 第1ラウンド Q12 |
| どれも選ばないときの表し方 | 組ごとに、最後のラジオボタンとして「選ばない（補足で答える）」を足す。推奨のラベルが見つからない組は、これを選んだ状態で始める | 第2ラウンド Q13 |
| 1行の答えの書き方 | 番号と問いの題とラベル（`Q1 操作の入口: C`）。組が2つ以上ある問いは、組の見出しを付けて並べる（`範囲はA、欄はX`） | 第2ラウンド Q14 |
| 計画の質問の待ちでの案内 | ボタンでの答え方の案内に置き換え、`/ok` には触れない | 第2ラウンド Q15 |
| 質問への `/ok` が古い計画の承認になる問題 | この変更には含めず、別のissueにする。この変更の返答の文は `/ok` で始まらない | 第2ラウンド Q16 |
| 選んだ状態を残す範囲 | 同じ質問のコメントを表示している間は、自動更新があっても選択と自由記述を残す。次のラウンドの質問のコメントが届いたら初めからにする。返答の欄の書きかけは今までどおり残す | 第2ラウンド Q17 |

## 後回しにしたもの

- 計画のコメントのあとに質問のコメントが出たとき、その質問への `/ok` を前の計画の承認として数えてしまう問題（第2ラウンドQ16。エージェントの計画の段階の判定を直す別の変更にする）
- エージェントの宣言のスキーマで、選択肢を構造として持つこと（第1ラウンドQ1）
- 文中の `(A)…(B)…` のような形の選択肢の読み取り（第1ラウンドQ2）
