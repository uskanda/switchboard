# Design

## Context

動機はproposal.mdに、判断はgrilling.mdにある。設計の前提になる今の形は、次のとおりである。

- 質問のコメントは、エージェントが `internal/agent/planrun.go` の `planQuestions` で組み立てる。見出し（`### 計画についての質問`）、まとめ、問い、末尾の順に、空行で区切って並ぶ。問いは、見出しの行、本文、推奨の順に並び、問いと問いの間は `---` である。見出しの行は、疑問符の絵文字、太字の `Qn`、`-`、太字の題からなる。推奨は矢印の絵文字で始まる。末尾は、変更を捨てたことの注意と拒否された操作と、答え方の案内の1行である。枠はswitchboardが書くが、本文と推奨の中身はLLMが書く
- 1件の詳細のコメントは、`inboxapi.Comment` として届く。エージェントの投稿の本文はマーカーを除いたもので、`kind` はマーカーの `state` だけを持ち、`reason` は持たない。今の待ちの理由は、詳細の `reason` にある
- `Markdown.tsx` は `react-markdown` と `remark-gfm` に、生のHTMLを文字にする手書きの処理 `rawHTMLAsText` を足して描く。1つの改行は、mdastでは `text` の値の中の `\n` のまま残り、画面では空白になる
- `IssuePane.tsx` は返答の書きかけ、送信中、送信済みの状態を持ち、`Thread.tsx` にスレッドを描かせる。返答は `postReply` で `switchboard-web` の返答のPOSTに送る

## Goals / Non-Goals

**Goals:**

- 質問のコメントの書き方が少し違っても、問いを読み取れれば選んで答えられる。読み取れなければ、今と同じ表示と返答の欄に戻る
- 核、`inboxapi`、`switchboard-web` のサーバーを変えずに済ませる

**Non-Goals:**

- 文中の `(A)…(B)…` の形の選択肢の読み取り（grilling第1ラウンドQ2）
- 1組で複数を選ぶこと（第1ラウンドQ4）
- 計画のコメント（理由 `plan`）への答え方の変更
- 質問への `/ok` を前の計画の承認として数える問題（第2ラウンドQ16。別のissueにする）

## Decisions

### 1. 読み取りと返答の文の組み立てを、副作用の無い関数にする

`web/ui/src/lib/<planQuestions.ts>` に、次の関数を置く。どれも文字列と値だけを扱い、Reactに依存しない。テストはVitestで、実際の質問のコメント（`uskanda/smarternews#80` のもの）を入力にして書く。

- `parsePlanQuestions(body)`：コメントの本文から、問いより前の部分（`head`）、問いの配列、問いより後の部分（`tail`）を返す。問いが1つも無ければ `null` を返す
- `defaultAnswers(questions)`：問いごと、組ごとの既定の選択を返す
- `composeReply(questions, answers, overall)`：送る文を返す

問いは `{ n, title, parts, recommendation }` とし、`parts` は本文を文の部分と選択肢の組に分けたものの並びとする。組は `{ heading?, options: { label, text }[] }` とする。

代わりに、核の `inbox serve` で読み取って `inboxapi` で渡す形も考えた。表示のためだけにAPIを広げることになるので、採らない（第1ラウンドQ1）。

### 2. 問いの区切り方

- 問いの始まりは、問いの見出しの行とする。絵文字の後ろの異体字セレクタの有無と、区切りの `-`、`–`、`—` の揺れは許す
- 問いの本文は、始まりの次の行から、矢印の絵文字で始まる行の前までとする
- 推奨は、矢印の絵文字を除いた、その行から続く文とする。最後の問いでなければ、`---` の行の前まで続く。最後の問いでは、推奨の最初の空行で切り、その後ろを `tail` にする。末尾の案内と拒否された操作を推奨に含めないためである
- 矢印の行が無い問いは、推奨を空とし、本文は次の問いの始まりか `---` の行の前まで続く

### 3. 選択肢の組の読み取り

本文を行に分け、コードのブロック（` ``` ` か `~~~` の行で囲まれた部分）の外の行だけを見る。

- 1行ずつの形：行頭のラベルの前後の揺れ（specsの「選択肢の組の読み取り」）を許して、ラベルと文に分けられる行を、選択肢の行とする。続いた選択肢の行のうち、ラベルが同じ種類で1つずつ増える並びを1組にする。並びが2つ以上のときだけ組とし、1つだけなら文の行に戻す
- 1行を区切った形：行頭の `^([^:：]{1,20})[:：]\s*` を見出しの候補として外し、残りを `\s*[/／]\s*` で区切る。区切ったものが2つ以上で、それぞれが `^([A-Z]|\d+)(?:[:：.、)）]|\s)\s*(.+)$` に合い、ラベルが1つずつ増えるとき、1組とする
- 1行ずつの形の組の見出しは無しとする。直前の行が `:` か `：` で終わるときは、その語を見出しにする

ラベルが1つずつ増えることを求めるのは、`A user …` と `I think …` のような英文の行頭を、選択肢と取り違えないためである。番号付きの箇条書き（`1.`、`2.`）は組として読み取られるが、「選ばない」と送る前の表示で避けられる。

### 4. 推奨からの既定の選択

組ごとに、推奨の文を先頭から見て、前後が英数字でない位置で最初に出てくる、その組のラベルを選ぶ。どの組のラベルにも合わなければ、その組は「選ばない」にする。全角の英字は数えない。

### 5. 改行の描き方

`Markdown.tsx` に、`text` のノードの値を `\n` で区切り、間に `break` のノードを挟む処理を足す。`inlineCode` と `code` は値を持つが `text` ではないので、変わらない。`remark-breaks` は同じことをするが、依存を足さずに手書きの処理にする。今の `rawHTMLAsText` と同じ置き方で、`rawHTMLAsText` より後に動かす。生のHTMLから文字に変えた値の中の改行も、改行として描くためである。

### 6. 描く場所と状態の持ち方

- 選択の状態は `IssuePane` が持つ。`Thread` は、描くコメントの番号と、そのコメントを描く部品を受け取る。返答の欄の「この内容で返答」が、同じ状態から送る文を作るためである
- 対象のコメントは、詳細の `waiting` が真で `reason` が `plan-questions` のときの、エージェントの最新の `kind=waiting` のコメントとする。読み取りが `null` なら、今までどおりMarkdownで描く
- 状態は、対象のコメントの `created_at` と本文を合わせた鍵と組にして持つ。鍵が変わったら（次のラウンド）、`defaultAnswers` で初めからにする。鍵が同じなら、自動更新で詳細を取り直しても状態を残す（第2ラウンドQ17）
- 新しい部品 `<PlanQuestions.tsx>` は、`head` と `tail` をMarkdownで描き、問いごとに題、本文の文の部分（Markdown）、組、自由記述の欄、推奨を描く。組は `fieldset` と `legend`（見出しか「Qnの選択肢」）で囲み、選択肢と「選ばない（補足で答える）」を `input type="radio"` と `label` で並べる。押せる高さは、ほかの欄と同じく44px以上にする。選択肢の文はMarkdownの部品で描く

- 答えるために描く質問のコメントでは、`tail` から、承認の語で答えるよう案内するエージェントの段落を除く（`withoutAnswerHint`）。案内の文は `internal/agent/messages.go` の `planQuestionsHint` の2つの言語のものに合わせる。WUIでは選んで答えるので、この案内は第2ラウンドQ15と食い違う
- 返答の欄の送り方は、`DESIGN.md` の「塗りのボタンは1画面に1つ」に従う。問いを読み取れたときは「この内容で返答」を `button-primary` にし、「返答を送る」を `button-secondary` にする。送る文の表示は、ボタンの上に `surface` の地と `outline` の枠で置く

### 7. 返答の文と送信

`composeReply` は次の形の文を返す。

```
Q1 操作の入口: C
Q2 選んだあとの流れ: B。補足：件数は出さない
Q3 ダイアログの既定値: 範囲はA、欄はY
Q5 アプリの扱い: 回答なし

全体への補足：
<返答の欄の文>
```

- 見出しの無い組が2つ以上あるときは、ラベルを `、` でつなぐ
- 自由記述と返答の欄の文は、前後の空白を除いてから使う。空なら付けない
- 送信は `postReply` を使い、成功したら今の「返答を送る」と同じく、送信済みの表示にし、返答の欄の文を消す

### 8. 計画の実行の指示

`internal/prompt/prompt.go` の `PlanSystem` で、`status "questions"` の行に1文を足す。文は `Put each option of a question on its own line, labeled like "A: ...".` とする。`prompt_test.go` で、その文が入ることを確かめる。

## Risks / Trade-offs

- LLMが別の書き方で選択肢を書くおそれがある。読み取れなかった問いは自由記述だけになり、返答の欄も残るので、答えられなくなることは無い。指示の1文で書き方を揃える
- 番号付きの箇条書きを、選択肢と取り違えるおそれがある。組の最後の「選ばない」と、送る前の表示で避けられる
- 推奨の文で、結論より前にほかのラベルが出ると、既定の選択が推奨と違ってしまう。送る前の表示で見て直せる
- エージェントが質問のコメントの枠を変えると、読み取りが `null` になり、今の表示に戻る。枠を変えるときは `<planQuestions.ts>` のテストも直す
