# Proposal

## Why

計画の質問の待ち（`plan-questions`）に答えるとき、受信箱のWeb表示（WUI）では、問いと選択肢を読んでから、`/ok q2はB` のような文を手で書いている。WUIはMarkdownの1つの改行を空白として描くので、1行ずつ書かれた選択肢がつながって1段落になり、読みにくい。スマホで問いの番号とラベルを打つのも手間がかかる。問いごとに選択肢を選んで答えられるようにする。

## What Changes

- WUIは、本文とコメントのMarkdownで、1つの改行を改行として描く（GitHubと同じ）
- WUIは、最新の計画の質問のコメントから、問い、選択肢、推奨を読み取る。問いは `Qn` の見出しで、推奨は矢印の段落で見分ける。選択肢の書き方はLLM任せなので、1行ずつの形と1行を `/` で区切った形を広く受け付け、1問に何組あってもよい
- そのコメントのカードの中では、選択肢の組をラジオボタンで描く。組の最後には「選ばない（補足で答える）」を足す。問いの最後の組の下には自由記述の欄を置く。既定では、推奨の文で最初に出てくるラベルを選ぶ。選択肢を読み取れなかった問いでは、自由記述の欄だけを付ける
- 返答の欄に「この内容で返答」のボタンを足す。選択と自由記述と返答の欄の文を、問いごとに1行の返答の文（`Q1 操作の入口: C。補足：…`）にして、issueへのコメントとして送る。送る文は、ボタンの上に読み取り専用で表示する。返答の文は承認の語で始めない
- 計画の質問の待ちでの案内を、ボタンでの答え方の案内に置き換える
- 計画の実行の指示に、選択肢を1行に1つ、ラベルを付けて書くよう1文を足す

## Capabilities

### New Capabilities

- なし

### Modified Capabilities

- `web`: スレッドの改行の描き方、計画の質問の選択肢と自由記述の欄、返答の文の組み立てと送信、計画の質問の待ちでの案内
- `plan-mode`: 計画の実行の指示に、選択肢の書き方を足す

## Impact

- `web/ui`：質問のコメントの読み取りと返答の文の組み立てを `src/lib` に足す。改行の処理は `Markdown.tsx`、質問のカードは `Thread.tsx` と新しい部品、ボタンは `IssuePane.tsx` で扱う
- `internal/prompt`：計画の実行のsystem promptに1文を足す
- 核の受信箱のサービス、`inboxapi`、`switchboard-web` のサーバーは変えない。返答は今の返答のPOSTで送る
- 依存は足さない。改行の処理は、今の `rawHTMLAsText` と同じく、手書きのremarkの処理にする
- 計画のコメントのあとに出た質問への `/ok` を前の計画の承認として数える問題は、この変更に含めず、別のissueにする
