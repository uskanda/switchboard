## MODIFIED Requirements

### Requirement: 計画の待ちの表示
一覧の画面と1件の画面は、待ちの理由 `plan-questions` と `plan` を、ほかの理由と同じく理由として表示しなければならない（MUST）。
理由が `plan` のとき、1件の画面は、返答の欄の近くに、承認の語を送れば承認になることを示さなければならない（MUST）。
理由が `plan-questions` で問いを読み取れたとき、1件の画面は、返答の欄の近くに答え方を示さなければならない（MUST）。答え方とは、問いごとに選んで「この内容で返答」を押すことと、返答の欄の文が全体への補足として加わることをいう。
理由が `plan-questions` で問いを読み取れなかったとき、1件の画面は、返答の欄の近くに、問いごとの答えを返答の欄に書いて送るよう示さなければならない（MUST）。
理由が `plan-questions` のとき、1件の画面は、承認の語で答えるよう勧めてはならない（MUST NOT）。

#### Scenario: 計画の承認待ちを開く
- **WHEN** 理由が `plan` の待ちのissueを1件の画面で開く
- **THEN** 計画の全文と、`/ok` を送れば承認になることが表示される

#### Scenario: 計画の質問の待ちを開く
- **WHEN** 理由が `plan-questions` の待ちのissueを1件の画面で開く
- **THEN** 返答の欄の近くに、選んで「この内容で返答」を押す答え方が表示され、`/ok` を送るよう勧める文は表示されない

### Requirement: スレッドの表示
1件の表示は、issueの本文とコメントを、古い順に表示しなければならない（MUST）。
1件の表示は、本文とコメントをMarkdownとして描かなければならない（MUST）。生のHTMLは描かずに文字として出し、画像は読み込まずにリンクとして出す。
1件の表示は、本文とコメントの段落の中の1つの改行を、改行として描かなければならない（MUST）。
1件の表示は、本文とコメントの中のHTMLのコメント（`<!--` から `-->` まで）を表示してはならない（MUST NOT）。
1件の表示は、エージェントの投稿に、エージェントのものであることを示す印を付けなければならない（MUST）。
1件の表示は、エージェントの着手のコメントを1行に畳み、進捗のコメントは最新の1件だけを表示しなければならない（MUST）。
1件の表示は、エージェントの投稿のマーカーを表示してはならない（MUST NOT）。
issueから来たリンクは、新しいタブで開き、参照元を送ってはならない（MUST NOT）。

#### Scenario: 本文にHTMLと画像がある
- **WHEN** 本文が `<img src=x onerror=alert(1)>` と、Markdownの画像 `![a](https://example.com/a.png)` を含むissueを開く
- **THEN** `<img` の文字列がそのまま表示され、画像は読み込まれずにリンクとして出る

#### Scenario: 本文にissueのテンプレートのコメントがある
- **WHEN** 本文が `<!-- 再現の手順を書く -->` と、その下の文を含むissueを開く
- **THEN** `<!--` で始まるコメントは出ず、その下の文だけが出る

#### Scenario: 着手と進捗のコメントがある
- **WHEN** 着手のコメント1件、進捗のコメント2件、人のコメント1件があるissueを開く
- **THEN** 着手のコメントは1行で出て、進捗のコメントは新しい1件だけが出て、人のコメントはそのまま出る

#### Scenario: 選択肢を1行ずつ書いたコメント
- **WHEN** 空行を挟まずに `A: 右クリックだけ` と `B: 選択メニューだけ` の2行が続くコメントを開く
- **THEN** 2つの選択肢は1段落につながらず、別の行に表示される

## ADDED Requirements

### Requirement: 計画の質問の読み取り
理由が `plan-questions` の待ちの間、1件の表示は、最新の待ちのコメントから問いを読み取らなければならない（MUST）。問いは、行頭の `❓` に続く太字の `Qn` と太字の題で始まる。1件の表示は、問いを番号と題と本文と推奨に分ける。推奨は、問いの中の `➡️` で始まる段落である。
問いを1つも読み取れなかったとき、1件の表示は、そのコメントを、ほかのコメントと同じく描かなければならない（MUST）。
最新でない質問のコメントについて、1件の表示は、選択肢と自由記述の欄を付けてはならない（MUST NOT）。
問いを読み取った質問のコメントで、1件の表示は、承認の語で答えるよう案内するエージェントの段落を表示してはならない（MUST NOT）。

#### Scenario: 6つの問いのコメント
- **WHEN** Q1からQ6を `---` で区切って並べた質問のコメントで待っているissueを開く
- **THEN** 6つの問いが、それぞれの番号、題、本文、推奨とともに表示される、コメントの最後の `/ok` で答えるよう案内する段落は表示されない

#### Scenario: 前のラウンドの質問
- **WHEN** Q1からQ3のコメントのあとに、Q4とQ5のコメントで待っているissueを開く
- **THEN** 選択肢と自由記述の欄は、Q4とQ5にだけ付く

### Requirement: 選択肢の組の読み取り
1件の表示は、問いの本文の中で、行頭にラベルを持つ行が2つ以上続くとき、それを1組の選択肢として読み取らなければならない（MUST）。
ラベルは、A〜Zの1文字か、1桁以上の数字とする。ラベルの前には `-`、`*`、`+` の箇条書きの印と空白、`**`、`(` があってもよく、ラベルの後ろには `)`、`）`、`**` のあとに、`:`、`：`、`.`、`、`、空白のどれかが続く。1組のラベルは、同じ種類（英字か数字）で、`A`、`B`、`C` や `1`、`2`、`3` のように1つずつ増えなければならない（MUST）。
1件の表示は、1行を `/` か `／` で区切り、区切ったそれぞれがラベルで始まるとき、その行を1組の選択肢として読み取らなければならない（MUST）。行頭の、`:` か `：` で終わる語を、その組の見出しとする。
1件の表示は、1つの問いの中の組を、いくつでも読み取らなければならない（MUST）。
コードのブロックの中の行を、1件の表示は、選択肢として読み取ってはならない（MUST NOT）。

#### Scenario: 1行ずつの選択肢
- **WHEN** 本文に `A: 右クリックだけ。`、`B: いまの選択メニュー。`、`C: AとBの両方。` の3行がある問いを開く
- **THEN** A、B、Cの3つの選択肢の組が表示される

#### Scenario: 1行に2組
- **WHEN** 本文に `範囲: A 全体 / B 購読フィード / C カテゴリ` と `欄: X タイトルと内容 / Y タイトルだけ` の2行がある問いを開く
- **THEN** 見出しが「範囲」の組と「欄」の組が表示される

#### Scenario: 英文の行頭
- **WHEN** 本文に `A user opens the page.` と `I think it is fine.` の2行が続く問いを開く
- **THEN** ラベルが1つずつ増えていないので、選択肢の組として読み取られない

### Requirement: 選択肢の描き方
1件の表示は、読み取った組の選択肢を、1行に1つずつ、ラジオボタンとして描かなければならない（MUST）。1組の中で選べるのは1つだけとする。
1件の表示は、組ごとに、最後のラジオボタンとして「選ばない（補足で答える）」を足さなければならない（MUST）。
1件の表示は、問いの最後の組の下に、その問いの自由記述の欄を置かなければならない（MUST）。組を読み取れなかった問いでは、本文の下に自由記述の欄だけを置く。
選択肢の文は、ほかのissueの文字列と同じく、HTMLとして解釈させてはならない（MUST NOT）。

#### Scenario: 組を読み取れなかった問い
- **WHEN** 本文に選択肢の組が無い問いを開く
- **THEN** 本文と推奨がそのまま表示され、自由記述の欄だけが付く

### Requirement: 推奨の既定の選択
1件の表示は、組ごとに、推奨の文で最初に出てくるその組のラベルを、既定で選ばなければならない（MUST）。英字か数字に挟まれた文字は、ラベルとして数えない。
推奨の文にその組のラベルが無いとき、1件の表示は、その組の「選ばない（補足で答える）」を既定で選ばなければならない（MUST）。

#### Scenario: 理由の中でほかの案に触れる
- **WHEN** 推奨が「A。全文を表示するのが普通なので、Bでは使える場面が減ります」である問いを開く
- **THEN** Aが選ばれた状態で表示される

#### Scenario: 2組の推奨
- **WHEN** 推奨が `範囲はA（全体）、欄はX（タイトルと内容）。` で、組が「範囲」と「欄」の問いを開く
- **THEN** 範囲の組ではA、欄の組ではXが選ばれた状態で表示される

#### Scenario: 推奨にラベルが無い
- **WHEN** 推奨が「APIの名前は今のままにします」で、組がAとBである問いを開く
- **THEN** その組では「選ばない（補足で答える）」が選ばれた状態で表示される

### Requirement: 選択の保持
同じ質問のコメントを表示している間、WUIは、自動更新で表示を書き換えても、選択と自由記述の欄の書きかけを消してはならない（MUST NOT）。
新しい質問のコメントで待つようになったとき、WUIは、選択と自由記述の欄を、新しい問いの既定の状態から始めなければならない（MUST）。

#### Scenario: 選んでいる途中で自動更新が来る
- **WHEN** Q2でBを選び、自由記述を書いている途中で、そのissueの一覧の行が変わる
- **THEN** Bの選択と自由記述の書きかけは残る

### Requirement: 返答の文
1件の表示は、問いを読み取れたとき、返答の欄に「この内容で返答」のボタンを置かなければならない（MUST）。今の返答の欄と「返答を送る」のボタンは残す。
「この内容で返答」が送る文は、問いごとに1行、`Q<番号> <題>: <答え>` の形でなければならない（MUST）。答えは、選んだラベルとする。2組以上の問いでは、見出しのある組を `<見出し>は<ラベル>` として、`、` でつなぐ。自由記述があれば、そのあとに `。補足：<自由記述>` を付ける。どの組でもラベルを選ばなかった問いでは、自由記述だけを答えとする。
選んだラベルと自由記述のどちらも無い問いの答えは、`回答なし` でなければならない（MUST）。
返答の欄に文があるとき、「この内容で返答」が送る文は、問いの行のあとに、その文を全体への補足として含まなければならない（MUST）。
「この内容で返答」が送る文は、承認の語で始まってはならない（MUST NOT）。
1件の表示は、「この内容で返答」のボタンの上に、送る文を読み取り専用で表示し、選択と自由記述の変化に合わせて書き換えなければならない（MUST）。

#### Scenario: 推奨と違う案を選んで補足を書く
- **WHEN** Q1の推奨のCを残し、Q2でBを選んで自由記述に「件数は出さない」と書く
- **THEN** 送る文は `Q1 操作の入口: C` と `Q2 選んだあとの流れ: B。補足：件数は出さない` の2行になる

#### Scenario: 2組の問い
- **WHEN** 組が「範囲」と「欄」のQ3で、範囲はA、欄はYを選ぶ
- **THEN** 送る文のQ3の行は `Q3 ダイアログの既定値: 範囲はA、欄はY` になる

#### Scenario: 何も選ばず何も書かない
- **WHEN** Q5のすべての組で「選ばない（補足で答える）」を選び、自由記述を空のままにする
- **THEN** 送る文のQ5の行は `Q5 <題>: 回答なし` になる

### Requirement: 返答の文の送信
「この内容で返答」が押されたとき、`<switchboard-web>` は、送る文を、今の返答と同じ返答のPOSTで、issueへのコメントとして投稿しなければならない（MUST）。
そのissueが待ちでないとき、1件の表示は、「この内容で返答」を押せなくしなければならない（MUST）。

#### Scenario: この内容で返答する
- **WHEN** 計画の質問の待ちのissueで、「この内容で返答」を押す
- **THEN** 表示されていた送る文が、そのままissueのコメントとして投稿され、送ったことが表示される

#### Scenario: 選んでいる途中で待ちでなくなる
- **WHEN** 選んでいる途中で、フォージから別の返答が届いて、そのissueが待ちでなくなる
- **THEN** ボタン「この内容で返答」は押せなくなり、待ちでなくなったことが示される
