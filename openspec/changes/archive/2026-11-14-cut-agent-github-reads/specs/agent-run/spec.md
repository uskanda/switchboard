# Spec Delta

## MODIFIED Requirements

### Requirement: 評価のやり直し
issueの評価がエラー、キュー待ち、ロック中のどれかで終わったとき、エージェントは、そのissueを後のポーリングで評価し直さなければならない（MUST）。
同じプロジェクトの別のissueを評価できても、評価の終わっていないissueは、評価し直す対象から外れない。
キュー待ちで終わったissueは、フォージの一覧での更新の時刻が、キュー待ちと決めたときの更新の時刻より後のときだけ、ポーリングと中継の取り直しで評価し直さなければならない（MUST）。更新の時刻が変わらないキュー待ちのissueを、エージェントはポーリングと中継の取り直しで読み直してはならない（MUST NOT）。枠が空いて順番待ちから取り出すときは、そのissueを読み直してから実行を始める。

#### Scenario: キューの消化で一時的に失敗した
- **WHEN** `max_parallel: 1` の端末で、1つ目の実行の間に2つ目のissueに `agent:ready` が付き、同じプロジェクトの別のissueも更新される。1つ目が終わって2つ目を取り出すとき、フォージへの要求が1回失敗する
- **THEN** 次のポーリングで2つ目のissueが評価し直され、`agent:running` になる

#### Scenario: ポーリングで一時的に失敗した
- **WHEN** 1回のポーリングで、issue 3の評価がフォージの502で失敗し、issue 3より1分以上後に更新されたissue 4の評価は成功する
- **THEN** 次のポーリングでissue 3が評価し直される

#### Scenario: 変化の無い順番待ちのissue
- **WHEN** `max_parallel: 1` の端末で1つの実行が動き、80件のissueが順番待ちになっている。どのissueも更新されないまま、ポーリングと中継の取り直しが続く
- **THEN** エージェントは、そのポーリングと取り直しで、順番待ちのissueを1件も読まない

#### Scenario: 順番待ちのissueのラベルを外す
- **WHEN** 順番待ちのissueから、マスターが `agent:ready` を外す
- **THEN** フォージの一覧でそのissueの更新の時刻が動くので、次のポーリングでそのissueを評価し、順番待ちから外す

## ADDED Requirements

### Requirement: API制限の間の読み取り
フォージがAPI制限で要求を断ったとき、エージェントは、応答が示すリセットの時刻まで、そのフォージのクライアントで読み取りを送ってはならない（MUST NOT）。止める読み取りは、ポーリング、評価、順番待ちの取り出し、CIの監視のためのものである。応答にリセットの時刻が無いときは、1分後をリセットの時刻とする（V61）。
エージェントは、API制限に入ったときと、リセットの時刻を過ぎて読み取りを再開したときに、それぞれ1回ずつログに残さなければならない（MUST）。
API制限の間に始められなかった評価と書き戻しは、評価のやり直しと書き戻しの再試行の対象として残る。

#### Scenario: 枠が尽きる
- **WHEN** 1回のポーリングの途中で、GitHubが403と `X-Ratelimit-Remaining: 0`、30分後の `X-Ratelimit-Reset` を返す
- **THEN** エージェントはそのポーリングの残りのGitHubへの読み取りをやめ、30分の間はGitHubのプロジェクトをポーリングしない。ログには制限に入ったことが1回だけ残る

#### Scenario: リセットのあと
- **WHEN** API制限の間に、順番待ちのissueと、評価に失敗したissueがある。リセットの時刻を過ぎる
- **THEN** 次のポーリングでGitHubの読み取りを再開し、評価に失敗したissueを評価し直す。ログには再開したことが1回だけ残る

#### Scenario: ほかのフォージ
- **WHEN** GitHubがAPI制限の間に、GitLabのプロジェクトのissueに `agent:ready` が付く
- **THEN** GitLabのプロジェクトは今までどおりポーリングされ、そのissueの実行が始まる
