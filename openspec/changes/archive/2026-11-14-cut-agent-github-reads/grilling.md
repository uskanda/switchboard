# grilling 記録: cut-agent-github-reads

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 主な対策 | 検索の `updated_at` が前に読んだときから動いていない順番待ちのissueは、ポーリングと中継の取り直しで読み直さない。枠が空いたときは、今までどおり `drain` が読み直してから始める。人の操作（ラベルを外す、closeする）は `updated_at` を動かすので、今までどおり次のポーリングで評価する。 | 第1ラウンド Q1 |
| `Thread` と `LabelActor` の条件付きリクエスト | この変更では付けない。直したあとに測り直し、必要なら別の変更にする。 | 第1ラウンド Q2 |
| API制限を受けたあと | `RateLimitError` を受けたら、そのフォージ（トークン）について、リセットの時刻までポーリング、評価、`drain` で読みに行かない。ログは制限に入ったときと抜けたときに1回ずつ残す。書き戻しの再試行は、今の仕組みのまま後に回る。 | 第1ラウンド Q3 |
| 順番待ちのコメントによる1回の読み直し | 受け入れる。新しく順番待ちになったissueは、自分の投稿で `updated_at` が動くので、次のポーリングで1回だけ読み直す。 | 第1ラウンド Q4 |
| 起動したときの順番待ちのコメント | この変更では扱わない。 | 第1ラウンド Q5 |
| 回帰テスト | 測定に使ったテストを、上限を確かめるテストとして残す。測った数字はROADMAPの検証項目V64に記録する。 | 第1ラウンド Q6 |
| 決定の記録と変更の名前 | ADR-072を足す。変更の名前は `cut-agent-github-reads`。 | 第1ラウンド Q7 |

第1ラウンドの答えは、利用者が `/ok` で、すべて推奨どおりに確定した。

## 後回しにしたもの

- `Thread` のコメントの読み取りと `LabelActor` へのETagの適用（第1ラウンドのQ2）。直したあとに測り直してから決める。
- 起動したときに順番待ちのコメントを全部消して投稿し直すこと（第1ラウンドのQ5）。80件なら削除80回と投稿80回で、GitHubの投稿の二次的な制限に近い。要件の変更を伴う。
- 中継の `hooks` にGitHubのプロジェクトを載せること。本番では `gh:uskanda/smarternews` が30秒ごとのポーリングで読まれている。これは利用者の設定の話で、製品の変更ではない。
