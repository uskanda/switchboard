# grilling 記録: add-project-max-parallel

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| grillingの省略 | 省略する。理由：決める論点を会話中に推奨とともに提示し、ユーザーが変更なしで `/no-grilling` を実行した | ユーザーの指示（会話中に確認） |
| q1 設定の形 | 全体の上限は `<agent.max_parallel>` のまま残し、`<projects[].max_parallel>` を足す。書いていないプロジェクトは全体の上限だけで制限する | 会話中に提示した推奨。ユーザーは変更しなかった |
| q2 全体の既定値 | 1のまま据え置く。サブスクリプションの利用上限への配慮（phase1のdesign.md）を引き継ぐ | 会話中に提示した推奨。ユーザーは変更しなかった |
| q3 順番待ちからの取り出し | 上限に達したプロジェクトのissueは飛ばし、ほかのプロジェクトのissueを先に実行する。順番は今の名前順のまま | 会話中に提示した推奨。ユーザーは変更しなかった |
| q4 反映のしかた | 全体の上限とプロジェクトの上限は、どちらも設定の読み直しで反映する。上限を下げても、動いている実行は止めない | 会話中に提示した推奨。ユーザーは変更しなかった |
| q5 プロジェクトの上限が全体を超えるとき | 誤りにせず受け付ける。実際の上限は全体の値になる | 会話中に提示した推奨。ユーザーは変更しなかった |
