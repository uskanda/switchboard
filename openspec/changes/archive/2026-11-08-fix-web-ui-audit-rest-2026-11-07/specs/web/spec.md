## ADDED Requirements

### Requirement: 画面を移ったときのスクロールの位置
別の1件を開いたとき、WUIは、その1件を先頭から表示しなければならない（MUST）。返答の対象のカードへのスクロールは、その後に行う。
幅1024px未満で1件から一覧へ戻ったとき、WUIは、一覧を離れたときのスクロールの位置に戻さなければならない（MUST）。

#### Scenario: スクロールした一覧から1件を開いて戻る
- **WHEN** 幅390pxで一覧を下までスクロールし、1件を開き、「← 一覧へ」で戻る
- **THEN** 1件は先頭から表示され、一覧は離れたときの位置で表示される

### Requirement: 作成中の新規issueのダイアログ
作成の応答を待つあいだ、WUIは、新規issueのダイアログをEscapeで閉じてはならない（MUST NOT）。応答が届いた後は、Escapeで閉じられる。

#### Scenario: 作成中にEscapeを押す
- **WHEN** 作成のボタンを押し、応答が届く前にEscapeを押す
- **THEN** ダイアログは開いたままで、作成が失敗したときは誤りがダイアログの中に出る

### Requirement: 作ったばかりのissueの1件の表示
このタブで作り、エージェントがまだ取りかかっていないissueを開いたとき、WUIは、作ったばかりであることの文を出さなければならない（MUST）。文は`作ったばかりのissueです。エージェントが取りかかると、この画面が自動で切り替わります`とする。
WUIは、そのissueに、一覧から消えたことの文と、返答を送れないことの文を出してはならない（MUST NOT）。

#### Scenario: 作った直後の行を開く
- **WHEN** 開始ラベル付きのissueを作り、一覧の「処理中」の行を開く
- **THEN** 作ったばかりであることの文が出て、一覧から消えたことの文は出ない

### Requirement: 設定の画面の誤りと権限
設定の画面の読み直しが成功したとき、WUIは、前の読み込みの誤りを消さなければならない（MUST）。
ログインが有効で、ログインした人が管理者でないとき、WUIは、設定の画面に`設定を変えられるのは管理者だけです`を出さなければならない（MUST）。このとき、WUIはプロジェクトと追加の指示を読んではならない（MUST NOT）。
WUIは、ログインの状態が分かるまで、設定の画面で何も読んではならない（MUST NOT）。

#### Scenario: 読めなかった後に読み直す
- **WHEN** 追加の指示を読めなかった後、プロジェクトを追加して読み直しが成功する
- **THEN** 誤りの表示は消える

#### Scenario: 管理者でない人がURLで開く
- **WHEN** 管理者でない人が `/settings` を開く
- **THEN** 管理者だけが変えられることの文が出て、`/api/instructions` と `/api/projects` は呼ばれない

### Requirement: 自動マージの結果のタブの間の重複
一覧が届くたびに、WUIは、伝えた自動マージの結果をブラウザの保存から読み直さなければならない（MUST）。他のタブが伝えた結果を、伝え直してはならない（MUST NOT）。

#### Scenario: 2つのタブで開いている
- **WHEN** 別のタブが自動マージの結果を伝えた後、このタブに同じ結果を含む一覧が届く
- **THEN** このタブにはその結果のトーストが出ない

### Requirement: 理由のバッジの名前
WUIは、理由のバッジに、理由の語に続けて日本語の短い名前を出さなければならない（MUST）。名前は、`question` を質問、`verify` を確認、`plan-questions` を計画の質問、`plan` を計画の承認とする。失敗の理由は、`error` を実行の失敗、`permission` を権限の不足、`push` をpushの失敗、`ci` をCIの失敗、`conflict` を衝突とする。
名前の無い理由では、WUIは語だけを出さなければならない（MUST）。

#### Scenario: CIの失敗の待ち
- **WHEN** 理由が `ci` の待ちを一覧に出す
- **THEN** バッジに `ci` と「CIの失敗」が並ぶ

### Requirement: 表の列の位置
幅640px以上1024px未満で一覧を表にするとき、WUIは、どの節の表でも、状態、端末、時間の列を同じ幅にしなければならない（MUST）。

#### Scenario: 待ちと実行中の節がある
- **WHEN** 幅800pxで、待ちと実行中のissueがある一覧を開く
- **THEN** 2つの表の状態、端末、時間の列は同じ位置に並ぶ

### Requirement: 計画の質問の補足の欄
問いのどの組でも選択肢を選んでいて、補足に何も書いていないあいだ、WUIは、その問いの補足の欄を畳み、`Qnに補足を書く`のボタンを出さなければならない（MUST）。
ボタンを押したとき、WUIは、欄を開いて欄にフォーカスを移さなければならない（MUST）。
選択肢の無い問い、「選ばない」を選んだ組がある問い、補足を書いた問いでは、WUIは欄を開いておかなければならない（MUST）。

#### Scenario: 推奨のまま答える
- **WHEN** 計画の質問の待ちを開く
- **THEN** 推奨の選択肢が選ばれた問いの補足の欄は畳まれ、`Qnに補足を書く`のボタンが出る

#### Scenario: 選ばずに補足で答える
- **WHEN** ある問いの組で「選ばない（補足で答える）」を選ぶ
- **THEN** その問いの補足の欄が開く
