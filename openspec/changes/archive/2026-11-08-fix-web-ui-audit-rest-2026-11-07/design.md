# Design

## Context

2026-11-07のWeb受信箱の監査で見つかった課題のうち、前の変更 `fix-web-ui-audit-2026-11-07` の対象外にしたものを、issue #171〜#185に起こした。この変更は、そのうち#171〜#180を直す。受信箱のサービスとAPIは変えない。変えるのは、`switchboard-web` のサーバーとフロントエンドだけである。

## Goals / Non-Goals

**Goals:**

- #171〜#180を、それぞれ先に書いたテストで確かめて直す
- 見た目の変わる修正（#178、#179、#180）はDESIGN.mdに書き、スクリーンショットで確かめる

**Non-Goals:**

- スマホの固定の見出しの縮小（#181）、送信後の仮のカード（#182）、何も選んでいない右のペイン（#183）、スマホの一覧の先頭のボタン（#184）、スレッドの進捗のカードの整形（#185）。どれもDESIGN.mdの大きな改訂か、仕様の判断が要るので、`/spec` で計画する
- 実行中のissueで右のペインが空になる件。再現できておらず、利用者が調査を止めている

## Decisions

### ログインの戻り先はcookieに覚える

ログインの画面のリンクは、一覧と `/login` 以外で開かれたとき、今のパスと問い合わせを `/auth/login?next=...` で渡す。`/auth/login` は、`next` がこの受信箱のパスのときだけ、`sb_next` のcookieに10分のあいだ覚える。cookieは `Path=/auth/`、`HttpOnly`、`SameSite=Lax` にする。`/auth/callback` は、セッションを作った後に `sb_next` を読んで消し、そのパスへリダイレクトする。

受信箱のサービスの `state` に戻り先を載せる案もある。しかしその案は `inboxapi` を変えるので、`switchboard-web` だけで閉じるcookieにした。

この受信箱のパスは、`/` で始まる1024バイト以下の文字列とする。ただし、`//` か `/\` で始まるものと、制御文字を含むものは除く。外部のサイトへのリダイレクトに使わせないため、`/auth/login` と `/auth/callback` の両方で確かめる。

### スクロールの位置はページの側と1件の側で分けて持つ

`IssuePane` は、`issueRef` が変わるたびに、レイアウトの効果で `window` と右のペイン（`main`）のスクロールを先頭へ戻す。返答の対象のカードへのスクロールは、同じ部品のより後の効果で行うので、この後に動く。

一覧のスクロールの位置は `lib/listScroll.ts` にメモリだけで持つ。一覧を出している間、`InboxLayout` が `scroll` のイベントで位置を覚え、一覧へ戻ったときにその位置へ戻す。`/` と `/issue/:ref` は別の経路の要素なので、`InboxLayout` は移るたびに作り直される。そのため、位置は部品の外に置く。

### 作ったばかりのissueは一覧の印で見分ける

`IssuePane` は、受信箱のサービスの一覧に無く、表示の一覧（`view`）に `pending: "create"` の行があるissueを、作ったばかりとして扱う。一覧から消えたとは言わず、返答を送れない旨の文も出さない。エージェントが取りかかれば一覧に載り、`watchKey` が変わって読み直される。

### 設定の画面はログインの状態が分かってから読む

`SettingsPage` は、`useAuth` の `known` が真になるまで読み込み中を出す。ログインが有効で `admin` でなければ、設定を変えられるのは管理者だけだと出し、プロジェクトと追加の指示を読まない。`failure` は `forbidden` にも同じ文を返す。ログインの状態が古いまま読んだときに備えるためである。読み直しが成功したら、誤りを消す。

### 「処理中」の印はセッションとともに消す

`AuthGate` は、ログアウトが成功したときと、セッション切れを受けたときに、`saveMarks([])` で印を消す。

### 自動マージの結果は一覧のたびにlocalStorageを読み直す

`useAutoMergeResults` は、一覧が届くたびに、伝えた結果をlocalStorageから読み、メモリの集合と合わせる。2つのタブが同時に同じ一覧を受けたときは、両方のタブで伝えることがありうる。この隙間は短いため、受け入れる。

### 理由のバッジは語と名前を別のspanにする

`ReasonBadge` は、理由の語と日本語の名前を別の `span` に入れ、間を `gap-x-xs` で空ける。語だけで探す既存のテストと、読み上げの両方で、語が1つのまとまりとして残る。

### 表は列の幅を固定する

表を `table-fixed` にし、`colgroup` で状態を10rem、端末を7rem、時間を6remにする。issueの列は残りの幅を取る。端末の名前は1行で切り、全体をtitle属性に持たせる。状態の列は折り返しを許し、長い理由のバッジを2行にする。

### 補足の欄は畳み、押すと開いてフォーカスを移す

`OneQuestion` は、補足を書いていない間、どの組でも選択肢を選んでいるなら、欄の代わりに「Qnに補足を書く」のボタンを出す。押すと欄を開き、`autoFocus` で欄にフォーカスを移す。選択肢の無い問いと、「選ばない」を選んだ組がある問いでは、欄を開いたままにする。

## Risks / Trade-offs

- 設定の画面は `/api/auth` の応答を待つので、表示が一拍遅れる → 読み込み中の表示を出す
- 理由のバッジが長くなり、カードの2行目が折り返しやすくなる → スマホの幅のスクリーンショットで確かめる
