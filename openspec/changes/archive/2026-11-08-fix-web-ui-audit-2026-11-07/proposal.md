# Proposal

## Why

2026-11-07のWeb受信箱の監査で、操作の不具合4件と、すぐ直せる使い勝手の問題が見つかった。不具合のうち2件は、表示の食い違いと、操作できなくなる状態を生む。返答を送っている間に別のissueへ移ると、移った先の下書きが消える。また、受信箱のサービスの再起動と重なると、ログインの画面へ移れなくなる。

## What Changes

- 返答の送信中に別のissueへ移っても、送信の結果は送った先のissueにだけ反映する。結果が届いたとき、今表示しているissueの下書き、送信済みの表示、誤りは変えない
- `/api/auth` が読めずにログインを無効と見なしていても、401 `unauthenticated` を受けたらログインの画面を出す
- ログアウトのPOSTが失敗したときは、ログインした状態を保ち、失敗をトーストで知らせる
- 自動マージを取り消した後と、自動マージが打ち切られた後は、マージのボタンを押せる状態に戻す
- 経過時間（「5分前から待ち」など）を、一覧が届かなくても1分ごとに描き直す
- 一覧の完了の行ごとに繰り返していた注記を、完了の節の見出しの下に1回だけ出す
- 実行中のissueの1件の画面で、質問か完了になれば画面が自動で切り替わることを案内する
- 1件の見出しのフォージへのリンクの文言を「フォージで開く ↗」に縮め、新しいタブで開くことは読み上げの名前で伝える
- 実装の修正：`cn` がデザイントークンのクラス（`p-lg`、`text-label-md` など）を正しく統合するようにする。カードの余白が二重になっていた原因である
- 文言の修正：返答の欄の案内の「返信」を「返答」にそろえる

## Capabilities

### New Capabilities

- なし

### Modified Capabilities

- `web`：送信中の移動、マージのボタンの戻り、経過時間の描き直し、完了の節の注記、実行中の案内、フォージへのリンクの要件を足す
- `web-auth`：ログインの状態が読めなかったときのセッション切れと、ログアウトの失敗の要件を足す

## Impact

- `web/ui/src/components/IssuePane.tsx`、`MergeButton.tsx`、`InboxList.tsx`、`Header.tsx`
- `web/ui/src/pages/InboxLayout.tsx`
- `web/ui/src/lib/auth.tsx`、`lib/utils.ts`、新しい `lib/now.ts`
- サーバーとAPIは変えない
