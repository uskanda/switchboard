# grilling 記録: add-phase4-relay

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 対象のフォージ | GitHubとGitLabの両方のwebhookを受けられるように作る。すぐに実物で確かめて使うのはGitLabだけにする。GitHubは当面ポーリングのままにする | 第1ラウンド Q1 |
| webhookの受け口の公開方法（ADR-007） | 当面は公開しない。将来は中継用のサーバーを別に用意する | 第1ラウンド Q2 |
| 中継を動かす端末 | 当面はusknasで動かす | 第1ラウンド Q3 |
| webhookの登録 | APIでの登録と、画面での登録の両方に対応する。トークンにwebhookを登録する権限が無ければ、画面から登録する手順（URL、対象のイベント、シークレットの貼り方）を案内する | 第1ラウンド Q4 |
| GitLabのwebhookの検証（ADR-017） | 署名トークン（`webhook-signature`、HMAC-SHA256）を優先し、タイムスタンプが5分を外れたら破棄する。署名トークンを使えないGitLabに限り、設定で `X-Gitlab-Token` の比較を許す | 第1ラウンド Q5 |
| 中継モードでのポーリング | 中継につながっている間は、`reconcile_interval`（既定10分）ごとに担当の全プロジェクトを照合する。届いたIDはissueごとに3秒まとめる。切れたらすぐに `poll_interval` のポーリングに戻り、再接続を続ける。再接続したら `Last-Event-ID` で取りこぼしを埋める | 第1ラウンド Q6 |
| webhookの受け口のアドレス | `127.0.0.1:<port>` で待つ。GitLabのローカルへの送信の許可リストに、このアドレスだけを足す。全体の許可はしない | 第2ラウンド Q7 |
| SSEの配信口と端末の認証 | webhookとは別のリスナーにし、既定は `127.0.0.1:<別のport>` とする。アドレスは設定で変えられる。端末ごとにbearerトークンを発行し、中継はハッシュだけを持つ。エージェントは自分のトークンをSecret Service（サービスではsystemdのクレデンシャル）から読む | 第2ラウンド Q8 |
| webhookを登録するトークン | 受信箱のトークン（`inbox_token_ref`）を使う。権限が足りずに403か404が返ったら、画面から登録する手順を表示する | 第2ラウンド Q9 |
| 中継のシークレットの置き場所とコマンドの形 | `relay hook add <project>` でシークレットを作ってSecret Serviceに置き、登録する（できなければ案内する）。`relay hook remove` で登録とシークレットを消す。端末のトークンは `relay token add <host>` で発行する。中継は `<switchboard-relay.service>` として、`service install --relay` で設置し、シークレットは暗号化したクレデンシャルとして渡す。設定の `relay:` 節には、アドレスと、プロジェクトとhook-keyの対応だけを書く | 第2ラウンド Q10 |
| 重複排除の記録 | 配信IDの記録はメモリだけに持つ。エージェントは届いたIDを取り直しの合図にしか使わないので、重複しても害がない | 第2ラウンド Q11 |
| GitLabの許可リストを誰が変えるか | 利用者が管理画面で足す。`switchboard` は足す値を案内するだけにする | 第3ラウンド Q12 |
| 署名トークンが使えなかったとき（V16） | APIで署名トークンを設定できればAPIで登録し、画面でしか設定できなければ画面での登録を案内する。どちらでも使えなければ、そのプロジェクトに限って `X-Gitlab-Token` を許し、V16とADR-017に記録する | 第3ラウンド Q13 |
| 完了条件の確かめ方 | `nas/switchboard-sandbox` に中継のwebhookを登録し、照合を10分ごとにした中継モードで動かす。受信箱からの返答から実行の開始までが10秒以内であることを監査ログの時刻で確かめる。中継を止めて30秒のポーリングに戻ること、起動し直して再接続することも確かめる | 第3ラウンド Q14 |
| GitHubの実物での確認 | 記録したHTTPのやり取りと偽物でテストし、実物での確認は公開の受け口を用意したときに行う。そのためのGitHubのissueを作る | 第3ラウンド Q15 |
| grillingで聞かなかった細部 | DESIGN.md 4.7節の案（処理の順、対象のイベント、SSEの形と1,000件のバッファ、全端末への同報、3秒のまとめ、残すログの項目）をそのまま使う。エージェントの設定に `relay:`（URLと `token_ref`）と `reconcile_interval` を足し、`relay:` が無ければポーリングだけで動く | 会話中に確認 |
