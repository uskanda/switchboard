# grilling 記録: add-prefer-plan-option

issue `gh:uskanda/switchboard` #74の計画である。順番待ちのissueのうち、実装より計画の実行を先に始める設定を足す。grillingは、issueのコメントで計画を先に立てるモードとして行った。エージェントが第1ラウンドの質問Q1〜Q4を出し、issueの持ち主が回答した。続く計画は `/ok` で承認を受けた。この記録は、PR #79にOpenSpecの変更が無かったため、そのやりとりを事後に写したものである。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 設定の置き場所と名前 | A：端末の設定 `agent.prefer_plan`（既定はfalse）。`agent.max_parallel` と同じく、10秒ごとの読み直しで反映する | issue #74 第1ラウンド Q1 |
| 「計画」として先にする実行の範囲 | A：計画の実行だけを先にする。承認済みの計画の実装、計画なしの実装、返答による再開、doneからの再開は後に回す。CIの直しは順番待ちに入らないので対象外とする | issue #74 第1ラウンド Q2 |
| 同じ種類どうしの順 | B：順番待ちに入った順にスロットを渡す。設定がオフのときもこの順にし、refの文字列の辞書順はやめる | issue #74 第1ラウンド Q3 |
| 優先をどこまで強くするか | A：並べ替えるのは順番待ちから取り出すときだけにする。スロットが空いていれば、実装もすぐに始まる | issue #74 第1ラウンド Q4 |
| 計画の全体 | 回答を前提にした計画（設定、読み直し、順番待ちの取り出す順、ADR、README、DESIGN.mdの更新、テスト）を承認した | issue #74 計画の承認（`/ok`） |

## 後回しにしたもの

- 同じポーリングで計画と実装が見つかったときに、計画を先に起動すること（Q4のB）。空いたスロットが1つで、両方が同じポーリングの間隔の中に見つかったときだけ順が逆になる。次に空くスロットは計画に渡る
- 計画が残っているあいだ実装を始めないこと（Q4のC）。返答待ちの計画が1つあるだけで、空いたスロットが使われなくなる
- プロジェクトの上限で順番待ちに戻ったissueが入った時刻を保つことの、結合テストでの確認。PR #79は、時刻を戻す処理を単体のテストで確かめた
