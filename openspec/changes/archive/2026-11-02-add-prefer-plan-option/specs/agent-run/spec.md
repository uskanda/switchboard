## ADDED Requirements

### Requirement: 順番待ちから取り出す順
スロットが空いたとき、エージェントは、順番待ちのissueを、順番待ちに入った時刻の早い順に実行しなければならない（MUST）。時刻が同じissueは、refの文字列の順に実行する。
順番待ちのあいだに実行の種類が変わったとき、エージェントは、そのissueが順番待ちに入った時刻を変えてはならない（MUST NOT）。種類が変わるのは、計画が承認されたときなどである。
取り出したissueがプロジェクトの上限で順番待ちへ戻ったとき、エージェントは、そのissueが最初に順番待ちへ入った時刻を保たなければならない（MUST）。
エージェントを再起動すると、順番待ちに入った時刻は消える。再起動のあとは、評価で順番待ちへ入り直した順になる。

#### Scenario: 入った順に始まる
- **WHEN** `<agent.prefer_plan>` がfalseで、`<agent.max_parallel>` が1の端末で1つの実行が動いている。その間、実装の `#10`、計画の `#9`、実装の `#11` の順で順番待ちに入り、実行が1つずつ終わる
- **THEN** 実行は `#10`、`#9`、`#11` の順に始まる

#### Scenario: 順番待ちのあいだに計画が承認される
- **WHEN** `<agent.prefer_plan>` がtrueの端末で、実装の `#10`、計画の `#9`、実装の `#11` の順で順番待ちに入る。そのあと `#9` の計画が承認され、`#9` は実装の実行に変わる
- **THEN** `#9` は入った時刻を保ったまま実装として扱われ、実行は `#10`、`#9`、`#11` の順に始まる

### Requirement: 計画の実行の優先
`<agent.prefer_plan>` がtrueの間、スロットが空いたとき、エージェントは、順番待ちのうち計画の実行になるissueを、ほかのissueより先に実行しなければならない（MUST）。
ほかのissueとは、承認済みの計画の実装、計画なしの実装、返答による再開、doneからの再開になるissueをいう。
スロットが空いている間、エージェントは、計画の実行になるissueが順番待ちにあることを理由として、実装の実行を遅らせてはならない（MUST NOT）。

#### Scenario: 計画が先に始まる
- **WHEN** `<agent.prefer_plan>` がtrueで、`<agent.max_parallel>` が1の端末で1つの実行が動いている。その間、実装の `#10`、計画の `#9`、実装の `#11` の順で順番待ちに入り、実行が1つずつ終わる
- **THEN** 実行は `#9`、`#10`、`#11` の順に始まる

#### Scenario: 読み直しでオンにする
- **WHEN** `<agent.prefer_plan>` がfalseの端末で、実装の `#10`、計画の `#9`、実装の `#11` が順番待ちにある。その間に `<agent.prefer_plan>` をtrueへ変えて保存し、そのあとスロットが空く
- **THEN** エージェントは再起動せず、次の取り出しから `#9` を先に始める

#### Scenario: スロットが空いている
- **WHEN** `<agent.prefer_plan>` がtrueで、スロットが空いている端末で、計画の実行が返答を待っている。そこで別のissueへ `agent:ready` が付き、そのissueは実装の実行になる
- **THEN** その実装の実行は順番待ちを経ないで、すぐ始まる
