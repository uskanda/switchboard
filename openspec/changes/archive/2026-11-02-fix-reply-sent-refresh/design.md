# Design

## Context

動機はproposal.mdにある。`IssuePane` は、返答を送ると `sent` を真にしていた。`sent` を偽に戻すのは、別のissueを開いたときだけだった。一覧の行が動く（`watchKey`）と1件を取り直すが、`sent` は残る。返答の欄、計画の質問の選択肢、状態の文言は、どれも `sent` が偽のときだけ出る。

## Goals / Non-Goals

**Goals:**

- 返答のあと、画面を読み込み直さずに、その時点の状態と返答の欄を表示する

**Non-Goals:**

- 返答を送ってから取り直しが届くまでの表示を変えること

## Decisions

- 状態としての `sent` をやめ、返答を送った時点の待ちの印 `sentAt` を持つ。中身は `since` と `waitKey` である
  - `since` は、1件の `since` である
  - `waitKey` は、エージェントの最後の待ちのコメントの `created_at` と本文である。探し方は `questionsOf` に合わせる。そのコメントが無いときは、1件の `post` を使う。スレッドの無い古いバックエンドのためである
- 「送りました」は、次のすべてを満たすときだけ出す。描画のたびにこの条件を求め、`sent` に入れる
  - `sentAt` がある
  - 一覧から消えていない
  - 1件が待ちで、状態が実行中でも順番待ちでもない
  - 取り直した1件の `since` と `waitKey` が、`sentAt` と同じである
- `sent` が偽になったら、effectで `sentAt` を空に戻す。そのため、古い待ちに戻っても「送りました」は出ない
- 返答の欄、計画の質問の選択肢、状態の文言は、今までどおり `sent` を見る

案Bは採らない。案Bは、新しい待ちが届いたときだけ「送りました」を消す形である（grilling.md）。案Bでは、実行が終わって一覧から消えたときに、「送りました」と、一覧から消えたことの表示が並ぶ。

## Risks / Trade-offs

- ［エージェントが新しい待ちのコメントを書かずに待ちを続ける］→「送りました」が残る。返答は届いているので、エージェントが次に動くまで残ってよい
