# grilling 記録: add-web-multi-user

issue #146。第1ラウンドはKeycloakのSSOを前提に聞いたが、利用者の指示で前提をGitLabのOpenID Connectに改め、質問を組み直した。KeycloakはKeycloakの課題（#151）に分けた。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| ログインの方法 | 当面はGitLabのOpenID Connectを使う。Keycloakは #151 に分ける | 第1ラウンドへの返答 |
| 変更の分け方と順序 | #15（ログイン、セッション、ログインできる人の判定）と #146（書き込みの身元、権限、信頼、botの身元）を別の変更にする。計画は #146、#149、#15 の順に書き、実装は #15、#146 の順に行う | 第2ラウンド Q1 |
| GitLabのプロジェクトへのWeb表示からの書き込みの身元 | ログインで `api` のスコープも求め、ログインした人のOAuthのアクセストークンで書き込む | 第2ラウンド Q2 |
| エージェントとWeb表示の書き込みの分担 | エージェントの書き込みはbotの権限で行い、Web表示とアプリからの書き込みはログインした人のGitLabの権限で行う | 第2ラウンドへの返答（会話中に確認） |
| GitHubのプロジェクトへの利用者ごとの書き込み | #152 に先送りする | 第2ラウンド Q3 |
| ログインできる人と権限 | GitLabのグループで決める。`member_groups` は閲覧、返答、計画の承認、issueの作成、マージ。`admin_groups` はそれに加えて追加の指示の編集、プロジェクトの追加、設定の画面 | 第2ラウンド Q4 |
| 信頼の判定との関係 | `trusted_authors` は明示したままにし、ログインとは独立に保つ。信頼されない人が返答するときは、Web表示が返答の前に知らせる | 第2ラウンド Q5 |
| エージェントの身元 | 認証を設定したら、botかProject Access Tokenを必須にする。`agent_identity` が `trusted_authors` にあれば設定の誤りにする。ADR-056の特例は認証なしの構成でだけ残す | 第2ラウンド Q6 |
| 通知の宛先 | 今のまま全員に届ける。Androidの端末を登録した利用者を記録する | 第2ラウンド Q7 |
| 認証を有効にしたときのGitHubのプロジェクト | 書き込めるのはownerの1人だけで、共有の GitHubの `inbox_token_ref` を使う。ほかの人は書き込めない | 第3ラウンド Q8（利用者の上書き）、第4ラウンド Q15 |
| 一覧の絞り込み | ログインした人がGitLabのプロジェクトを読めるかを、その人のトークンで確かめ、読めないプロジェクトを一覧、1件の表示、SSEから外す。結果は10分間キャッシュする | 第3ラウンド Q9 |
| 利用者のトークンの持ち方 | 受信箱のサービスのメモリーにだけ置く。再起動すると全員がログインし直す | 第3ラウンド Q10 |
| 共有の受信箱のトークン（GitLab）の役割 | 一覧の取得、SSEのための取り直し、アイコンの取得という読み取りだけに使う。`read_api` のトークンを推奨し、`doctor` が書き込みのスコープを警告する | 第3ラウンド Q11 |
| Androidのアプリの通知のボタン | 認証を有効にしたときは、押すとアプリが開いて確認の画面を出し、画面でもう一度押して送る | 第3ラウンド Q12 |
| 監査ログ | Web表示からの書き込みの各行に、GitLabのユーザー名を残す | 第3ラウンド Q13 |
| CLI | 変えない。共有の端末の `switchboard reply` は `inbox_token_ref` で書き込む | 第3ラウンド Q14 |
| ownerの決め方 | `<web.auth.owner>` にGitLabのユーザー名を1人書く。ownerはグループに関係なくadminで、GitHubのプロジェクトに書き込める唯一の人である。`admin_users` は足さない | 第4ラウンド Q15 |
| owner以外へのGitHubのプロジェクトの表示 | ownerにだけ見せ、ほかの人の一覧、1件の表示、SSEには出さない | 第4ラウンド Q16 |
| ownerの設定の検査 | `doctor` が、GitHubの受信箱のトークンの持ち主が `trusted_authors.github` に無いときと、ownerが `trusted_authors.gitlab` に無いときに警告する | 第4ラウンド Q17 |
| 認証を設定しないときの振る舞い | `<web.auth>` が無ければ、今の1人の構成のまま何も変えない | 第4ラウンド Q18 |
| 認証を設定したときのGitLabの自動のマージ | 押した人の更新用のトークンを、自動のマージが済むか取り消されるまでメモリーに持ち、その人の身元でマージする。受信箱のサービスが再起動したら取り消し、次に画面を開いたときにトーストで知らせる | 第5ラウンド Q19 |
