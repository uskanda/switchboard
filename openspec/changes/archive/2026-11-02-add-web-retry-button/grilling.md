# grilling 記録: add-web-retry-button

issue `gh:uskanda/switchboard` #72の計画である。実行の失敗（理由が `error`）の待ちに、受信箱のWeb表示（`switchboard-web`）から1クリックで再実行を頼めるボタンを置く。grillingは、issueのコメントで計画を先に立てるモードとして行った。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| ボタンを出す待ちの理由 | 理由が `error` の待ちだけに出す。`verify` は設定ファイルを直さないかぎり同じ理由でまた止まる。`push` と `ci` には返信の前に確かめることの案内があり、ボタンで済ませると確認を飛ばしてしまう | issue #72 第1ラウンド Q1 |
| ボタンが投稿する文と作り方 | UIが決まった文 `再実行してください。` を、今の返答のPOST（`/api/reply`）で送る。サーバー、受信箱のサービス、エージェントは変えない | issue #72 第1ラウンド Q2 |
| 返答の欄との関係 | 計画の「承認する」と同じ並べ方にする。返答の欄が空の間だけ「再実行する」を主ボタンとして押せる。「返答を送る」は副ボタンにし、欄に書いた文はこちらで送る | issue #72 第1ラウンド Q3 |
| 計画の承認 | 上の3つの回答に基づく計画（`IssuePane.tsx`、DESIGN.md、README.mdを変え、`failure.test.tsx` のテストを先に書く）を `/ok` で承認した | issue #72 計画への `/ok` |

## 後回しにしたもの

- 受信箱のサービスに再実行の専用API（`<POST /v1/retry>` など）を足すこと。CLIから再実行したくなったときに足す（Q2のB）
- 投稿する文を `comments.language` に合わせて作ること（Q2のB）
