## MODIFIED Requirements

### Requirement: 実行中の表示
一覧の画面は、待ちの欄とは別に、実行中のissueの欄を表示しなければならない（MUST）。実行中の行には、プロジェクトとissue番号、タイトル、端末の名前、経過時間、最新の進捗の1行を出す。
実行中のissueの1件の画面は、返答の欄を表示してはならない（MUST NOT）。
スレッドの進捗のカードは、最新の行のエージェントの発言を本文として表示しなければならない（MUST）。発言の無い行では`作業しています`を出す。最新の行の時刻、経過、ツールは、本文の下に1行で出す。
進捗のカードは、進捗のコメントのすべての行を、押すと開く「進捗の記録」の中に表示しなければならない（MUST）。行の読めない進捗のコメントは、全文をそのまま出す。

#### Scenario: 実行中のissueを開く
- **WHEN** 一覧の実行中の欄の行を開く
- **THEN** 進捗のカードに最新の発言が出て、返答の欄は出ない

#### Scenario: 進捗の記録を開く
- **WHEN** 3行の進捗のコメントがある実行中のissueで「進捗の記録」を押す
- **THEN** 3行がすべて出る

### Requirement: 1件の表示の位置と固定の見出し
待ちのissueを開いた直後、WUIは、エージェントの最新の質問のカードが見出しの直下に来るようにスクロールしなければならない（MUST）。完了のissueでは、エージェントの最新の完了の報告のカードへ、それが無ければスレッドの最後のカードへスクロールしなければならない（MUST）。ほかの状態のissueでは、スクロールしてはならない（MUST NOT）。
このスクロールは、issueを開くごとに1回だけでなければならない（MUST）。前回読んだ内容を先に出したときは、それを描いた時点で1回とし、後から届いた読み直しではスクロールしてはならない（MUST NOT）。
開いている間の読み直しで、表示するカードが増えたとき、WUIは、スクロールの位置を変えずに、画面の下に「自動更新がありました」の知らせを出さなければならない（MUST）。進捗のカードが書き換わったときも、カードが増えたものとして扱う。状態や時刻だけが変わったときは、知らせを出してはならない（MUST NOT）。
知らせを押したとき、WUIは、待ちと完了のissueでは開いた直後と同じカードへ、ほかの状態では新しく加わったカードの最初のものへスクロールし、知らせを消さなければならない（MUST）。行き先のカードが画面に入ったときと、別のissueへ移ったときも、知らせを消さなければならない（MUST）。
1件の表示の「← 一覧へ」（幅1024px未満）、タイトル、状態の行は、スクロールしても上に残らなければならない（MUST）。完了のissueでマージのボタンを出すときは、状態の行の下のPR/MRのリンク、マージのボタン、自動マージを取り消すボタンも、スクロールしても上に残らなければならない（MUST）。
スクロールが一番上でないとき、タイトルは、幅1024px以上では2行までにし、幅1024px未満では1行にして、全文をtitle属性に持たせなければならない（MUST）。一番上では全文を出す。
幅1024px未満でスクロールが一番上でないとき、WUIは「← 一覧へ」を「←」に縮め、タイトルと同じ行に置かなければならない（MUST）。このとき、WUIは参照を隠し、状態の行の端末とフォージで開くリンクも隠さなければならない（MUST）。「←」の読み上げの名前は「一覧へ」とする。

#### Scenario: 待ちのissueを開く
- **WHEN** 最新の質問の後に人のコメントがある待ちのissueを開く
- **THEN** 最新の質問のカードへスクロールする

#### Scenario: 完了のissueを開く
- **WHEN** 完了の報告の後に人のコメントがある完了のissueを開く
- **THEN** 完了の報告のカードへスクロールする

#### Scenario: 実行中のissueを開く
- **WHEN** 実行中のissueを開く
- **THEN** スクロールしない

#### Scenario: 開いている間にカードが増える
- **WHEN** 待ちのissueを開いたまま、人のコメントが付いて読み直しが届く
- **THEN** スクロールの位置は変わらず、画面の下に「自動更新がありました」が出る

#### Scenario: 状態だけが変わる
- **WHEN** issueを開いたまま、カードは同じで状態と時刻だけが変わった読み直しが届く
- **THEN** 知らせは出ない

#### Scenario: 知らせを押す
- **WHEN** 実行中のissueを開いたまま、待ちになって進捗と質問のカードが加わり、知らせを押す
- **THEN** 質問のカードへスクロールし、知らせが消える

#### Scenario: スマホの幅でスクロールする
- **WHEN** 幅390pxで待ちのissueを開き、下へスクロールする
- **THEN** 見出しは「←」とタイトル1行、状態の行の2行になり、参照と端末は隠れる

## ADDED Requirements

### Requirement: 送った返答の仮のカード
返答を送れたとき、WUIは、そのissueのスレッドの末尾に、送った文の仮のカードを出さなければならない（MUST）。カードの書き手の行には、送信済みでフォージへの反映を待っていることを出す。
フォージから読んだスレッドに、送った文と同じ本文の人のコメントが載ったとき、WUIは仮のカードを消さなければならない（MUST）。issueが送った待ちを離れたときも消す。

#### Scenario: 返答を送る
- **WHEN** 待ちのissueで返答を送る
- **THEN** スレッドの末尾に送った文のカードが出る

#### Scenario: 返答がフォージに載る
- **WHEN** 返答を送った後、同じ文のコメントを含む読み直しが届く
- **THEN** 送った文のカードは1枚だけになる

### Requirement: 送った後の状態の行
このタブで送った返答の「処理中」の印がissueにあるあいだ、WUIは、1件の表示の状態の行に`処理中`を出さなければならない（MUST）。
返答を送ったissueが実行中になったとき、WUIは、実行中の案内の代わりに再開したことの文を出さなければならない（MUST）。文は`返答を受けて、エージェントが作業を再開しました。質問か完了になると、この画面が自動で切り替わります`とする。別のissueを開いたら、この文は出さない。

#### Scenario: 送った後に再開する
- **WHEN** 待ちのissueで返答を送り、一覧でそのissueが実行中になる
- **THEN** 1件の表示に再開したことの文が出る

### Requirement: 何も選んでいない右のペインの概要
幅1024px以上でissueを選んでいないとき、WUIは、右のペインに一覧の4つの節（返答待ち、実行中、順番待ち、完了）の件数を出さなければならない（MUST）。
待ちが1件以上あるとき、WUIは、待ちの理由ごとの件数を、理由のバッジと並べて出さなければならない（MUST）。最も古い待ちのカードは、今と同じく出す。

#### Scenario: 待ちと実行中がある
- **WHEN** 理由が `question` の待ち2件、`ci` の待ち1件、実行中1件がある状態で、幅1280pxで `/` を開く
- **THEN** 右のペインに返答待ち3件、実行中1件と、理由ごとの件数（質問2件、CIの失敗1件）が出る

### Requirement: 一覧の先頭のボタンの位置
WUIは、「プロジェクトでまとめる」と「新規issue」のボタンを、返答待ちの節の見出しと同じ行に置かなければならない（MUST）。幅640px未満では、まとめるボタンの表示を「まとめる」に縮め、読み上げの名前は「プロジェクトでまとめる」のままにする。

#### Scenario: スマホの幅で一覧を開く
- **WHEN** 幅390pxで一覧を開く
- **THEN** 返答待ちの見出しとボタンが同じ行に並び、その下から待ちの行が始まる
