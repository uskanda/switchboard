# Design

## Context

2026-11-07のWeb受信箱の監査の残りの課題#181〜#185を直す。どれも `web/ui` の中で閉じ、サーバーとAPIは変えない。grillingは省いたので、見た目の決めごとは下の既定に従い、実装の後に画面で確かめる。

## Goals / Non-Goals

**Goals:**

- #181〜#185を、テストを先に書いて直す
- Playwrightでモックの受信箱を開き、各課題が解消したことを画面で確かめる

**Non-Goals:**

- ヘッダ（名前、件数、自動更新の状態）の縮小。ヘッダはどの画面にも共通で、1件の見出しを縮めれば足りる
- 実行中のissueで右のペインが空になる件。再現できていない

## Decisions

### 縮めた見出しは同じ要素のクラスの切り替えで作る

`IssuePane` は既に、スクロールが一番上かどうか（`atTop`）を見張っている。幅1024px未満の指定（`max-lg:`）で、一番上でないときだけ次を切り替える。

- 「← 一覧へ」は「←」にして、タイトルと同じ行に置く。読み上げの名前は `aria-label` で「一覧へ」とする
- 参照、端末、フォージで開くリンクは `max-lg:hidden` にする
- タイトルは1行で切る

別の小さな見出しを重ねる案もあるが、マージのボタンなどの要素が二重になるので、1つの要素のクラスだけを変える。見出しの高さは `--pane-head-h` で測り続けているので、カードを止める位置も追従する。

### 仮のカードは送った文と送った待ちで決める

`IssuePane` は、送れた返答の文を `sentAt` と一緒に持つ。`sent` が真のあいだ、`Thread` に `pendingReply` として文を渡し、スレッドの末尾にカードを出す。スレッドの最後の人のコメントの本文が送った文と同じなら、カードは出さない。比べるときは、両方の前後の空白を除く。

### 処理中と再開は一覧の印と送った待ちから決める

状態の行の「処理中」は、表示の一覧（`view`）の行に `pending: "reply"` があるかで決める。一覧と同じ印なので、一覧と1件で表示が食い違わない。

再開の文を出すため、返答を送ったissueの参照を `resumedFor` で持つ。`sent` が偽になった時点でissueが実行中なら、`resumedFor` をそのissueの参照にする。別のissueを開いたら消す。

### 右のペインの概要は一覧から数える

`NothingChosen` は、表示の一覧（`view`）から4つの節の件数を数え、`<dl>` で並べる。待ちの理由ごとの件数は、`ReasonBadge` と件数を1行ずつ並べ、多い順にする。

### 一覧の先頭のボタンは返答待ちの見出しの行へ

`InboxList` の先頭の行を、返答待ちの見出しの行にする。見出しは左、ボタンは右に置き、狭い幅では折り返す。一覧がまだ届かないあいだも、見出しとボタンは出す。`GroupToggle` は `aria-label` に「プロジェクトでまとめる」を持ち、幅640px未満では「まとめる」だけを表示する。

### 進捗のカードは進捗のコメントを読んで描く

`lib/api.ts` に `parseProgress` を足す。進捗のコメントの `- ` で始まる行を集め、各行を区切り（`｜` か `|`）の前と後に分ける。行が1つも無ければ `null` を返し、カードは今までどおり全文を描く。

カードには、最新の行の発言（`progressText` と同じ規則）を本文に、区切りの前（時刻、経過、ツール）を`muted`の1行で出す。その下に、`<details>` で「進捗の記録（N行）」を置き、開くと全行を古い順に並べる。

## Risks / Trade-offs

- 見出しが縮むと、その分だけ下の内容が上へずれる → 縮む境目はスクロールの最上部だけなので、読み進めている途中では起きない
- 送った文とフォージのコメントの本文が、フォージの整形で一致しないことがある → その場合は、issueが待ちを離れたときに仮のカードが消える
