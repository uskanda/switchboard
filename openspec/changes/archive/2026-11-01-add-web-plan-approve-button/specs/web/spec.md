## MODIFIED Requirements

### Requirement: 計画の待ちの表示
一覧の画面と1件の画面は、待ちの理由 `plan-questions` と `plan` を、ほかの理由と同じく理由として表示しなければならない（MUST）。
理由が `plan` のとき、1件の画面は、返答の欄の近くに、承認の語を送れば承認になることを示さなければならない（MUST）。
理由が `plan` のとき、1件の画面は、「承認する（<承認の語> を送る）」のボタンを置かなければならない（MUST）。押すと、確認を挟まずに、承認の語だけを返答のPOSTで投稿する。
返答の欄に空白以外の文があるとき、または待ちでないとき、承認のボタンは押せてはならない（MUST NOT）。
理由が `plan` 以外のとき、1件の画面は、承認のボタンを置いてはならない（MUST NOT）。
理由が `plan-questions` で問いを読み取れたとき、1件の画面は、返答の欄の近くに答え方を示さなければならない（MUST）。答え方とは、問いごとに選んで「この内容で返答」を押すことと、返答の欄の文が全体への補足として加わることをいう。
理由が `plan-questions` で問いを読み取れなかったとき、1件の画面は、返答の欄の近くに、問いごとの答えを返答の欄に書いて送るよう示さなければならない（MUST）。
理由が `plan-questions` のとき、1件の画面は、承認の語で答えるよう勧めてはならない（MUST NOT）。

#### Scenario: 計画の承認待ちを開く
- **WHEN** 理由が `plan` の待ちのissueを1件の画面で開く
- **THEN** 計画の全文と、`/ok` を送れば承認になることが表示される

#### Scenario: 計画の質問の待ちを開く
- **WHEN** 理由が `plan-questions` の待ちのissueを1件の画面で開く
- **THEN** 返答の欄の近くに、選んで「この内容で返答」を押す答え方が表示され、`/ok` を送るよう勧める文は表示されない

#### Scenario: 空の欄で承認のボタンを押す
- **WHEN** 理由が `plan` の待ちのissueで、返答の欄が空のまま、承認のボタン `承認する（/ok を送る）` を押す
- **THEN** `/ok` だけがissueへのコメントとして投稿され、「送りました」が表示される

#### Scenario: 返答の欄に文がある
- **WHEN** 理由が `plan` の待ちのissueで、返答の欄に直しの文を書く
- **THEN** 承認のボタンは押せず、「返答を送る」は押せる

#### Scenario: 計画の質問の待ちには承認のボタンが無い
- **WHEN** 理由が `plan-questions` の待ちのissueを1件の画面で開く
- **THEN** 承認のボタンは表示されない
