# Proposal

## Why

エージェントは、実行の枠が空いていないissueを順番待ちにするが、そのことをissue・受信箱・ログのどこにも出さない（uskanda/switchboard#46）。2026-11-01に、smarternews#79とswitchboard#40は順番待ちのまま動かず、利用者からは返答やラベルが無視されたように見えた。

## What Changes

- エージェントは、順番待ちに入ったissueへ、マーカー `state=queued` 付きのコメントを投稿する。コメントには、当たった上限の種類（端末の上限、プロジェクトの上限）とその値だけを書く
- 順番待ちのコメントは、着手の直前と、順番待ちから外れたときに消す。エージェントの再起動の後は、その端末が前に書いたものを消す
- エージェントのログに、順番待ちに入ったことと、順番待ちから実行を始めたことを1回ずつ出す
- 受信箱は、始めるラベルの付いたissueも読み、順番待ちのissueを「順番待ち」として一覧に出す。返答の待ちから順番待ちになったissueも含める
- Web表示は、「実行中」の節の下に「順番待ち」の節を出し、1件の表示にも順番待ちであることを示す。会話では、順番待ちのコメントを1行に畳む
- ラベルと通知は変えない

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `agent-run`：順番待ちのコメントの投稿と削除、順番待ちのログを足す
- `inbox`：一覧に順番待ちのissueを足す
- `inbox-api`：順番待ちのissueの詳細を返す
- `web`：順番待ちの節と1件の表示、会話での畳み方を足す

## Impact

- `internal/marker`：状態 `queued` を足す
- `internal/agent`：`launch`、`drain`、`consider`、起動時の後片付け、メッセージ
- `internal/inbox`：一覧の検索ラベル、順番待ちの行、詳細、表示
- `inboxapi` と `web/ui`：状態の型、一覧の節、1件の表示、会話
- 受信箱は、始めるラベルの付いたissueのコメントも読むため、フォージへの問い合わせが増える
