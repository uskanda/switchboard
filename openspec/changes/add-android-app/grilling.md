# grilling 記録: add-android-app

issue `gh:uskanda/switchboard` #99の対応である。grillingの前に、今のコードベース（`web/ui`、`switchboard-web`、`notify`）を読んだ。Expo/React Nativeの現状（2026-11時点、Expo SDK 58、RN 0.88）も調べた。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| アプリにする目的 | ホーム画面から全画面で開けること、ネイティブのプッシュ通知、スマホでの手触り。家の外からの利用と、iOSは対象外 | 第1ラウンド Q1 |
| 既存のWUIの活かし方 | 段階を踏む。まずWebViewで動くAPKを作る | 第1ラウンド Q2 |
| 置き場所 | このリポジトリの `app/`。`web/ui` とは別のpnpmのプロジェクト。WUIの変更に追随できることを求める | 第1ラウンド Q3 |
| 届く範囲 | LANの中だけ。ADR-036を変えない | 第1ラウンド Q4 |
| 通知 | FCMでネイティブのプッシュ通知を送る。デスクトップなどではTelegramを今までどおり使うので、両方を併用する | 第1ラウンド Q5 |
| ビルドと配布 | この端末で `expo prebuild` と `./gradlew assembleRelease` を実行し、自分の鍵で署名したAPKを手で入れる。EASは使わない。iOSは対象外 | 第1ラウンド Q6 |
| 1つのコードベースからwebとappを作るか | 今はWebViewの殻にし、WUIそのものを唯一のコードベースとする。Expo Routerとreact-native-webでの書き直しは別のissueにする | 第2ラウンド Q7 |
| FCMの通知を送る場所 | 受信箱のサービス（`inbox serve`）が、一覧の変化を見て送る。Telegramは今までどおりエージェントが送る | 第2ラウンド Q8 |
| 通知に載せる内容 | 参照、理由、issueのタイトル。質問の本文は載せず、通知を押したときにLANから読む | 第2ラウンド Q9 |
| WUIのURLの設定 | 初回の起動で入力させ、アプリの設定画面で変えられるようにする | 第2ラウンド Q10 |
| トークンの登録とネイティブからのPOST | アプリが、設定したWUIのURLを `Origin` に明示して送る。サーバーの検査は変えない。`POST /api/devices` でトークンを登録し、複数の端末を登録できる。FCMが無効と答えたトークンは消す | 第3ラウンド Q11 |
| 通知のボタンの種類 | 計画の承認待ち（`plan`）に「承認」を付け、承認の語を返答する。完了に「マージ」を付け、押すとアプリが開いてWUIのマージの確認のダイアログを出す。計画の質問の「推奨で承認」は付けない（何も見ずに承認するのは普通はできない）。インラインの返信と「開く」のボタンも付けない。通知の本体を押すと、そのissueを開く | 第3ラウンド Q12 |
| 古い通知のボタン | 通知に待ちの投稿の識別子を入れ、押したときに受信箱のサービスが最新の待ちの投稿と比べ、違えば断る。マージは今の `sha` の検査で足りる | 第3ラウンド Q13 |
| 受信箱のサービスが送る条件 | 新しく待ちか完了になったissueと、待ちの理由か待ちの投稿が変わったissueに限る。送った記録を状態のファイルに残す。起動して最初の一覧では送らずに記録だけする。FCMの設定が無ければ送らない。送れなくても一覧と返答を止めない | 第3ラウンド Q14 |
| FCMの資格情報 | サービスアカウントのJSONを `token_ref` でSecret Serviceから読む。`google-services.json` はリポジトリに入れず、ビルドのときに環境変数で場所を渡す。Expoのプッシュの中継は使わず、GoからFCM HTTP v1を直接呼ぶ | 第3ラウンド Q15 |
| アプリの検査 | `make verify` に `app/` の型の検査、lint、テストを足す。APKのビルドは `make app-apk` に分け、`verify` には入れない | 第3ラウンド Q16 |
| 原則3の扱い | 全文を読まずに送れる近道は、計画の「承認」のボタンだけとする。PRODUCT.mdの原則3を、この1点に限って改める | 第4ラウンド（Q12の答えから導き、会話中に確認） |
| アプリが止まっているときの「承認」 | 前面に出さずに送る形を目指す。実機で動かなければ、アプリを開いてから送る形に切り替え、結果をROADMAPの検証項目に残す | 第4ラウンド Q17 |

## 後回しにしたもの

- Expo Routerとreact-native-webでの書き直し（`web/ui` の置き換え）。NativeWind v5が安定し、WebViewの手触りに不満が出たら決め直す
- 家の外からの利用と、WUIの認証（#15）
- Telegramの通知のリンクからアプリを開くApp Links
- 質問へのインラインの返信、計画の質問の「推奨で承認」
- iOS
- CIでのAPKのビルドと、署名の鍵の置き場所
- targetSdk 37で要る `ACCESS_LOCAL_NETWORK` の実行時の許可（SDK 58のtargetSdkは36）
- 別のリポジトリへの切り出し（肥大化したとき）
