## ADDED Requirements

### Requirement: 新規issueのダイアログ
WUIは、一覧のペインの先頭に「新規issue」のボタンを表示しなければならない（MUST）。押すと、ダイアログを開く。
ダイアログは、プロジェクトの選択、タイトル、本文、開始ラベルの選択の4つを持たなければならない（MUST）。プロジェクトの選択肢は、作れる先の一覧のすべてのプロジェクトとし、各選択肢に担当の端末の名前を表示する。開始ラベルの初期値は `ready` とし、各選択肢にラベル名を表示する。
タイトルが空白だけのあいだ、WUIは作成のボタンを押せなくしなければならない（MUST）。
ダイアログは、ラベル名や、ほかの項目を入力させてはならない（MUST NOT）。

#### Scenario: ダイアログを開く
- **WHEN** 一覧の画面で「新規issue」を押す
- **THEN** ダイアログが開き、最初のプロジェクトと開始ラベル `ready` が選ばれている

#### Scenario: タイトルが無い
- **WHEN** 本文だけを書く
- **THEN** 作成のボタンは押せない

### Requirement: issueの作成の結果の表示
作成に成功したとき、WUIは、ダイアログを閉じ、一覧の上に、作ったissueの参照とフォージのページへのリンクを表示しなければならない（MUST）。リンクは新しいタブで開く。知らせは閉じられる。
作成が拒まれたとき、WUIは、ダイアログの中に理由を表示し、書いた内容を残さなければならない（MUST）。

#### Scenario: 作れた
- **WHEN** `gl:nas/sb` に、タイトル「Add a flag」で種別 `plan` のissueを作る
- **THEN** ダイアログが閉じ、一覧の上に `gl:nas/sb#7 を作りました` と、フォージで開くリンクが表示される

#### Scenario: フォージが拒んだ
- **WHEN** フォージがissueの作成を拒む
- **THEN** ダイアログは開いたままで、理由が表示され、タイトルと本文は残る

### Requirement: issueの作成のPOSTの検査
issueの作成のPOSTについて、`<switchboard-web>` は、返答のPOSTと同じ検査をしなければならない（MUST）。本文がJSONであることと、`Origin` と `Host` が `<listen>` のアドレスと一致することである。どちらかに当たらないPOSTは、受信箱のサービスに渡してはならない（MUST NOT）。

#### Scenario: Originの無いPOST
- **WHEN** `Origin` の無いPOSTで、issueの作成を求める
- **THEN** 403が返り、issueは作られない
