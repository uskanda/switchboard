# Spec Delta

## MODIFIED Requirements

### Requirement: 一覧の節のプロジェクトのサブグループ
プロジェクトでまとめる間、一覧は、4つの節（返答待ち・実行中・順番待ち・完了）の行を、節ごとにプロジェクトのサブグループに分けて表示しなければならない（MUST）。
各サブグループは、プロジェクトの参照、フォージのバッジ、行の件数からなる見出しを持たなければならない（MUST）。
節の中のプロジェクトが1つだけのときも、一覧は、サブグループの見出しを表示しなければならない（MUST）。
サブグループの中の行は、プロジェクトの参照を表示してはならない（MUST NOT）。
サブグループの中の行は、プロジェクトのアイコンを表示してはならない（MUST NOT）。
サブグループの中の行は、フォージのバッジを表示してはならない（MUST NOT）。
サブグループの中の行は、issueの番号をタイトルの左に表示しなければならない（MUST）。
フォージが違う同名のリポジトリの行を、一覧は、同じサブグループにまとめてはならない（MUST NOT）。

#### Scenario: 2つのプロジェクトの待ちがある
- **WHEN** `o/a` の待ちが始まって5分、`o/b` の待ちが始まって10分と1分のissueがある一覧を開く
- **THEN** 返答待ちの節に、`o/b`［GitHub］2件の見出しが先、`o/a`［GitHub］1件の見出しが後に出て、`o/b` の下には10分のissue、1分のissueの順で行が出る

#### Scenario: プロジェクトが1つだけ
- **WHEN** 実行中のissueが1つのプロジェクトの1件だけの一覧を開く
- **THEN** 実行中の節に、そのプロジェクトの参照、バッジ、1件の見出しが出て、その下に行が出る

#### Scenario: GitHubとGitLabの同名のリポジトリ
- **WHEN** `gh:o/r` と `gl:o/r` のそれぞれに待ちのissueがある一覧を開く
- **THEN** 返答待ちの節に、`o/r`［GitHub］と`o/r`［GitLab］の2つのサブグループが出る

#### Scenario: まとめる表示の行
- **WHEN** プロジェクトでまとめる表示にして、`gh:o/r#12` の待ちのissue「タイトル」がある一覧を開く
- **THEN** `o/r`［GitHub］の見出しの下の行は、番号`#12`、タイトルの順に始まり、その行には`o/r#12`の参照、プロジェクトのアイコン、GitHubのバッジが出ない

#### Scenario: まとめない表示の行
- **WHEN** プロジェクトでまとめない表示にして、`gh:o/r#12` の待ちのissueがある一覧を開く
- **THEN** 行には今までどおり、プロジェクトのアイコン、`o/r#12`の参照、GitHubのバッジ、タイトルが出る
