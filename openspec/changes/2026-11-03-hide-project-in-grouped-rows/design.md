# Design

## Context

一覧の行は、`web/ui/src/components/InboxList.tsx`で2通りに描く。表（640〜1024px）は`Row`、カード（640px未満と1024px以上の左のペイン）は`CardList`である。どちらも先頭に`IssueRef`を置き、プロジェクトのアイコン、参照`o/r#12`、フォージのバッジを出している。まとめるかどうかは`Items`が`grouped`として持っている。サブグループの見出し`GroupHeading`も`IssueRef`でプロジェクトを出す。動機はproposal.mdのWhyを参照する。

## Goals / Non-Goals

**Goals:**

- まとめる表示の行を、番号とタイトルだけの形にする
- まとめない表示の行と、サブグループの見出しは変えない

**Non-Goals:**

- `IssueRef`そのものの形を変えること
- `/api/inbox`の形や、CLIの表示を変えること

## Decisions

### 番号は一覧の項目の`number`から取る

`/api/inbox`の各項目は、issueの番号を`number`として既に持っている。参照の文字列から取り出す関数は足さない。参照を解析し直すより、サービスが返した値をそのまま使うほうが単純で、食い違いも起きない。

### 番号の見た目（Q4）

番号は`<span className="font-mono text-mono-sm text-muted">#12</span>`にし、空白を1つ挟んでタイトルと同じ要素の中に置く。カードでは`line-clamp-2`の要素の中に入れ、番号も含めて2行に収める。表では`truncate`の要素の中に入れる。番号をタイトルの外に別の行として置く案は、行が1段増え、issueの「タイトルの左」とも合わないので採らない。リンクの読み上げは、番号、タイトルの順になる。

### 表とカードの両方を変える（Q2）

表もまとめる表示ではサブグループの見出しにプロジェクトとバッジを出しているので、行に残すと重複するのはカードと同じである。幅を変えたときに行の形が変わらないよう、両方をそろえる。`Items`が持つ`grouped`を`Row`と`CardList`に渡し、それぞれが`IssueRef`を描くかどうかを決める。

### アイコンも消す（Q3）

アイコンもプロジェクトを示し、見出しと重複する。`IssueRef`ごと描かないので、アイコン、参照、バッジがまとめて消える。

## Risks / Trade-offs

- ［タイトルの`title`属性は番号を含まない］→ 省略されたタイトルの全文を見るためのものなので、タイトルだけで足りる
- ［番号だけでは、まとめない表示に切り替えたときと見た目が変わる］→ まとめない表示では参照に番号が入っているので、情報は失われない
