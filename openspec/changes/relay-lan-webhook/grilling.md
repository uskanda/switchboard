## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 何を実現するか（範囲） | B：設定できるGitLabは1つのまま（ADR-030）。2つ目を足すのではなく、webhookがローカル前提である挙動を変える | 第1ラウンド Q1、全体への補足 |
| 2つ目以降のインスタンスの設定の形 | 回答なし。Q1がBのため扱わない | 第1ラウンド Q2 |
| refでのインスタンスの表し方 | 回答なし。Q1がBのため扱わない | 第1ラウンド Q3 |
| 別の機械のGitLabのwebhook | B：受け口をLANのアドレスでも待てるようにし、別の機械のGitLabからwebhookを受ける（ADR-007を改める） | 第1ラウンド Q4 |
| 私設のCAの証明書 | A：新しい設定は足さない。OSの信頼ストアに入れる手順をGUIDEに書く | 第1ラウンド Q5 |
| WUIでの扱い | A：WUIは変えない | 第1ラウンド Q6 |
| 別の機械のGitLabからどう受けるか | A：受け口をLANのIPアドレスで待つことを正式に認める。`webhook_listen` にWUIと同じ検査（ADR-036）をかけ、IPアドレスで明示させ、すべてのインターフェースは拒む。`webhook_url` の既定は `http://<webhook_listen>` のまま。`sse_listen` は変えない | 第2ラウンド Q7 |
| LANに出すときのGitLabの検証方式 | A：`webhook_listen` がループバックでないときは、`gitlab_token: true` を設定の誤りとして拒む。LANでは署名トークンだけを使う | 第2ラウンド Q8 |
| 送り元のアドレスを絞るか | A：絞らない | 第2ラウンド Q9 |
| 受け口をHTTPSにするか | A：HTTPのまま。LANの中でペイロードが平文で流れることを受け入れる | 第2ラウンド Q10 |

- 送り元のアドレスの制限。LANの外にも出すことになったら足す。
- 受け口のHTTPS。必要になったら別のissueにする。
