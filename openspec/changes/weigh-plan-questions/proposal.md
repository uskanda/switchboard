# Proposal

## Why

計画の質問で返答のあった約200問のうち、約9割は推奨どおりに答えている（#191）。それでも所有者は、すべての問いを同じ重さで読んでいる。推奨と違う答えになった16問のうち5問は、範囲や方向を決めるQ1だった。Q1の答えが変わると、同じラウンドのほかの問いは前提を失う（#168）。判断の要る問いと確認だけの問いを分け、範囲の問いを先に聞き、問いの書き方をそろえれば、所有者が読む量と読み直しを減らせる。

## What Changes

- 計画の実行の宣言で、各問いに必須の `weight`（`decision` か `check`）を持たせる
- switchboardは、質問のコメントで判断が要る問いを先に並べる。確認だけの問いは「推奨でよいか確認してほしい問い」の見出しの下に、全文のまま続きの番号で書く
- 計画の実行のsystem promptに、次の指示を足す
  - 確認だけの問いの基準。判断の要る問いが1つも無ければ、問いを出さずに計画を出すこと。計画の段階を省いてよい実行でも、そのときは `implement` にしないこと
  - 答えがほかの問いの選択肢を変える問いがあれば、そのラウンドではその問いだけを聞くこと
  - 本文は、問いの1文と、判断に要る事実の3つまでの箇条書きにすること。調べた根拠は `summary` に書くこと。コードの名前は初めて出たところで説明すること
  - 範囲や方向を決める問いでは、何が含まれて何が外れるかを図で示すとよいこと
- 計画の実行のsystem promptから、#190で不要になった「選択肢にラベルを付けて書く」指示の要件を除く
- Web表示は、最新の質問のコメントの確認だけの問いを「推奨でよいか確認してほしい問い（n件）」の節に1行ずつ並べる。行を押すとその問いのカードが開き、選び直せる
- Web表示の問いの状態のチップは、確認だけの問いを `推奨どおり n件` の1つにまとめる。選び直した確認だけの問いには、その問いのチップを別に出す
- PRODUCT.mdの原則3（返答の前に質問の全文を読めるようにする）に、確認だけの問いの例外を足し、ADRを書く

## Capabilities

### New Capabilities

- なし

### Modified Capabilities

- `plan-mode`: 計画の実行の終了の宣言の形、質問のコメントの並べ方、計画の実行の指示、確認だけの事項と計画の段階の省略
- `web`: 確認だけの問いのまとめ方、問いのカード、問いの状態のチップ

## Impact

- `internal/agent/planrun.go`：宣言のスキーマと検査、質問のコメントの並べ方
- `internal/agent/messages.go`：確認だけの問いの見出し（日本語と英語）
- `internal/prompt/prompt.go`：計画の実行のsystem prompt
- `web/ui`：質問のコメントの読み取り、問いのカード、確認だけの問いの節、チップ
- `PRODUCT.md`（原則3）、`docs/DECISIONS.md`（ADRの追加）、`DESIGN.md`
