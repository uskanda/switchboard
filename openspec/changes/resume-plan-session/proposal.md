# Proposal

## Why

実行は毎回新しいセッションで起動し、1つのissueあたり平均3.8回、コードを読み直している。計画の実行のあとの次の計画の実行は51件あり、そのうち34件が1時間以内に始まっていた（#131）。前回の計画の実行のセッションを引き継げば、読み直しの手数が減り、1時間のキャッシュの読み込みで入力のトークンの費用も減る。ADR-005は、同じ端末で新しいセッションに分岐する再開を、最適化として認めている。

## What Changes

- 計画の実行の次の計画の実行を、条件を満たすとき、`--resume <前回のセッション> --fork-session` で前回のセッションから分岐して起動する。分岐した先のセッションIDは、今までどおりエージェントが先に決める。
- 引き継ぐ条件は、次のすべてとする。
  - 前回の実行がこの端末の計画の実行で、質問か計画を投稿して終わった。
  - 前回の実行の終わりから `<agent.resume_within>` 以内に始まる。既定は1時間で、0なら引き継がない。
  - 前回の実行のシステムプロンプト、ツール、モデル、effortが今回と同じで、worktreeのHEADも同じ。
- 引き継いだ実行にも、今と同じプロンプトの全体を渡す。先頭に、前の段の続きであることを書く。信頼の判定とnonce付きの区切りは、毎回やり直す。
- 引き継ぐ元のセッションが無いとき（`No conversation found`）は、同じ実行の中で新しいセッションとして起動し直す。
- 監査ログの `run.started` に、引き継いだ元のセッションを足す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `agent-run`: 要件の「毎回新しいセッション」を、計画の実行のセッションの引き継ぎを許す形に改める。引き継ぐ条件、引き継いだ実行のプロンプト、引き継ぎに失敗したときの起動し直しを足す。
- `config`: `<agent.resume_within>` の設定を足す。
- `run-instructions`: 計画の実行の `run.started` に、引き継いだ元のセッションを足す。

## Impact

- コード：`internal/claudecode` は、引き継ぐ元のセッションを受けて `--resume` と `--fork-session` を付け、元のセッションが無い誤りを見分ける。`internal/agent` は、引き継ぐ条件を判定し、実行ごとに条件の判定に使う値を記録する。`internal/config` は、`<agent.resume_within>` を読む。`internal/prompt` は、引き継いだ実行のプロンプトの先頭の行を持つ。
- 文書：`docs/DECISIONS.md` にADRを足す。`docs/ROADMAP.md` の検証項目に、再開のときのシステムプロンプト、ツール、スキーマ、キャッシュの振る舞いを書く。`README.md` と `docs/DESIGN.md` に、引き継ぎの説明を書く。
- 運用：同じ端末で1時間以内に続く計画のラウンドは、前回のセッションから分岐する。`<agent.resume_within>` を0にすると、今までどおり毎回新しく起動する。
