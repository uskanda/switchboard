## MODIFIED Requirements

### Requirement: 毎回新しいセッション
エージェントは、実行ごとに新しいセッションIDを決め、`--session-id` で指定して `claude -p` を起動しなければならない（MUST）。
エージェントは、「計画の実行のセッションの引き継ぎ」の条件を満たす計画の実行のときだけ、`--resume` で前回のセッションを使ってよい（MAY）。そのときも、`--fork-session` を付け、新しいセッションIDを `--session-id` で指定しなければならない（MUST）。
エージェントは、それ以外の実行で、`--resume` で以前のセッションを使ってはならない（MUST NOT）。

#### Scenario: 返答による2回目の実行
- **WHEN** 待ちのissueへの返答で2回目の実行を始める
- **THEN** 1回目とは別のセッションIDで起動し、issueの本文と信頼済みのコメントの全体をプロンプトに含める

#### Scenario: 承認のあとの実行
- **WHEN** 計画の承認の返答で、承認のあとの実装の実行を始める。前回の計画の実行は、同じ端末で10分前に終わっている
- **THEN** `--resume` を付けずに、新しいセッションIDで起動する

## ADDED Requirements

### Requirement: 計画の実行のセッションの引き継ぎ
計画の実行を始めるとき、エージェントは、次のすべてを満たせば、前回の計画の実行のセッションから分岐して `claude -p` を起動しなければならない（MUST）。
- issueの最新のエージェントの待ちの投稿が、この端末の計画の実行のもので、理由が `plan-questions` か `plan` である。
- その投稿の時刻から、`<agent.resume_within>` 以内である。
- 端末に残る前回の実行の記録で、追記する指示、渡すツール、モデル、effortが、今回と同じである。
- 前回の実行の始まりのworktreeのHEADが、今回の始まりのHEADと同じである。
1つでも満たさないとき、エージェントは、前回のセッションを使わずに起動しなければならない（MUST）。

#### Scenario: 質問への返答
- **WHEN** この端末の計画の実行が質問を投稿して20分後に、信頼するユーザーが返答し、次の計画の実行を始める
- **THEN** `claude -p` は `--resume <前回のセッション> --fork-session --session-id <新しいID>` で起動する

#### Scenario: 間隔が長い
- **WHEN** `<agent.resume_within>` が1時間で、前回の計画の実行の投稿から2時間たって、次の計画の実行を始める
- **THEN** `--resume` を付けずに起動する

#### Scenario: 指示が変わった
- **WHEN** 前回の計画の実行のあとに `plan.md` が編集され、次の計画の実行を始める
- **THEN** `--resume` を付けずに起動する

#### Scenario: 別の端末の投稿
- **WHEN** 前回の計画の実行の投稿のマーカーが別の端末のもので、この端末で次の計画の実行を始める
- **THEN** `--resume` を付けずに起動する

#### Scenario: 誤りで終わった前回の実行
- **WHEN** 前回の計画の実行が時間切れで終わり、返答で次の計画の実行を始める
- **THEN** `--resume` を付けずに起動する

### Requirement: 引き継いだ実行のプロンプト
前回のセッションを引き継ぐとき、エージェントは、引き継がない実行と同じ規則でプロンプトの全体を作らなければならない（MUST）。信頼の判定とnonce付きの区切りも、この実行で改めて行う。
エージェントは、プロンプトの先頭に、前の段の続きであり、issueの今の内容が続くことを書かなければならない（MUST）。

#### Scenario: 引き継いだ実行に非信頼のコメントがある
- **WHEN** 前回の計画の実行のあとに、信頼しないユーザーがコメントし、信頼するユーザーが返答して、前回のセッションを引き継ぐ計画の実行を始める
- **THEN** プロンプトには、この実行のnonceの区切りが使われ、信頼しないコメントは指示の区切りに入らない

### Requirement: 引き継ぎに失敗したときの起動し直し
引き継ぎの失敗とは、前回のセッションを引き継いで起動した `claude -p` が、ターン数0のまま、前回のセッションが見つからないという誤りで終わることをいう。
引き継ぎに失敗したとき、エージェントは、同じ実行の中で新しいセッションIDを決め、前回のセッションを使わずに起動し直さなければならない（MUST）。
このとき、エージェントは、誤りのコメントを書いてはならない（MUST NOT）。
1ターン以上進んだあとの誤りは、引き継がない実行と同じく、実行の誤りとして扱わなければならない（MUST）。

#### Scenario: 前回のセッションが消えている
- **WHEN** 前回のセッションのtranscriptが消えた状態で、引き継ぐ条件を満たす計画の実行を始める
- **THEN** claudeは `--resume` 付きと、付けない形とで2回起動され、issueには1回分の結果のコメントだけが付く
