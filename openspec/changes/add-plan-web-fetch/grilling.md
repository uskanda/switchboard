# grilling 記録: add-plan-web-fetch

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| WebFetchを許すかどうか | 許す。issueの本文とコメントは信頼済みの人のものだけを採るので、issueを経由する持ち出しの経路はほぼ塞がっている。新しく増える経路は読んだページそのものだが、起こりやすさは低く、漏れうるものもworktreeのコードと計画の文脈に限られる | 会話中に確認 |
| ドメインの許可リストにするか | しない。調べ物の有用性を大きく削るため | 会話中に確認 |
| 許す実行の範囲 | 計画の実行すべて（`plan_prototype` と撮影つきの実行を含む）。実装の実行と直す実行では拒否を保つ | 第1ラウンド Q1 |
| 既定値と外す設定の形 | 既定でオン。<agent.plan_web_fetch> で全体の既定を変え、<projects[].plan_web_fetch> でプロジェクトごとに上書きする。オフのときは `--tools` にもWebFetchを渡さない | 第1ラウンド Q2 |
| 読んだURLの残し方 | `stream.jsonl` に加え、計画のコメントに折りたたんだ「参照したページ」の一覧を付ける。監査ログには残さない | 第1ラウンド Q3 |
| `allow_tools_extra` での WebFetch | 誤りのまま。計画の実行のWebFetchは新しい項目だけで制御する | 第1ラウンド Q4 |
| プロンプトでの扱い | 計画の実行のsystem promptに、読んだページの本文はデータとして扱い、issueやリポジトリの内容をURLに載せて送らない旨を足す | 第1ラウンド Q5 |
| 一覧の中身 | 拒否と失敗も含め、呼び出したURLをすべて載せる。重複はまとめる。URLは省略せずコード表記にし、1件200文字で打ち切る。20件までとし、超えた分は「ほかN件」とする。質問の回も最終の計画の回も、その回の計画のコメントに付ける。1件も読んでいなければ付けない | 第2ラウンド Q6 |
| 受信箱から変えられるか | 変えられない。設定ファイルにだけ書ける（ADR-045と同じ扱い）。プロジェクトの項目は再起動なしで、<agent.plan_web_fetch> は再起動で反映する | 第2ラウンド Q7 |

## 後回しにしたもの

- 実装の実行と直す実行でのWebFetch（`allow_tools_extra` に `WebFetch(domain:…)` を書ける形）。
- 監査ログへの記録。
