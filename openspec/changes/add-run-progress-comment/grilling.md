# grilling 記録: add-run-progress-comment

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 進捗のコメントに書く内容 | 経過時間、最後に動いた時刻、使ったツールの名前と回数に加え、何を考えているか・何を目的として作業しているかが分かる1行。コマンドの中身や編集したファイルの名前は書かない（公開リポジトリで漏らしたくない情報が出ないように） | 第1ラウンド Q1 |
| 書き換えの間隔 | 1分 | 第1ラウンド Q2 |
| 書き換えるときの検査 | 書き換えるたびに、秘密の検査と `comments.check_command` を通す | 第1ラウンド Q3 |
| 止まっている目安 | 書かない | 第1ラウンド Q4 |
| Web表示に進み具合を出すか | 出す | 第1ラウンド Q5 |
| #21（受信箱に実行中のissueを出す）との関係 | この変更に含める。受信箱（CLI、`inboxapi`、Web表示）に実行中のissueを出し、その行に進み具合を出す | 第2ラウンド Q6 |
| Web表示が進み具合を取る場所 | フォージの進捗のコメントから取る。受信箱は今までどおりフォージだけを読み、別の端末の実行も見える | 第2ラウンド Q7 |
| 進捗を書くコメント | 着手のコメントとは別に、実行ごとに進捗のコメントを1つ投稿する。着手のコメントとADR-033の重複防止には手を入れない | 第2ラウンド Q8 |
| 1分ごとの1行の形 | 「時刻 経過時間 ツールの回数 ｜ 目的の1行」。目的の1行は、最新のassistantのテキストの1行目を120文字で切る。前の行と同じ内容なら足さない | 第2ラウンド Q9 |
| CLIの `switchboard inbox` での実行中の扱い | 既定で出す。待ちの一覧の下に、実行中の欄を分けて出す | 第2ラウンド Q10 |
| 進捗のコメントの投稿による通知 | 受け入れる。投稿の通知は実行ごとに1回で、書き換えでは届かない | 第3ラウンド Q11 |
| 進捗のコメントを消す時機 | 結果のコメント（待ちか完了）を投稿したあとに消す。取り消し、時間切れ、異常終了でも同じ。エージェントが落ちて残ったものは、再起動のあとの回復で消す | 第3ラウンド Q12 |
| 目的の1行に出るファイルの名前 | 受け入れる。第1ラウンドQ1の「ファイルの名前は書かない」を緩め、書かないのはツールの入力と出力（コマンドの中身、ツールに渡したパス）に限る。目的の1行はassistantの文をそのまま使い、ファイルの名前が含まれることがある | 第4ラウンド（PRの監査のあと、ユーザーの指示） |
| Web表示での実行中のissueの見せ方 | 一覧では、実行中の欄に端末の名前、経過時間、最新の進捗の1行を出す。1件の画面では、進捗のコメントの全文を出し、返答の欄は出さない | 第3ラウンド Q13 |
