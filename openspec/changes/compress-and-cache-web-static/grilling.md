# grilling 記録: compress-and-cache-web-static

issue `gh:uskanda/switchboard` #91の変更である。Web UIの静的ファイルを圧縮し、ブラウザにキャッシュさせる。面接の代わりに、エージェントがissueに計画の質問（Q1〜Q3）を出し、オーナーがすべてAと答えた。その後の計画もオーナーが `/ok` で承認した。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| gzipをどこで作るか | A：Go側で作る。ファイルごとに初回の要求で圧縮し、結果をメモリに持って使い回す。圧縮して小さくなるテキスト系の型に限り、`Accept-Encoding: gzip` が来たときだけ返す。ビルドの手順は変えない | issue #91のQ1（コメント6584271032） |
| index.htmlにETagを付けて304を返すか | A：中身のハッシュから `ETag` を作り、`If-None-Match` が一致すれば304を返す。ハッシュ付きでないファイルにも同じ方法で付ける | issue #91のQ2（コメント6584271032） |
| 変更をOpenSpecに記録するか | A：OpenSpecの変更として記録する | issue #91のQ3（コメント6584271032） |
| 計画の承認 | コメント6586127006の計画どおりに進める | issue #91のコメント6586210391（`/ok`） |
