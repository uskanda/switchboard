# Design

## Context

画面の見出しは、ヘッダがh1、1件の画面のissueのタイトルがh2である。本文とコメントは、見出しを挟まずにその下へ並ぶ。Markdownは`react-markdown`で描き、`components`で要素ごとの描き方を差し替えている。`.md`の書式はh1からh4にしか当たっていない。

マージの確認はネイティブの`<dialog>`を`showModal()`で開く。ブラウザは最初のフォーカスできる要素、つまりPR/MRのリンクにフォーカスを当てる。

一覧のカードは、選んでいる行を`primary`の2pxの枠（Cardの`border-2`）で示す。リンクのフォーカスの輪郭も`primary`の2pxで、間を空けずに同じ位置で重なる。

## Goals / Non-Goals

**Goals:**
- 本文とコメントの見出しを、ページの見出しの階層に収める
- マージのダイアログで、安全な側を最初のフォーカスにする
- 一覧で、選んでいる状態とフォーカスを見分けられるようにする

**Non-Goals:**
- 幅640px〜1023pxで出る表の側のリンクのフォーカス。選んでいる行を枠で示していないため変えない

## Decisions

- **見出しは2段ずつ下げる。** `components`に`h1`から`h6`を足し、2段下の要素で描く。`inlineComponents`は`components`を広げて作るので、同じ扱いになる。h1とh2だけをh3にする案と、すべてをh3にする案は、コメントの中の見出しの上下の関係が失われるので採らない。見た目はDESIGN.mdのとおり、どの段でも`body-md`の太字のままにする。`.md`の書式は`h3`から`h6`に当てる
- **計画の質問の題はh3にする。** 題の下の本文の`##`は、上の決定でh4になり、階層が飛ばない
- **マージのダイアログは、`showModal()`の直後に「やめる」へ`focus()`する。** Reactの`autoFocus`は`autofocus`属性を出さない。マウント時に`focus()`を呼ぶだけなので、閉じた`<dialog>`の中の要素はフォーカスを受け取れない。このため使わない
- **カードのフォーカスの輪郭は`focus-visible:outline-offset-2`で離す。** ボタンのフォーカスの描き方とそろい、新しい色やトークンが要らない。地の色や輪郭の色で見分ける案は、新しいトークンが要るので採らない

## Risks / Trade-offs

- 離した輪郭が、左のペインのスクロールする箱の端で切れる → 実際の画面で確かめ、切れるなら`<ul>`かペインに輪郭の分の内側の余白を足す
