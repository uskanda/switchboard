# Proposal

## Why

受信箱のWeb表示は、一覧と1件を別の画面に分けており、1件を見るたびに一覧から離れる。1件の画面にはエージェントの最新の投稿しか出ないため、返答するときに、依頼の本文や途中のやり取りをフォージで開き直す必要がある。画面は開いた時点の内容のままで、待ちが増えても実行が進んでも、再読み込みするまで変わらない（issue #29）。

## What Changes

- Web表示を、ヘッダと2つのペインの画面にする。幅1024px以上では、左に一覧、右に選んだissueを並べる。それより狭い幅では、今どおり一覧の画面と1件の画面を行き来する
- 選んだissueは、今と同じ `/issue/:ref` で表す
- ヘッダには、名前、待ちと実行中の件数、自動更新の状態、設定へのリンクを出す
- 右のペインには、issueの本文とコメントのスレッドを古い順に出し、今までどおり返答の欄を置く。本文とコメントは、生のHTMLを描かないMarkdownとして描く。エージェントの投稿には印を付け、着手のコメントは1行に畳み、進捗のコメントは最新の1件だけを出す
- 受信箱のサービス（`switchboard inbox serve`）は、SSEで変化を知らせる口を足す。SSEでつないでいるブラウザがある間だけ、一定の間隔でフォージに問い合わせ、一覧が変わったら知らせる
- `switchboard-web` は、受信箱のサービスのSSEを、ブラウザへのSSEとして中継する
- ブラウザは、知らせを受けて一覧を書き換える。選んでいるissueが変わったときは、その1件を取り直す。返答の書きかけは消さない
- 間隔は、`config.yaml` の `<inbox.refresh_interval>` で決める。既定は30秒、下限は10秒とする
- 一覧の要素に、issueの更新の時刻と人のコメントの数を足す。1件の詳細に、issueの本文とコメントの一覧を足す

## Capabilities

### New Capabilities

- なし

### Modified Capabilities

- `web`: ヘッダと2つのペインの画面、スレッドの表示、自動更新
- `inbox-api`: 変化を知らせるSSEの口、一覧の要素の更新の時刻と人のコメントの数、1件の詳細のスレッド
- `config`: 受信箱の更新の間隔の設定

## Impact

- `inboxapi`：一覧の要素と1件の詳細の型に項目を足し、SSEを読むクライアントを足す
- `internal/inbox`：一覧の要素に更新の時刻と人のコメントの数を足し、1件の詳細でissueの本文とコメントを返す
- `internal/inboxserve`：問い合わせのループと `/v1/events` を足す
- `internal/config`：`inbox` の節を足す
- `web/internal/server`：`/api/events` を足す
- `web/ui`：画面の組み方、スレッドの表示、SSEの受け取りを作り直す。Markdownを描くライブラリを足す
- `DESIGN.md` の「Layout」を、2つのペインに合わせて書き直す
- README.mdと `config/switchboard.example.yaml` を更新する
- フォージへの問い合わせは、画面を開いている間だけ、間隔ごとに1回の一覧の取得が増える。待ちが5件で間隔が30秒なら、GitHubのREST APIは約600回/時、検索は120回/時である
