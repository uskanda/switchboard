# grilling 記録: add-web-two-pane-live

issue #29（WebUIのブラッシュアップ）の計画である。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 右ペインに出すissueの内容 | issueの本文とコメントのスレッドを古い順に出す。エージェントの最新の投稿は目立たせる | 第1ラウンド Q1 |
| 左ペインの一覧に出すissue | 今までどおり、待ちと実行中だけ | 第1ラウンド Q2 |
| 更新を知る方法 | `inbox serve` が一定の間隔でフォージに問い合わせ、前回と違えば知らせる | 第1ラウンド Q3 |
| ブラウザへの流し方 | `inbox serve` が1つの問い合わせのループを持ち、Unixソケットで `/v1/events`（SSE）を出す。`switchboard-web` はそれをブラウザへのSSEとして中継する | 第1ラウンド Q4 |
| 狭い幅での形 | 幅1024px以上で2ペインにする。それより狭いと、今どおり一覧の画面と1件の画面を行き来する | 第1ラウンド Q5 |
| URL | 選択中のissueを今と同じ `/issue/:ref` で表す。デスクトップでは、そのURLで左に一覧、右に1件を出す | 第1ラウンド Q6 |
| 返答を書いている途中の更新 | 書きかけは消さない。待ちでなくなったら、送信を止めてその旨を出す。新しいコメントは足していく | 第1ラウンド Q7 |
| ヘッダに出すもの | 名前（受信箱）、待ちと実行中の件数、自動更新の状態（つながっている／切れて再接続中）、設定へのリンク。設定の画面は同じヘッダの下に1列で出す | 第1ラウンド Q8 |
| 本文とコメントの描き方 | Markdownとして描く。生のHTMLは描かずに文字として出し、画像は読み込まずにリンクにする。リンクは新しいタブで開き、`rel="noreferrer"` を付ける | 第2ラウンド Q9 |
| 問い合わせのループを動かす時間 | SSEでつないでいるブラウザが1つ以上あるときだけ動かす。誰もいなければ、今と同じく要求のときだけ問い合わせる | 第2ラウンド Q10 |
| 間隔の設定 | `config.yaml` の `<inbox.refresh_interval>`。既定は30秒、下限は10秒 | 第2ラウンド Q11 |
| 右ペインの1件を取り直すきっかけ | `inboxapi.Item` に `updated_at` と `notes` を足す。選択中のissueについて、この2つか、状態、理由、進捗が変わったら、ブラウザが1件を取り直す。一覧から消えたときは、右ペインの表示を残したまま、待ちでも実行中でもなくなったことを出す | 第2ラウンド Q12 |
| スレッドのエージェントの投稿 | 全部を並べ、エージェントの投稿には印を付ける。着手のコメントは1行に畳み、進捗のコメントは最新の1件だけを出す。マーカーは出さない | 第2ラウンド Q13 |
| 中継で即時に知る方法 | この変更には含めない。課題としてissueを立てる | 第2ラウンド Q14 |
| 仕様の作成から実装、テスト、PRまで | 続けて進める。議論したい点は途中で止めずに、最後にまとめて示す | 会話中に確認 |
