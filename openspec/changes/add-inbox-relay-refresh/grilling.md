# grilling 記録: add-inbox-relay-refresh

issue `gh:uskanda/switchboard#34` のコメントで、質問と回答を往復した。出典は `add-web-two-pane-live` のgrilling、第2ラウンドQ14である。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| q1 受信箱のサービスのトークンの発行と置き場所 | `relay token add --inbox <端末名>` を足す。トークンは `switchboard/relay-<端末名>-inbox` に置き、`relay.hosts` の名前は `<端末名>-inbox` にする。画面には `inbox.relay` に足す項目を出す。`service install --inbox` は、このトークンも暗号化したクレデンシャルとして渡す | 第1ラウンドQ1（A） |
| q2 中継につないでいる間の問い合わせの間隔 | 延ばさない。`inbox.refresh_interval` ごとに問い合わせ、イベントは間隔を待たずに取り直すきっかけにだけ使う | 第1ラウンドQ2（A） |
| q3 続けて届いたイベントのまとめ方 | 最初のイベントから2秒待ち、その間のイベントを1回の取り直しにまとめる。前回の取得から10秒（`MinRefreshInterval`）たつまでは取り直さない。どちらも定数にする | 第1ラウンドQ3（A） |
| q4 中継につなぐ時間の範囲 | 受信箱のサービスが動いている間、ずっとつなぐ。画面が無いときにイベントが届いたら、一覧のキャッシュを捨てるだけにする | 第1ラウンドQ4（A） |
| q5 中継の状態を画面に出すか | 出す。ヘッダの自動更新の表示に印を足す | 第1ラウンドQ5（B） |
| q6 中継の状態を画面へ届ける方法 | `inboxapi.Inbox` に `relay` を足す。値は `connected`、`disconnected`、空（設定なし）の3つ。状態が変わったら、最後の一覧に新しい状態を入れて送り直す | 第2ラウンドQ6（A） |
| q7 ヘッダの文言 | つながっているときは「自動更新中（即時）」、設定が無いときは今のまま「自動更新中」。切れているときの文言はq8で決める。点の印は変えない | 第2ラウンドQ7（A、補足つき） |
| q8 中継が切れているときの文言 | 「自動更新中（30秒ごと）」。数字は `inbox.refresh_interval` の秒数とし、`inboxapi.Inbox` に `refresh_interval_seconds` を足す | 第3ラウンドQ8（A） |
