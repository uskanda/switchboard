issue #119の計画の段で、エージェントが質問を投稿し（comment 6594311858）、issueの持ち主が回答した（comment 6594334307）。回答をもとにした計画（comment 6594990745）は、comment 6595635669で `/ok` により変更なしで承認された。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 衝突で断られたマージを、衝突が直ったあと誰がどう行うか | B：受信箱のサービスが「マージの依頼」を覚え、エージェントが直して新しいdoneを投稿したら、そのマーカーの `sha` を指定して受信箱のトークンでマージする。断られたら `inbox.refresh_interval` ごとに試し直す。画面がつながっていなくても試す | issue #119の計画の質問Q1（comment 6594311858）、回答はcomment 6594334307 |
| 自動でマージしてよいコミットの範囲 | A：押したあとにエージェントの直す実行（衝突、CIの失敗、non-fast-forward）がpushしたコミットだけを許す。人の指示で始まった実行がその間に入ったら、自動のマージをやめる。doneのマーカーに直す実行の種類を足す | 同Q2、回答はcomment 6594334307 |
| マージの依頼をどこに覚えておくか | A：受信箱のサービスの状態ディレクトリにファイルを置く。ラベルとコメントには触らない | 同Q3、回答はcomment 6594334307 |
| 画面での見え方と取り消し | A：衝突で断られたらトーストで知らせ、一覧の行と詳細のペインに「自動マージ待ち」の印を付け、詳細のペインに取り消しのボタンを置く。取り消しのPOSTにはマージと同じ検査をかける | 同Q4、回答はcomment 6594334307 |
| 自動のマージをやめる条件 | A：issueのclose、PR/MRのcloseとマージ、`waiting` への移行、人のpush、許さない実行が入ったとき。時間の上限は設けない。やめたときは次に画面を開いたときにトーストで理由を出す | 同Q5、回答はcomment 6594334307 |
| 依頼の置き場とファイルの形 | 状態ディレクトリの `inbox/automerge.json` に、ref、PR/MRの番号、押したときの `sha`、押した時刻、押したときに最後だったコメントのIDを書く。終わった依頼は結果と理由と時刻を付けて24時間残す | 計画（comment 6594990745）の3.、承認はcomment 6595635669 |
| 依頼を登録する条件 | フォージが断り、PR/MRのheadが押した `sha` のままで衝突しているときだけ、409の代わりに202と `auto_merge_pending` を返す。衝突でない理由では今までどおり409 | 計画の4.、承認は同上 |
| 見張りの判断の順 | closed → `waiting` → 押したあとの信頼済みの人のコメントか `reason=fix` でない着手 → 実行中か同じ `sha` なら待つ → `fix` の無い新しいdoneなら打ち切り → PR/MRの状態とheadを確かめてマージ | 計画の5.、承認は同上 |
| ADR | ADR-048を足し、ADR-043の「画面で見た `sha` に限る」を改める | 計画の1.、承認は同上 |
