## MODIFIED Requirements

### Requirement: マージの結果の表示
マージの結果が返ったとき、WUIは、ダイアログを閉じ、結果をトーストで表示しなければならない（MUST）。成功は成功のトースト、断られたときは誤りのトーストとし、誤りのトーストは理由を2行目に出す。
衝突のため自動マージの依頼になった（202）とき、WUIは、エージェントが衝突を直したあとに自動でマージすることを知らせるトーストを出さなければならない（MUST）。
WUIは、マージの誤りをダイアログの中に残してはならない（MUST NOT）。
権限が無いと断られたとき、誤りのトーストは、受信箱のトークンに要る権限を名指さなければならない（MUST）。

#### Scenario: マージできた
- **WHEN** ダイアログで「マージする」を押し、マージが成功する
- **THEN** ダイアログが閉じ、`PR #73をマージしました` の成功のトーストが出る

#### Scenario: 衝突していた
- **WHEN** ダイアログで「マージする」を押し、202と `auto_merge_pending` が返る
- **THEN** ダイアログが閉じ、衝突を直したあとに自動でマージすることを知らせるトーストが出て、マージのボタンは「自動マージ待ち」で押せなくなる

#### Scenario: 画面が古い
- **WHEN** 画面を読んだ後にPRへコミットが足され、マージが `stale` で断られる
- **THEN** ダイアログが閉じ、開き直すよう促す誤りのトーストが出る

#### Scenario: 権限が無い
- **WHEN** マージが `forbidden` で断られる
- **THEN** 誤りのトーストに、GitHubの `Pull requests` と `Contents` の書き込みと、GitLabの `api` のスコープが出る

## ADDED Requirements

### Requirement: 自動マージ待ちの印
完了のissueに `auto_merge` があるとき、WUIは、一覧の完了の行と詳細のペインに「自動マージ待ち」の印を出し、マージのボタンを押せなくしなければならない（MUST）。

#### Scenario: 依頼のある行
- **WHEN** `auto_merge` のある完了の行を、一覧で見る
- **THEN** 行に「自動マージ待ち」の印が出て、マージのボタンは押せない

### Requirement: 自動マージの取り消し
完了のissueに `auto_merge` があるとき、WUIは、詳細のペインに「自動マージを取り消す」のボタンを出さなければならない（MUST）。ボタンを押したとき、WUIは、確認のダイアログを開き、確かめてから取り消しを送らなければならない（MUST）。
取り消しの結果を、WUIはトーストで表示しなければならない（MUST）。

#### Scenario: 取り消す
- **WHEN** 詳細のペインで「自動マージを取り消す」を押し、ダイアログで取り消しを確かめる
- **THEN** issueの参照を付けて取り消しが送られ、取り消したことを知らせるトーストが出る

### Requirement: 自動マージの結果のトースト
一覧の `auto_merge_results` に、まだ見せていない件があるとき、WUIは、件ごとにトーストを出さなければならない（MUST）。マージした件は成功のトースト、打ち切った件は理由を2行目に出す誤りのトーストとする。人が取り消した件（理由 `user`）は、取り消したときにトーストを出しているので、出さない。
見せた件は、refと終えた時刻でブラウザのストレージに覚え、同じ件を2度出してはならない（MUST NOT）。

#### Scenario: 夜のあいだにマージされた
- **WHEN** 画面を閉じているあいだに依頼がマージで終わり、翌朝WUIを開く
- **THEN** `PR #73をマージしました` の成功のトーストが1回だけ出る

#### Scenario: 打ち切られた
- **WHEN** 依頼が `instruction` で打ち切られたあとにWUIを開く
- **THEN** 人の指示で実行が始まったため自動マージをやめたことを知らせるトーストが出る

### Requirement: 自動マージの取り消しのPOSTの検査
取り消しのPOSTについて、`<switchboard-web>` は、マージのPOSTと同じ検査をしなければならない（MUST）。本文がJSONであることと、`Origin` と `Host` が `<listen>` のアドレスと一致することである。
どちらかに当たらないPOSTを、`<switchboard-web>` は受信箱のサービスに渡してはならない（MUST NOT）。

#### Scenario: 外のWebページから送られる
- **WHEN** 別のオリジンのWebページが、WUIの取り消しのURLへPOSTを送る
- **THEN** 403が返り、依頼は残る
