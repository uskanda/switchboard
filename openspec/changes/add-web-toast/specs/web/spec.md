## ADDED Requirements

### Requirement: トースト
WUIは、一時的な知らせをトーストとして、受信箱と設定のどちらの画面でも表示できなければならない（MUST）。
トーストの種類は、通常、成功、警告、誤りの4つとし、種類ごとにDESIGN.mdの色と印を付ける。
トーストは✗のボタンを持ち、押すと消えなければならない（MUST）。
トーストは、既定では5秒で消えなければならない（MUST）。表示時間は、トーストを出す側が指定できる。マウスがトーストの上にある間と、フォーカスがトーストの中にある間は、時間を数えてはならない（MUST NOT）。
複数のトーストは、重ねずに縦へ並べ、新しいものを最も下に置く。同時に表示するのは5個までとし、6個目を出すときは最も古いものを消す。
トーストは画面の右下に出す。幅1024px未満では、下の端に全幅で出す。
誤りのトーストは`role="alert"`、ほかの種類は`role="status"`で読み上げさせる。

#### Scenario: 5秒で消える
- **WHEN** 表示時間を指定せずに、成功のトーストを出す
- **THEN** トーストが右下に表示され、5秒たつと消える

#### Scenario: マウスを載せている
- **WHEN** トーストを出した1秒後にマウスを載せ、10秒たってからマウスを外す
- **THEN** マウスを載せている間は消えず、外してから4秒たつと消える

#### Scenario: 6個目を出す
- **WHEN** 5個のトーストが表示されている間に、6個目を出す
- **THEN** 最も古いトーストが消え、表示は5個のままになる

### Requirement: 設定の画面の保存の結果
追加の指示の保存に成功したとき、WUIは、保存した欄の名前と、保存したことを、成功のトーストで表示しなければならない（MUST）。
保存の誤りは、トーストにせず、その欄の中に表示しなければならない（MUST）。

#### Scenario: 指示を保存する
- **WHEN** 設定の画面で、`gl:nas/sb`の欄に指示を書いて保存する
- **THEN** `gl:nas/sbの指示を保存しました`という成功のトーストが表示され、欄の中には知らせが残らない

## MODIFIED Requirements

### Requirement: issueの作成の結果の表示
作成に成功したとき、WUIは、ダイアログを閉じ、成功のトーストで、作ったissueの参照とフォージのページへのリンクを表示しなければならない（MUST）。リンクは新しいタブで開く。一覧の上には知らせを残さない。
作成が拒まれたとき、WUIは、ダイアログの中に理由を表示し、書いた内容を残さなければならない（MUST）。

#### Scenario: 作れた
- **WHEN** `gl:nas/sb`に、タイトル「Add a flag」で種別`plan`のissueを作る
- **THEN** ダイアログが閉じ、成功のトーストで`gl:nas/sb#7 を作りました`と、フォージで開くリンクが表示される

#### Scenario: フォージが拒んだ
- **WHEN** フォージがissueの作成を拒む
- **THEN** ダイアログは開いたままで、理由が表示され、タイトルと本文は残る

### Requirement: 追加の結果の表示
追加に成功したとき、WUIは、足したプロジェクトの参照を成功のトーストで表示し、プロジェクトの一覧を取り直さなければならない（MUST）。応答にwebhookの案内があれば、案内とコマンドは、トーストにせず、プロジェクトの一覧の下に表示する。
追加が拒まれたとき、WUIは、追加の欄に、拒まれた理由を表示しなければならない（MUST）。

#### Scenario: 中継を使う端末で足す
- **WHEN** `<agent.relay>`のある端末で、`gh:uskanda/notes`を追加する
- **THEN** 成功のトーストに`gh:uskanda/notes を追加しました`と表示され、一覧に`gh:uskanda/notes`が現れる。一覧の下には、`switchboard relay hook add gh:uskanda/notes`を実行するよう表示される

#### Scenario: 同じプロジェクトを足す
- **WHEN** 既にある`gh:uskanda/switchboard`を追加する
- **THEN** 追加の欄に、既にあることが表示される
