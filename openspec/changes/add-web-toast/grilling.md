# grilling 記録: add-web-toast

受信箱のWeb表示（WUI）に汎用のトーストを作り、新規issueの作成の知らせを、一覧の上に残す形からトーストに替える計画である（issue #66）。問いはissueのコメントで2回に分けて出し、返答もissueのコメントで受けた。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 成功と警告の色 | 成功の色のトークン（`success`、`on-success-container`、`success-container`と`dark-`の値）を足す。警告は`attention`を使い、通常は`surface-raised`の地と`outline`の枠にする。Do'sの一文を「待ちの理由、誤り、トーストの種類」に改める | Q1 = A |
| 出す位置 | 右下に出し、新しいものを下に積む。幅1024px未満では、下の端に全幅（左右に`lg`の余白）で出す | Q2 = A |
| 5秒で消えるときの例外 | 表示時間はトーストごとに指定でき、既定は5秒。マウスを載せている間と、フォーカスがトーストの中にある間はタイマーを止める（WCAG 2.2.1）。エラーも既定の5秒で消す | Q3 = A |
| トーストに移す範囲 | 新規issueの作成の知らせに加え、設定の画面の成功の知らせも移す | Q4 = B（推奨のAから変更） |
| 作り方 | ライブラリを使う | Q5 = B（推奨のAから変更） |
| 仕様の記録 | 新しい変更`add-web-toast`を作る。アーカイブは`add-web-issue-create`のあとにする | Q6 = A |
| 使うライブラリ | sonner。見た目なし（unstyled）にし、classNamesでDESIGN.mdのトークンを当てる。呼び出す側は`lib/toast.ts`の薄い層を通す | Q7 = A |
| スタックの見せ方 | 常に広げて縦に並べる（expand）。同時に見せるのは5個まで | Q8 = A |
| プロジェクトの追加の結果 | 「保存しました」と「追加しました」をトーストに移す。webhookの登録コマンドは、コピーできるよう欄の下に残す | Q9 = A |
| 設定の画面の誤り | 欄の中に残す。トーストに移すのは成功の知らせだけにする | Q10 = A |
| 計画 | issueのコメント6575831988の計画を、6575840268の`/ok`で承認した | 承認 |
