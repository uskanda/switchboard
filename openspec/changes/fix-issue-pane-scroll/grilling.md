# grilling 記録: fix-issue-pane-scroll

issue `gh:uskanda/switchboard` #67の計画である。1件の画面で、待ちのissueを開いた直後に、返答に要るコメントが見える位置までスクロールする。参照、タイトル、状態の行は、スクロールしても上に残す。grillingは、issueのコメントで計画を先に立てるモードとして行った。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 待ちのissueでスクロールする先 | エージェントの最新の質問のカード（`primary`の枠で目立たせているカード） | 第1ラウンド Q1 |
| 開いた直後にスクロールする状態 | 待ちと完了 | 第1ラウンド Q2 |
| いつスクロールするか | 開いた直後の1回だけ。キャッシュを先に描いたときはその時点で1回。開いている間の自動更新では位置を変えず、画面の下に「自動更新がありました」の知らせを出し、押すとスクロールする | 第1ラウンド Q3 |
| 固定する見出し | 参照、タイトル、状態の行と、スマホの「← 一覧へ」を固定する。スクロールしている間はタイトルを2行で切り、全文はtitle属性に持たせる。一番上では全文を出す | 第1ラウンド Q4 |
| 完了のissueでスクロールする先 | エージェントの最新の完了の報告（kindがdone）。無ければスレッドの最後のカード | 第2ラウンド Q5 |
| 知らせを出す条件 | 読み直しで、表示するカードが増えたときだけ。進捗のカードの書き換えも新しいカードとして数える。開いた直後の読み直しでは出さない | 第2ラウンド Q6 |
| 知らせを押したときの行き先 | 待ちと完了は開いた直後と同じカード。ほかの状態は、新しく加わったカードの最初のもの | 第2ラウンド Q7 |
| 知らせが消えるとき | 押したとき、行き先のカードを自分のスクロールで画面に入れたとき、別のissueへ移ったとき。×のボタンは置かない | 第2ラウンド Q8 |

## 後回しにしたもの

- 実行中と順番待ちのissueを開いた直後のスクロール。自動更新で中身が変わり続けるためである
