# grilling 記録: add-web-project-add

対象のプロジェクト（`config.yaml` の `projects`）を、受信箱のWeb表示（`switchboard-web`）から追加できるようにする計画である。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 1回の追加で済ませる範囲 | `config.yaml` に項目を足し、ラベルの作成とcloneはエージェントが新しいプロジェクトを読んだときに自分のトークンで行う。webhookは案内だけにする | 第1ラウンド Q1 |
| 書き込み先 | `config.yaml` の `projects` に、yaml.v3のノードで1項目を足す。コメントと並びは残す。ADR-035の「設定ファイルを書き換えない」を新しいADRで改める | 第1ラウンド Q2 |
| 反映のしかた | エージェントと `inbox serve` が設定ファイルの変化を見て、`projects` だけを読み直す。ほかの節が変わっていても、それは読み直さずにログに残す | 第1ラウンド Q3 |
| WUIから決められる項目 | `ref` と `plan_first` だけ。`path` は `<親>/<repo名>` に固定し、`base_branch` はフォージの既定のブランチにする。`verify_command`、`include_untrusted`、`token_ref`/`agent_identity`、`protected_paths_extra` は手で編集したときだけ書ける | 第1ラウンド Q4 |
| 操作の範囲 | 追加だけ。編集と削除は `config.yaml` を手で行う | 第1ラウンド Q5 |
| `ref` の入力 | `gh:owner/repo` の形を手で入力し、受信箱のトークンで実在を確かめる | 第1ラウンド Q6 |
| 担当する端末 | WUIがつながる `inbox serve` の端末に固定する | 第1ラウンド Q7 |
| 機能の有効化と親ディレクトリ | `config.yaml` の新しいキー `<inbox.project_root>` に親を書く。キーが無ければ追加は無効にし、画面に有効にする方法を示す | 第2ラウンド Q8 |
| cloneの仕方 | フォージのhttpsのURLから、エージェントのトークンを `GIT_ASKPASS` で渡してcloneする。`path` が既にあって `origin` がそのプロジェクトでなければ、そのプロジェクトを扱わずにログに残す | 第2ラウンド Q9 |
| この端末で使っていないフォージ | 追加を拒み、`config.yaml` に手で足して `switchboard service install` を実行し直すよう示す | 第2ラウンド Q10 |
| 状態の見せ方 | 設定の画面のプロジェクトの一覧に、`inbox serve` が調べた状態（`path` のクローンの有無、状態ラベルの有無）を出す | 第2ラウンド Q11 |
| 画面の置き場所 | 既存の設定の画面に「プロジェクト」の節を足し、指示の節より上に置く。この端末の担当プロジェクトの一覧と追加の欄を並べる | 第2ラウンド Q12 |
| `plan_first` の欄の初期値 | オン | 第2ラウンド Q13 |
| 読み直しの細部 | 10秒ごとに更新の時刻と中身のハッシュを確かめる。検証を通らなければ前の設定のまま動き、ログに残す。`projects` 以外の変化は再起動まで反映しないとログに残す。手で消されたプロジェクトは扱わなくなり、実行中の実行は最後まで続ける。ほかの端末の担当の変化も同じく反映する | 第2ラウンド Q14 |
| 書き込みの細部 | 読んだときと書く直前のハッシュが違えば書かずに誤りを返す。足したあとの内容を検証に通し、一時ファイルに書いて置き換える。元を `<config.yaml.bak>` に1世代残す。シンボリックリンクならリンク先を書き換える。同じ `ref` があれば拒む | 第2ラウンド Q15 |
| webhookの案内 | エージェントの設定に `<agent.relay>` があるときだけ、`switchboard relay hook add <ref>` の実行を案内する | 第2ラウンド Q16 |
| ラベルの作成と失敗の扱い | 読み直しで新しく現れたプロジェクトについて、cloneのあとに6つの状態ラベルを作る。cloneかラベルが失敗したら、そのプロジェクトは扱わずにログに残し、次の照合でやり直す。起動時の既存のプロジェクトの扱いは変えない。クローンが無いときは、エージェントのトークンの対象を確かめるよう画面に示す | 第3ラウンド Q17 |
| 土台にするブランチ | `add-web-two-pane-live` がmainに入ってから、mainを土台に実装する。成果物は今のブランチで書き、実装の前に新しいブランチへ移す | 第3ラウンド Q18 |
| 書き込みのPOSTの検査 | 既存のPOSTと同じく、本文がJSONであることと、`Origin`/`Host` が `<listen>` と一致することを確かめる | 第3ラウンドのまとめで確認 |
