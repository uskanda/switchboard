## MODIFIED Requirements

### Requirement: 計画の実行の終了の宣言
計画の実行では、エージェントは、実装の実行とは別のスキーマを `--json-schema` で渡さなければならない（MUST）。
宣言は `status`（`questions` か `plan`）と `title` を必ず持つ。`title` は、承認してもらう計画、または質問の後で立てる計画の題を1行で言う。`questions` のときは、題、本文、推奨の答えを持つ質問を1つ以上並べた配列を持つ。`plan` のときは、計画の本文を持つ。
宣言が無いか、スキーマに合わないとき、エージェントは、実行を `waiting(reason=error)` として扱わなければならない（MUST）。`title` が無いか空白だけのときも、スキーマに合わないものとして扱う。

#### Scenario: 質問を宣言する
- **WHEN** 計画の実行が、`status: questions` と題と質問2つを宣言して終わる
- **THEN** resultの `structured_output` から、計画の題と、2つの質問の題、本文、推奨の答えが読み取られる

#### Scenario: doneを宣言する
- **WHEN** 計画の実行が `status: done` を宣言して終わる
- **THEN** スキーマに合わないので、issueは `waiting(reason=error)` になる

#### Scenario: 題の無い宣言
- **WHEN** 計画の実行が、`title` の無い `status: plan` か、空白だけの `title` を宣言して終わる
- **THEN** issueは `waiting(reason=error)` になる

### Requirement: 質問のコメント
計画の実行が `questions` を宣言したとき、エージェントは、質問をまとめた1件のコメントを投稿し、issueを `agent:waiting` にしなければならない（MUST）。マーカーの `reason` は `plan-questions` とする。
コメントの見出しのすぐ次に、計画の題を1行にまとめた段落を、`**計画：** 〈題〉`（英語では `**Plan:** 〈title〉`）の形で置かなければならない（MUST）。
質問には、今の周期を通した番号を振らなければならない（MUST）。番号は、今の周期のそれまでの質問のコメントの最後の番号の次から始める。各質問には、題、本文、推奨の答えを書く。
コメントの最後に、推奨どおりなら承認の語だけを、変えたい問いがあれば承認の語に続けて上書きを書くよう案内する1行を書かなければならない（MUST）。

#### Scenario: 2ラウンド目の質問
- **WHEN** 1ラウンド目でQ1からQ3を聞いた周期で、計画の実行が質問2つを宣言する
- **THEN** 投稿されたコメントの質問はQ4とQ5で、それぞれに推奨の答えが付いている

#### Scenario: 質問のコメントの題
- **WHEN** 日本語のコメントの設定で、計画の実行が題「設定の読み込みを分ける」と質問を宣言する
- **THEN** 投稿されたコメントの見出しの次の段落は `**計画：** 設定の読み込みを分ける` である

### Requirement: 計画のコメント
計画の実行が `plan` を宣言したとき、エージェントは、計画を書いた1件のコメントを投稿し、issueを `agent:waiting` にしなければならない（MUST）。マーカーの `reason` は `plan` とする。
コメントの見出しのすぐ次に、計画の題を1行にまとめた段落を、`**計画：** 〈題〉`（英語では `**Plan:** 〈title〉`）の形で置かなければならない（MUST）。計画の本文はその後に続ける。
コメントの最後に、承認は承認の語で、直しはそのまま返答で伝えるよう案内する1行を書かなければならない（MUST）。

#### Scenario: 質問をせずに計画を出す
- **WHEN** 計画の最初の実行が、質問をせずに `plan` を宣言する
- **THEN** 計画のコメントが投稿され、issueは `agent:waiting` になり、マーカーの `reason` は `plan` である

#### Scenario: 計画のコメントの題
- **WHEN** 英語のコメントの設定で、計画の実行が題「Split the config loading」と計画を宣言する
- **THEN** 投稿されたコメントの見出しの次の段落は `**Plan:** Split the config loading` で、計画の本文はその後に続く
