# grilling 記録: add-setup-command

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 依存を用意する方法 | プロジェクトの設定に書いた準備のコマンドを、エージェントがclaudeの起動前に作業ツリーで走らせる。本体のクローンの `node_modules` を参照する案と、sandboxにレジストリへの接続を許す案は採らない。 | 第1ラウンド Q1 |
| 準備のコマンドを走らせる実行の種類 | すべての実行（計画の実行、承認のあとの実行、直す実行）。 | 第1ラウンド Q2 |
| 準備のコマンドが失敗したときの扱い | claudeを起動せず、実行を誤りで終える。コメントにコマンドと出力の末尾を書く。 | 第1ラウンド Q3 |
| 設定の名前と置き場所 | `<projects[].setup_command>` だけを足す。全プロジェクト共通の既定は作らない。 | 第2ラウンド Q4 |
| 準備のコマンドを走らせる時機 | 実行のたびに、作業ツリーの準備のあと、claudeの起動の前。ロックファイルの変化はswitchboardが検出しない。 | 第2ラウンド Q5 |
| 準備のコマンドを走らせる場所 | sandboxの外。`verify_command` と同じ環境で走らせ、フォージのトークンを渡さない。専用のsandboxをbwrapで作る案は採らない。 | 第2ラウンド Q6 |
| 準備のコマンドの時間の上限 | `<agent.timeout>` を使う。専用の項目は足さない。 | 第2ラウンド Q7 |
| claudeが準備のコマンドを自分で走らせること | 許さない。sandboxの外で動くのは、今までどおり `git` と `verify_command` だけとする。 | 第2ラウンド Q8 |
| 記録とclaudeへの知らせ方 | 監査ログに `<setup.ran>` を残す（コマンド、かかった時間、成否）。出力は実行のディレクトリの `<setup.log>` に残す。システムプロンプトに、依存は用意済みであることと、sandboxからは取得できないことを書く。 | 第2ラウンド Q9 |
| 準備のコマンドがworktreeにgitから見える変更を残したときの扱い | 準備の失敗にする。claudeを起動せず、コメントに変更されたパスを書く。変更をそのまま残す案と、捨てて続ける案は採らない。 | 会話中に確認（設計の途中の追加の質問） |
| この変更に含める文書 | ADRを1つ足す。`docs/GUIDE.md` と `docs/SECURITY.md` は日本語と英語の版を直す。 | 会話中に確認 |
| 変更の名前 | `add-setup-command` | 会話中に確認 |

## 後回しにしたもの

- claudeが依存を足す変更をしたときに、同じ実行の中で依存を取得する手段（第2ラウンドのQ8）。必要になったら別の変更で扱う。
- 回避できた拒否が1件でもあると、待ちの理由が `permission` になる問題。smarternewsのissueの107番の調査で見つけたが、この変更には入れない。
