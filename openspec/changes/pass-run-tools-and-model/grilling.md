# grilling 記録: pass-run-tools-and-model

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 実行に渡すツールの絞り方 | 固定のリストにし、利用者が足すツールを設定から足せるようにする。計画の実行はEditとWriteを渡さない | 第1ラウンド Q1 |
| WebSearchの扱い | 既定のツールに入れ、許可リストにも足す。計画の実行にも渡す | 第2ラウンドの回答に追記 |
| `--setting-sources` を今回入れるか | 入れない。sandboxの扱いと一緒に #130 で決める | 第1ラウンド Q2 |
| モデルとeffortの設定の形 | Claude固有でない名前にする。既定の値を置き、計画と修正で上書きできる。空ならフラグを付けない | 第1ラウンド Q3 |
| 製品の既定と利用者の値 | 製品の既定は空。利用者の設定では全種類をopusとmediumにする | 第1ラウンド Q4 |
| 設定の置き場所と名前 | <agent.model>、<agent.effort>、<agent.plan>、<agent.fix>。`claude.binary` と `claude.auth` は残す | 第2ラウンド Q5 |
| 足すツールの範囲 | 全体とプロジェクトの両方から足し、全体、プロジェクトの順につなげる。`WebFetch` は読み込みで誤りにする。計画の実行には足さない | 第2ラウンド Q6 |
| 足すツールの指定の場所 | 別の設定は作らない。`<agent.allow_tools_extra>` と `<projects[].allow_tools_extra>` の各項目のツール名を、渡すツールにも足す | 第3ラウンド Q9 |
| コードの抽象化の範囲 | 設定の名前だけを汎用にする。`claudecode.Request` にModel、Effort、Toolsを足す | 第2ラウンド Q7 |
| effortの値の検査 | 読み込みのときに、アダプタが持つ許容値の一覧で検査する。モデル名は検査しない | 第2ラウンド Q8 |
