# Design

## Context

動機はproposal.mdのWhyを参照する。マージ（ADR-043）は、受信箱のサービスが受信箱のトークンで行う。前提として、issueがopenで `agent:done` であることと、最新のdoneの投稿のマーカーの `cr` と `sha` を確かめている。フォージの層には、エージェントがCIを見張るための `forge.CI` が既にある。コミットのチェックと、PR/MRの状態・head・衝突を読む。GitHubとGitLabの実装と、テスト用の偽物もある。衝突の判定はADR-044で決めてある。

## Goals / Non-Goals

**Goals:**
- 既存の `forge.CI` を受信箱のトークンのクライアントでそのまま使い、新しいフォージのAPIを足さない
- マージと同じ前提の確かめ方を共有し、ダイアログが見せるPR/MRとマージするPR/MRを食い違わせない

**Non-Goals:**
- 一覧の行にCIを出すこと（第1ラウンドQ2で採らなかった）
- 衝突やCIの失敗でマージを止めること（第1ラウンドQ3で採らなかった）
- 状態のキャッシュ。ダイアログを開くたびに読む

## Decisions

- **計算中は `Conflict` と別の印にする。** `forge.ChangeRequestState` に `Computing` を足す。GitHubでは `mergeable` が `null` のopenのPR、GitLabでは `detailed_merge_status` が `checking` か `unchecked` のときに立てる。`Conflict` の意味は変えないので、ADR-044の見張りの動きは変わらない。GitLabで `unchecked` かつ `has_conflicts` のときは、両方の印を立てる。そのときダイアログは衝突ありを優先する。`Conflict` に計算中を混ぜる案は、見張りが計算中を衝突とみなすおそれがあるので採らなかった。
- **前提の確かめ方をマージと共有する。** 受信箱の中で、doneのマーカーを取り出して前提を確かめる処理を1つにまとめ、マージと状態の読み出しの両方から呼ぶ。誤りの文の終わりだけ、何をしなかったかに合わせて変える。
- **CIはマーカーの `sha` のコミットを読む。** PR/MRのheadが動いていても、マージされるのはマーカーのコミットだけなので、そのコミットのCIを出す。headが動いたことは `head_moved` で別に知らせる。
- **CIの権限の誤りだけを状態に変える。** `CommitChecks` が `ErrForbidden` のときは `ci=forbidden` にして、衝突の結果は返す。ほかの誤りは誤りとして返す。どちらもダイアログでは「読めなかった」と出るだけで、マージは押せる。
- **PR/MRとCIは同時に読む。** スマホからダイアログを開いたときの待ちを短くするため、2つの呼び出しを並べる。どちらもフォージの読み取りだけである。
- **口は `CI` の地図があるときだけ出す。** 受信箱のサービスの `Server` に、フォージの種類ごとの `forge.CI` を持たせる。`Merges` と同じく、無ければ404にする。`cmd/switchboard` は、受信箱のトークンのクライアントのうち `forge.CI` を満たすものを渡す。
- **WUIの口は読み取りとして扱う。** `GET /api/merge-status` は `/api/issue` と同じく、`Origin` の検査をかけずに中継する。何も書かず、返すのは同じ画面が既に読める範囲の情報だからである。
- **チェックの名前とURLは非信頼のデータとして描く。** 名前はReactの文字列として描く。URLは `http` か `https` で始まるときだけリンクにし、`javascript:` などを開かせない。
- **遅れて届いた結果を捨てる。** ダイアログを開くたびに番号を進め、閉じたときにも進める。応答が届いたときに番号が違えば捨てる。

## Risks / Trade-offs

- 危険：GitHubのCommitChecksは、runの一覧、runごとのジョブ、ステータスと複数の呼び出しになる → ダイアログを開いたときの1件だけにし、一覧では呼ばない
- 危険：受信箱のトークンの権限が広がる → 足すのは読み取りだけで、無ければCIが出ないだけにする。`switchboard doctor` が警告する
- 危険：GitHubの `mergeable` は計算に数秒かかり、開いた直後は計算中になりやすい → 計算中と出すだけにし、開き直せば読み直す

## Migration Plan

GitHubの受信箱のトークンに、ActionsとCommit statusesの読み取りを足す。トークンの値は変わらないので、登録し直しは要らない。足す前も、ダイアログにCIの権限の無いことが出るだけで、ほかは動く。戻すときは、この変更を戻せば、口が消えてダイアログが元に戻る。
