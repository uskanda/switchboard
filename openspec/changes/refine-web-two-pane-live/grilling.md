# grilling 記録: refine-web-two-pane-live

grillingは行っていない。issue #19を、switchboardのエージェントが無人で実行したためである。要件はissueの本文から取り、決めたことを下に並べた。覆す場合は、PRのレビューで指摘する。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 画面の組み方 | ヘッダと2つのペインにする。左に一覧、右に選んだissueの全文と返答の欄を出す | issue #19 |
| スマホの幅 | 幅768px未満では、ペインを1つだけ出す。`/` で一覧、`/issue/:ref` で1件を出し、1件の上に一覧へ戻るリンクを置く | エージェントの判断 |
| 自動更新の仕組み | `switchboard-web` が、開いている画面へServer-Sent Eventsで一覧を送る。一覧は5秒ごとに受信箱のサービスへ求め直し、変わったときだけ送る | issue #19（「SSE等」）とエージェントの判断 |
| 選んだissueの更新 | 一覧の項目（待ちの開始、理由、質問）が変わったとき、または一覧から消えたときに、詳細を取り直す。詳細のために別の流れは作らない | エージェントの判断 |
| 受信箱のサービスのキャッシュ | 60秒から30秒に縮める。画面に変化が出るまでの遅れは、最大で35秒ほどになる | エージェントの判断（V14、V27） |
| 中継のイベントを使うか | 使わない。受信箱のサービスが中継を購読する形は、別の変更にする | エージェントの判断 |

## 先送り

- 中継のイベントで受信箱のキャッシュを捨て、遅れを数秒にすること
- GitHubの受信箱をGraphQLの1リクエストにする切り替え（V14）
