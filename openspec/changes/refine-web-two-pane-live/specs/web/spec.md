## MODIFIED Requirements

### Requirement: 画面
画面は、ヘッダと、その下の2つのペインで組まなければならない（MUST）。左のペインは待ちの一覧、右のペインは一覧から選んだissueである。
一覧は、`switchboard inbox` と同じ項目を、待ちが始まった古い順に表示しなければならない（MUST）。届かなかったフォージがあれば、そのことも示す。選んでいるissueは、一覧の中で見分けられるようにする。
選んだissueのペインは、質問の全文、拒否された操作、フォージのissueへのリンク、返答の欄を表示しなければならない（MUST）。
幅の狭い画面では、ペインを1つずつ出してよい（MAY）。そのときは、issueのペインから一覧へ戻れるようにする。
画面は、デスクトップとスマホのどちらの幅でも、横へのスクロール無しで使えなければならない（MUST）。
issueから来た文字列（タイトル、質問）は、テキストとして表示し、HTMLとして解釈させてはならない（MUST NOT）。
画面の静的ファイルは、すべて `<switchboard-web>` に埋め込み、外のCDNから読み込んではならない（MUST NOT）。

#### Scenario: 一覧から選ぶ
- **WHEN** デスクトップの幅で、一覧のissueを1つ選ぶ
- **THEN** 一覧を出したまま、右のペインにそのissueの質問の全文と返答の欄が出る

#### Scenario: スマホの幅で開く
- **WHEN** 幅360pxのブラウザで一覧を開き、issueを1つ選ぶ
- **THEN** 横へのスクロール無しで、そのissueの質問を読み、返答を書いて送れ、一覧へ戻れる

#### Scenario: タイトルにHTMLが含まれる
- **WHEN** タイトルが `<script>` を含む待ちのissueを一覧に出す
- **THEN** その文字列がそのまま表示され、スクリプトは動かない

## ADDED Requirements

### Requirement: 自動更新
画面を開いている間、`<switchboard-web>` は、一覧の変化を画面へ送らなければならない（MUST）。送る仕組みはServer-Sent Eventsとし、受信ポートを増やさない。
`<switchboard-web>` は、受信箱のサービスへ一覧を数秒おきに求め直し、項目か届かなかったフォージが変わったときだけ送る。返答を投稿したら、すぐに求め直す。
画面は、選んだissueの一覧の項目（待ちの開始、理由、質問）が変わったとき、または一覧から消えたときに、そのissueの詳細を取り直さなければならない（MUST）。
フォージへの問い合わせの回数は、開いている画面の数で増えてはならない（MUST NOT）。
画面は、更新の流れがつながっているかどうかを示す。

#### Scenario: 待ちが増える
- **WHEN** 一覧を開いたままの間に、別のissueが待ちになる
- **THEN** 再読み込みせずに、そのissueが一覧に出る

#### Scenario: 選んだissueが待ちでなくなる
- **WHEN** issueを選んで開いている間に、そのissueが待ちでなくなる
- **THEN** 返答の欄が消え、待ちではないことが表示される

#### Scenario: 受信箱のサービスが止まる
- **WHEN** 画面を開いている間に、`switchboard inbox serve` が止まる
- **THEN** 受信箱のサービスに届かないことが表示され、サービスが戻ると一覧が戻る
