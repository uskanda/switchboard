# Proposal

## Why

switchboardのCLI、エージェントのコメント、Telegramの通知は英語で出せる。一方で、Web表示、Androidのアプリ、紹介ページ（GitHub Pages）、READMEと手引きは日本語だけである。日本語を読めない利用者は、受信箱で返答できず、導入の手順も読めない。ADR-025はOSSの利用者に英語で読める製品を目指しており、残る日本語だけの部分を日英の両方に対応させる。

## What Changes

- Web表示の文言を日本語と英語の辞書に移し、表示の言語で出す。既定はブラウザの言語で決め、日本語なら日本語、それ以外は英語にする
- 設定の画面を全員に開き、全員が使える「表示」の節に言語の選択（自動・日本語・English）を置く。選んだ値はブラウザごとに保存する。指示の編集とプロジェクトの追加の節は、今までどおり管理者だけに出す
- ログインの画面に、もう一方の言語へ切り替えるボタンを置く
- `<html lang>`、タブのタイトル、相対時間、件数、日時を表示の言語で出す。英語では単数と複数を表し分ける
- 理由のバッジの英語の名前を決める。語だけでは分かりにくい理由にだけ短い名前を付ける
- 計画の質問への返答と再実行の依頼をissueに投稿するとき、表示の言語で書く
- Androidのアプリの画面、通知のボタン、通知の文を、端末の言語で出す
- 紹介ページを、英語をルート（`/`）、日本語を `/ja/` に分ける。互いへのリンクと `hreflang` を付ける
- `README.md`、`docs/GUIDE.md`、`docs/SECURITY.md` を英語にする。日本語の版は、それぞれ `<README.ja.md>`、`<docs/GUIDE.ja.md>`、`<docs/SECURITY.ja.md>` に移す
- ADR-065を足し、ADR-025の言語の方針とPRODUCT.mdの「文言は日本語とする」を改める

## Capabilities

### New Capabilities

- `ui-language`: Web表示、Androidのアプリ、紹介ページで、文言を日本語と英語のどちらで出すかの決め方、切り替え、言語ごとの書き方

### Modified Capabilities

- `web`: 理由のバッジの名前を、日本語と英語のそれぞれで決める。設定の画面を管理者でない人にも開き、表示の節だけを出す

## Impact

- Web表示（`web/ui/src`）：辞書と言語の決め方の仕組みを足し、ほぼすべての部品の文言を辞書に移す。今のテストは日本語を既定にして通し、英語の表示のテストを足す
- Androidのアプリ（`app/src`）：画面と通知の文言を言語ごとに分け、端末の言語で選ぶ
- 紹介ページ（`site/`）：英語の `site/index.html` と日本語の `<site/ja/index.html>` に分ける。`.github/workflows/pages.yml` は変えない
- 文書：README、GUIDE、SECURITYの英語版と日本語版を作り、ADR-065を足す。PRODUCT.md、DESIGN.md（バッジ、時間の書き方、和文の前提）、`docs/ARCHITECTURE.md` のファイルの一覧を直す。AGENTS.mdに、両方の版を保つ規則を足す
- Goのコード、APIの形、設定のキーは変えない。サーバーが返す英語の誤りの文は、そのまま出す
