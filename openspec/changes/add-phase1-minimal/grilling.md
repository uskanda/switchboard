## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| switchboardとuskn-loopの関係 | switchboardを独立した製品として作り、実行器も持つ。uskn-loopは、switchboardが形になった後にswitchboardを前提にした形へ整理する | 第1ラウンド Q1 |
| 「待ち」の定義 | 実行が人間への質問を残して終わり、返答を待っている状態と定義し直す | 第1ラウンド Q2 |
| 手で開いた対話セッションの扱い | Phase 1では対象外とし、issueから起動した作業だけを受信箱に出す | 第1ラウンド Q3 |
| エージェントが投稿するアカウント | Phase 1はマスターと同じアカウントとし、エージェントの投稿はマーカーで見分ける。別アカウントへの移行はPhase 3とする | 第1ラウンド Q4 |
| 実行の隔離を入れる時期 | Phase 1は環境変数の除去だけとし、非公開リポジトリかつマスターだけが書けるissueに限って運用する。専用OSユーザーはPhase 3で入れる | 第1ラウンド Q5 |
| 非信頼コメントの扱い | 既定ではプロンプトにまったく含めない。非公開リポジトリに限り、プロジェクトの設定で含められる | 第1ラウンド Q6 |
| 技術スタック | Goとし、CLI・常駐エージェント・フック・中継を単一バイナリのサブコマンドにする | 第2ラウンド Q1 |
| フォージへの書き込みとpushの担当 | 親のエージェントが行い、Claudeのプロセスにはトークンを渡さない | 第2ラウンド Q2 |
| 実行時に読み込む設定 | ユーザー層の設定を読み込み、対象リポジトリのプロジェクト設定は読み込まない | 第2ラウンド Q3 |
| doneと判定する条件 | 終了プロトコルでの `done` の宣言、検証の成功、push前の出力検査の3つ。Phase 1では監査役を入れない | 第2ラウンド Q4 |
| done後に付いたコメントの扱い | 再実行しない。続きはマスターが `agent:ready` を付け直したときにだけ始める | 第2ラウンド Q5 |
| 最初のchangeの範囲 | Phase 0の検証を先に済ませ、結果をROADMAP.mdに記録してからPhase 1の成果物を書く | 第2ラウンド Q6 |
| verify-gateと待ちの関係 | 第3ラウンドで推奨したCは、第4ラウンド Q1の決定で置き換えた | 第3ラウンド Q1 |
| Phase 0の検証を行う場所 | CLIの挙動はクラウド環境で、認証とOSユーザーの項目はマスターの端末で確かめる。結果には環境と `claude` の版を併記する | 第3ラウンド Q2 |
| Phase 1の対象リポジトリ | 検証専用の非公開リポジトリを新しく作る | 第3ラウンド Q3 |
| Phase 1でエージェントを動かす端末 | マスターが普段使うmacOSの端末とし、手で起動する | 第3ラウンド Q4 |
| issueに書く文章 | 第3ラウンドで推奨した案は、第4ラウンド Q2の決定で置き換えた | 第3ラウンド Q5 |
| ハーネスへの依存 | 最終的に単体のOSSとして公開するため、ハーネスが無くても動く作りにする | 第3ラウンドへの回答（会話中に確認） |
| 検証コマンドの決め方 | プロジェクトごとの `verify_command` で決め、doneの判定でエージェントが実行する。未設定なら検証を省き、PRの本文に「検証なし」と書く | 第4ラウンド Q1 |
| issueに書くコメントの言語と検査 | 言語は設定で選び、既定は英語とする。投稿前の検査は任意の `comment_check_command` とし、既定では何もしない | 第4ラウンド Q2 |
| ソースコードと文書の言語 | 識別子、コードのコメント、CLIの出力は英語とする。docs/、ADR、OpenSpecの成果物は日本語で書き、英語版READMEは公開の準備で作る | 第4ラウンド Q3 |
| ライセンス | MIT | 第4ラウンド Q4 |
| Claudeの認証方式 | 設定で選べるようにし、既定はサブスクリプション（`ANTHROPIC_API_KEY` を除く）とする。APIキーは明示的に設定したときだけ渡す | 第4ラウンド Q5 |
| ハーネス非依存の確かめ方 | ハーネスを入れないCIで結合テストを実行し、製品のコードと既定の設定に `uskn` が現れないことをテストで確かめる | 第4ラウンド Q6 |
| grillingの記録先 | このchangeに `grilling.md` だけを記録し、残りの成果物はPhase 0の結果を見てから続きモードで作る | 第5ラウンド Q1 |
| 決定の反映先 | 設計判断はDECISIONS.mdにADRとして追加し、DESIGN.mdも直す。PR #1のマージ後のため、新しいPRで行う | 第5ラウンド Q2（PR #1のマージ後に会話中に確認） |
| 作業の順序 | PR #2のマージ後に、作り直した作業ブランチで記録する | 第5ラウンド Q4（会話中に確認） |
