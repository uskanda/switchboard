## MODIFIED Requirements

### Requirement: 質問のコメントの画像
質問が画像を持つとき、エージェントは、画像をフォージに付け、問いと選択肢の位置に置かなければならない（MUST）。
問いの画像は、本文と選択肢の行の間に置く。選択肢の画像は、その選択肢の行の直後の、別の行に置く。選択肢の行（`A: 文`）の形は変えない。
GitLabのプロジェクトでは、エージェントは、画像をそのプロジェクトにアップロードし、返った画像の記法を質問のコメントに置く。アップロードに失敗した画像は、検査で捨てた画像と同じに扱わなければならない（MUST）。
GitHubのプロジェクトでは、エージェントは、画像の位置に目印を置いた本文を、画像を添付して投稿する。そのあと、添付で末尾に付いた画像の記法を目印の位置へ移すように、そのコメントを編集しなければならない（MUST）。編集のあとのコメントは、末尾に画像を残さず、マーカーで終わる。
GitHubで、編集に失敗したとき、エージェントは、編集を1度だけやり直さなければならない（MUST）。それでも失敗したら、そのコメントを消し、画像なしで投稿し直さなければならない（MUST）。添付の投稿そのものに失敗したときも、画像なしで投稿し直す。投稿し直した質問では、すべての画像を、検査で捨てた画像と同じに扱う。図は残す。

#### Scenario: 問いと選択肢の画像
- **WHEN** GitLabのプロジェクトで、問いの画像と、選択肢Bの画像を持つ質問を投稿する
- **THEN** コメントでは、本文のあとに問いの画像、`A: 文` の行、`B: 文` の行、Bの画像、の順に並ぶ

#### Scenario: アップロードの失敗
- **WHEN** GitLabのアップロードのAPIが500を返す
- **THEN** 質問は画像なしで投稿され、画像を付けられなかったことが1行書かれる

#### Scenario: GitHubでの問いと選択肢の画像
- **WHEN** GitHubのプロジェクトで、問いの画像と、選択肢Bの画像を持つ質問を投稿する
- **THEN** コメントは1件で、本文のあとに問いの画像、`A: 文` の行、`B: 文` の行、Bの画像、の順に並び、最後の行はマーカーである

#### Scenario: GitHubで編集に2度失敗する
- **WHEN** GitHubのプロジェクトで、画像を添付して投稿できたが、画像を移す編集が2度とも失敗する
- **THEN** そのコメントは消え、質問は画像なしで投稿し直され、画像を付けられなかったことが1行書かれ、監査ログに `<plan.image_dropped>` が残る

#### Scenario: GitHubで添付の投稿に失敗する
- **WHEN** GitHubのプロジェクトで、`gh issue comment --attach` が失敗する
- **THEN** 質問は画像なしで投稿され、図を持つ問いでは図が残る

### Requirement: 画像の指示
ブラウザが見つかるとき、エージェントは、GitLabのプロジェクトの計画の実行への指示に画像の項を入れなければならない（MUST）。GitHubのプロジェクトでは、ブラウザが見つかり、さらに `gh` が `--attach` を持つとき（2.99.0以上）に入れなければならない（MUST）。それ以外のときは、入れてはならない（MUST NOT）。
画像の項は、GitLabとGitHubで同じものとし、次のことを伝えなければならない（MUST）。
- 1つの問いには、Mermaidの図か画像のどちらか1つを付ける。画面の見た目や変化はスクリーンショット、流れや状態の移り変わりはMermaidを目安にする
- Mermaidでは描きにくい説明（配置や大きさ、並べた比較、前後の比較、印を付けた表、まだ無い画面のラフ）は、HTMLで描いて撮った画像にしてよい。HTMLは画像の置き場所に書き、外から何も読み込まない
- スクリーンショットへの説明には、枠と矢印のラベルか、撮る前のJSが足す短い説明を使う
- 画像は `<switchboard shot>` で撮り、`.switchboard/plan-images/` に置く。アプリの起動のしかたはプロジェクトの指示に従う。サーバーの起動と撮影は1回のコマンドの中で行う
- 変更後の見た目は、次の順に試し、足りるところで止める。①今の画面に注記を付ける。②撮る前のJSでDOMやCSSを書き換える。③worktreeを一時的に書き換えて試作する。③は、`<projects[].plan_prototype>` が有効なときだけ伝える
- 問いの画像には今の画面を、選択肢の画像にはその案を選んだあとの画面を置く
- 形式と枚数の上限

#### Scenario: GitHubのプロジェクト
- **WHEN** ブラウザが見つかり、`gh` が2.103.3の端末で、GitHubのプロジェクトの計画の実行を始める
- **THEN** 指示に、GitLabと同じ画像の項が入る

#### Scenario: 古いgh
- **WHEN** ブラウザが見つかり、`gh` が2.98.0の端末で、GitHubのプロジェクトの計画の実行を始める
- **THEN** 指示に画像の項は入らず、Mermaidの図の項だけが入る

#### Scenario: 描いた画像
- **WHEN** GitLabのプロジェクトの計画の実行が、3つの案を並べたHTMLを `.switchboard/plan-images/` に書き、ループバックで配って撮った画像を問いの画像として宣言する
- **THEN** その画像は、スクリーンショットと同じ検査を通って、問いの画像として投稿される

#### Scenario: 試作を許していないプロジェクト
- **WHEN** `<projects[].plan_prototype>` が無効なGitLabのプロジェクトの計画の実行を始める
- **THEN** 画像の項は入るが、③の試作は伝えられない
