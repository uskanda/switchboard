## 4. 書き戻しの再試行（#26、`agent`）

- [x] 4.1 書き戻しの再試行の一覧と、ポーリングごとの処理を作る（design D2、D3の2）。失敗するテストから始め、次を確かめる。待ちへの付け替えが1回失敗したら、次のポーリングで `agent:waiting` になり、質問のコメントが1件のままであること。書き戻しの最初の `Thread` が失敗したら、次のポーリングでコメントが投稿されること。監査ログに、最初の失敗と成功が1回ずつ記録されること。GitLabで待ちにしたとき、ノートの数が記録されること
- [x] 4.2 再試行で待ちにしたとき、返答が届いていれば次の実行を始める。付け替えの失敗の間にマスターが返答を書くと、次のポーリングで待ちを経て `agent:running` に戻ることをテストで確かめる。設定から消えたプロジェクトでは、再試行は続き、次の実行は始まらないことも確かめる
- [x] 4.3 再試行でラベルを変えない場合を作る（design D3の3と4）。次の3つで、ラベルが変わらないことをテストで確かめる。1つ目は、issueがcloseされた場合で、未投稿の完了のコメントが投稿され、通知は送られない。2つ目は、マスターがラベルを `agent:ready` に変えた場合。3つ目は、別の実行の着手のコメントが後にある場合である。どれも、そのあと再試行が行われないことを確かめる
- [x] 4.4 着手のときの付け替えの失敗を、同じ一覧で扱う。`SetLabels` が成功して取り直しが失敗したら、次のポーリングで待ち（reason=error）になり、中断のコメントが付くことをテストで確かめる。`SetLabels` が失敗したら、次のポーリングで着手がやり直され、`agent:running` になることも確かめる
- [x] 4.5 起動時の回復で、issueごとの書き戻しの失敗を一覧に入れ、起動を続ける（design D2）。回復のコメントの投稿が1回失敗しても、`Start` が成功し、次のポーリングでそのissueが待ちになることをテストで確かめる。`agent:running` のissueの検索が失敗したら、`Start` が失敗することも確かめる
- [x] 4.6 実行の記録に状態 `<writeback>` を足し、`switchboard agent status` で書き戻し待ちとして表示する。エージェントが動いているときと、動いていないときの表示を、`status` のテストで確かめる
- [x] 4.7 README.mdの実行の節に、書き戻しの再試行と、`switchboard agent status` の書き戻し待ちの表示を書く。`docs/DESIGN.md` の9章の、フォージのAPIの失敗の行を、ポーリングごとの再試行に書き直す。textlintが通ることを確かめる
