# Proposal

## Why

2026-10-31の監査で、issueの動かなくなる不具合を3つ見つけた。止まったissueは受信箱の待ちの欄に出ず、通知も届かない。そのため、人が気付くか、エージェントを再起動するまで動かない。

- #25：着手の途中にポーリングがそのissueを評価すると、実行が取り消される。issueは `agent:running` のまま止まる。
- #26：書き戻しが一時的に失敗すると、issueは `agent:running` のまま止まる。人が返答しても実行されない。
- #27：評価が一時的な失敗やキュー待ちで終わったissueを、`since` が追い越す。そのissueは次のポーリングの結果に出なくなり、`agent:ready` のまま動かない。キューの消化だけでなく、通常のポーリングでも起きる。

## What Changes

- 着手（着手のコメントからrunningへの付け替えまで）をポーリングと直列にする。待ちのあとの再実行と、実行の後のキューの消化を、ポーリングと同じロックの中で行う
- 書き戻しが終わっていない自端末の実行を一覧に持ち、ポーリングのたびに書き戻し直す
  - 書き戻すのは、issueがopenで、ラベルがrunningで、最新の着手のコメントがその実行のものであるときだけとする。外れたら、未投稿の結果のコメントだけを投稿し、ラベルは変えない
  - 回数の上限は設けない
  - 着手のときのラベルの付け替えの失敗と、起動時の回復での書き戻しの失敗も、この一覧で扱う。起動時の回復で書き戻しに失敗しても、エージェントは起動を続ける
  - 待ちへの書き戻しの時点で返答が届いていれば、そのまま次の実行を始める（ADR-016）
  - `switchboard agent status` は、書き戻しを待つ実行を「書き戻し待ち」として、動いている実行と分けて表示する
- 評価が終わらなかったissue（エラー、キュー待ち、ロック中）の更新時刻より後に、`since` を進めない。issueが見つからないときだけ諦める
- やり直すものがある間は、中継につながっていても、ループを `poll_interval` で回す
- 設定から消えたプロジェクトでは、待ちのあとの再実行を始めない。書き戻しの再試行は続ける
- issueのロック名を、別のissueのロック名と重ならない形にする

## Capabilities

### New Capabilities

- なし

### Modified Capabilities

- `agent-run`: 評価のやり直し、着手の途中の評価、書き戻しの再試行、起動時の回復の失敗、状態の表示、消えたプロジェクトの再実行
- `run-outcome`: 書き戻しの再試行と、再試行のときに書き戻す条件

## Impact

- `internal/agent/agent.go`：評価の記録と `since`、`launch` の実行の終わり、キューの消化、ループの間隔、ロック名
- `internal/agent/writeback.go`：書き戻しの再試行の一覧と、起動時の回復
- `internal/agent/relay.go`：やり直すものがある間の `interval` と `due`
- `internal/agent/status.go`：書き戻しを待つ実行の表示
- `internal/forge/fake`：`PostComment` と `Thread` の失敗の注入
- `docs/DESIGN.md` の9章（フォージのAPIの失敗）とREADME.md
- 実行の記録（`issues/.../<n>.json`）に、状態が1つ増える
