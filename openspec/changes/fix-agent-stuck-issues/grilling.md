# grilling 記録: fix-agent-stuck-issues

issueが `agent:running` のまま止まる不具合（#25、#26）と、評価し損ねたissueが二度と評価されない不具合（#27）を直す計画である。どれも、止まったissueについて、受信箱の待ちの欄と通知のどちらにも何も出ない状態を作る。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 着手とポーリングの競合（#25）の防ぎ方 | 待ちのあとの再実行と、実行の後のキューの消化を、ポーリングと同じ `pollMu` の中で行う。`launch` はいつもポーリングのロックの中で呼ばれ、評価の時点でactiveなissueは、runningへの付け替えまで終わっている | 第1ラウンド Q1 |
| 書き戻しの失敗（#26）の再試行のしかた | 書き戻しが終わっていない自端末の実行を、メモリ上の一覧に持つ。ポーリングのたびに `outcome.json` から書き戻し直す。実行の枠とissueのロックは、失敗の時点で解放する。指数バックオフは採らず、DESIGN.mdの9章を書き直す | 第1ラウンド Q2 |
| 評価し損ねたissue（#27）の取りこぼしの防ぎ方 | 評価が終わらなかったissue（エラー、キュー待ち、ロック中）の更新時刻より後に、`since` を進めない。キューの消化での失敗と、通常のポーリングでの失敗を、同じ仕組みで防ぐ | 第1ラウンド Q3 |
| issueのロック名の衝突 | この変更で直し、区切りが曖昧にならない名前にする | 第1ラウンド Q4 |
| 再試行のときに書き戻す条件 | issueがopenで、ラベルがrunningで、最新の着手のコメントがこの実行のものであるときだけ書き戻す。外れたら、結果のコメントが未投稿ならコメントだけ投稿し、ラベルは変えずに一覧から外す。起動時の回復の判定は変えない | 第2ラウンド Q5 |
| 再試行の回数とログ | 回数の上限なしで、書き戻せるか条件を外れるまで続ける。ログには失敗のたびに1行出し、監査ログには最初の失敗と、成功または断念だけを記録する | 第2ラウンド Q6 |
| 着手のときの付け替えの失敗 | 同じ一覧で扱う。再試行のときにラベルがrunningなら中断として書き戻し（waiting、reason=error）、始めるラベルのままなら一覧から外して着手をやり直させる | 第2ラウンド Q7 |
| 評価が失敗し続けるissue | issueが見つからない（`forge.ErrNotFound`）ときだけ諦め、`since` を止めるのをやめる。ほかのエラーは成功するまで止め続ける | 第2ラウンド Q8 |
| 起動時の回復の失敗 | issueごとの書き戻しの失敗は再試行の一覧に入れ、起動は続ける。runningのissueの検索の失敗は、今までどおり起動の失敗とする | 第2ラウンド Q9 |
| 確かめ方 | 失敗と競合は偽フォージに失敗を注入するテストで確かめる。usknasでは、1件のissueがreadyからdoneかwaitingまで進むことを確かめ、ROADMAP.mdに記録する | 第2ラウンド Q10 |
| 再試行で待ちに書き戻せたときに届いていた返答 | ADR-016に従い、そのまま次の実行を始める | 第3ラウンドのまとめで確認 |
| 書き戻しを待つ実行の表示 | 実行の記録に状態 `<writeback>` を足し、`switchboard agent status` で「write-back pending since <時刻>; retried at each poll」と表示する | 第4ラウンド Q11 |
| 設定から消えたプロジェクトの再試行 | 書き戻しの再試行は続ける。評価のやり直しとキュー待ちは、`pending` と同じく捨てる | 第4ラウンド Q12 |
| 消えたプロジェクトでの待ちのあとの再実行 | この変更で直す。再実行の前に、プロジェクトがまだ担当にあるかを確かめる | 第4ラウンド Q13 |
| 中継につながっているときのやり直しの間隔 | やり直すもの（書き戻しの一覧、エラーかロック中で評価できなかったissue）がある間は、ループを `poll_interval` で回し、評価できなかったissueのプロジェクトをその回の取得の対象に入れる。キュー待ちは対象にしない | 第4ラウンド Q14 |
| 作業場所 | 別のworktree（`.claude/worktrees/fix-agent-stuck-issues`、ブランチ `fix-agent-stuck-issues`）で、最新のmainを土台にする | 会話中に確認 |
