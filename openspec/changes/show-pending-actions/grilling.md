# grilling 記録: show-pending-actions

issue `gh:uskanda/switchboard` #101の変更である。WUIで操作を依頼してから結果が一覧に届くまでの間、その行を「処理中」として表示し、一覧の並べ替えを動きで見せる。計画の段階で、エージェントがissueのコメントでQ1〜Q7を質問し、issueの持ち主がすべて推奨どおりに答えた（コメント6584186555）。そのやり取りをここに写す。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 処理中の印をどこに持つか | B：タブのsessionStorageに持つ。再読み込みしても残るが、別のタブや端末には出ない。スマホでは再読み込みやタブの復帰がよく起きるため、メモリだけでは足りない。サービスに持たせる案は、APIとサービスの変更が大きく、押した本人への即時の反応という目的には要らない | issue #101 第1ラウンド Q1（B） |
| 処理中にする操作と移す先の節 | A：マージは完了の節に残して「マージ処理中」と出す。待ちのissueへの返答（/ok、質問への回答、再実行を含む）と、完了のissueへのコメントは実行中の節へ移す。タブのタイトルとヘッダの件数は、移した先の節で数える | issue #101 第1ラウンド Q2（A） |
| 新規issueの作成も処理中に含めるか | B：含める。作成の応答（refとURL）と入力したタイトルから仮の行を作り、実行中の節に出す。端末名は空にする | issue #101 第1ラウンド Q3（B） |
| 処理中が終わる条件と時間切れ | B：依頼が成功したときだけ印を付ける。届いた一覧でそのissueの状態が変わるか、一覧から消えたら外す。10分たっても外れなければ外し、実際の状態に戻して「まだ反映されていません」とトーストで伝える | issue #101 第1ラウンド Q4（B） |
| 「処理中」の点滅の仕方 | A：既存のSpinner（回転する輪）を動かし、文言の不透明度を2秒周期でゆっくり上下させる。prefers-reduced-motionのときは両方止め、文言は常に見せる。PRODUCT.mdに例外を1行足す | issue #101 第1ラウンド Q5（A） |
| 並べ替えのアニメーションの作り方 | A：FLIPを自前で書く。依存は足さない。View Transitionsはページ全体の描画が固まり、ライブラリは依存が増える | issue #101 第1ラウンド Q6（A） |
| アニメーションをかける範囲 | B：前後どちらにもある行の移動を動かし、新しく現れた行はフェードインさせる。消えた行は今のとおりすぐ消す | issue #101 第1ラウンド Q7（B） |
| 計画の承認 | 計画を変えずに承認 | issue #101 コメント6584257629（`/ok`） |
