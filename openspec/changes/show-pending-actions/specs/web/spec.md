# Spec Delta

## ADDED Requirements

### Requirement: 処理中の印
マージ、返答、新規issueの作成のどれかが成功したとき、WUIは、そのissueに処理中の印を付けなければならない（MUST）。返答には、計画の承認、計画の質問への回答、失敗の再実行、完了のissueへのコメントを含む。
依頼が失敗したとき、WUIは、処理中の印を付けてはならない（MUST NOT）。
WUIは、処理中の印をタブのsessionStorageに保ち、同じタブで画面を読み込み直しても印を戻さなければならない（MUST）。

#### Scenario: 返答が成功する
- **WHEN** 待ちのissueに返答を送り、送信が成功する
- **THEN** 次の一覧が届く前に、そのissueの行に処理中の表示が出る

#### Scenario: 依頼が失敗する
- **WHEN** マージを依頼し、受信箱のサービスが断る
- **THEN** その行に処理中の表示は出ない

#### Scenario: 読み込み直す
- **WHEN** 処理中の印が付いたあとに、同じタブで画面を読み込み直す
- **THEN** その行には処理中の表示が残る

### Requirement: 処理中の行を置く節
処理中の印が付いている間、WUIは、返答と新規issueの作成の行を実行中の節に置かなければならない（MUST）。
処理中の印が付いている間、WUIは、マージの行を完了の節に置かなければならない（MUST）。
新規issueの作成の印が付いていて、そのissueが一覧に無い間、WUIは、作成の応答（参照とURL）と入力したタイトルで仮の行を作り、実行中の節に置かなければならない（MUST）。仮の行の端末名は空にする。

#### Scenario: 待ちのissueへの返答
- **WHEN** 待ちのissueに返答を送る
- **THEN** その行は、次の一覧が届く前に返答待ちの節から実行中の節へ移る

#### Scenario: マージ
- **WHEN** 完了のissueのPRをマージする
- **THEN** その行は完了の節に残る

#### Scenario: 新規issue
- **WHEN** 新規issueを作る
- **THEN** 実行中の節に、そのissueのタイトルの仮の行が出る

### Requirement: 処理中の表示
処理中の印が付いている間、WUIは、行の状態の欄に、回転する輪と処理中の文言を出さなければならない（MUST）。文言は、マージなら「マージ処理中」、返答と新規issueなら「処理中」とする。
処理中の印が付いている間、WUIは、行の説明に、返答と新規issueなら「実行の開始を待っています」、マージなら「closeされると一覧から消えます」と出さなければならない（MUST）。
WUIは、処理中の文言の不透明度を、2秒程度の周期でゆっくり上下させなければならない（MUST）。
prefers-reduced-motionが求められている間、WUIは、輪と文言を動かしてはならない（MUST NOT）。文言は常に読める濃さで出す。
処理中の状態の欄は、読み上げにも処理中を伝えなければならない（MUST）。

#### Scenario: マージの処理中
- **WHEN** PRのマージが成功する
- **THEN** その行の状態の欄に、回転する輪と「マージ処理中」が出る

#### Scenario: 処理中のマージのボタン
- **WHEN** マージの処理中の行を見る
- **THEN** その行のマージのボタンは押せない

### Requirement: 処理中の印を外す時
届いた一覧で、そのissueの状態か状態の始まりの時刻が、印を付けた時点から変わったとき、WUIは、処理中の印を外さなければならない（MUST）。
そのissueが一覧から消えたとき、WUIは、処理中の印を外さなければならない（MUST）。
新規issueの作成の印は、そのissueが一覧に現れたとき、外さなければならない（MUST）。

#### Scenario: 実行が始まる
- **WHEN** 返答したissueが、届いた一覧で実行中になる
- **THEN** 処理中の表示が消え、通常の実行中の行になる

#### Scenario: 計画の実行が早く済む
- **WHEN** 計画の承認を送ったissueが、次の一覧で、始まりの時刻の違う待ちになっている
- **THEN** 処理中の表示が消え、そのissueは返答待ちの節に出る

#### Scenario: マージしたissueがcloseされる
- **WHEN** マージしたissueが一覧から消える
- **THEN** 処理中の印も消える

#### Scenario: 作ったissueが一覧に現れる
- **WHEN** 新規issueの仮の行がある状態で、そのissueの本物の行が届く
- **THEN** 仮の行は本物の行に置き換わる

### Requirement: 処理中の時間切れ
処理中の印を付けてから10分たっても印が外れないとき、WUIは、印を外し、そのissueを実際の状態の節に戻さなければならない（MUST）。
時間切れで印を外したとき、WUIは、「<参照> の操作はまだ反映されていません」とトーストで伝えなければならない（MUST）。
一覧が届かない間も、WUIは、10分たった時点で時間切れを扱わなければならない（MUST）。

#### Scenario: 10分たつ
- **WHEN** 返答したissueの状態が10分変わらない
- **THEN** 行は返答待ちの節に戻り、「まだ反映されていません」のトーストが出る

### Requirement: 一覧の並べ替えの動き
一覧が更新されて、前後どちらにもある行の位置が変わったとき、WUIは、その行を元の位置から新しい位置へ動かして見せなければならない（MUST）。節をまたぐ移動も含む。動きは処理中の印に限らず、すべての更新に使う。
一覧が更新されて新しい行が現れたとき、WUIは、その行をフェードインさせなければならない（MUST）。消えた行は、動かさずにすぐ消す。
prefers-reduced-motionが求められている間、WUIは、行を動かしてはならない（MUST NOT）。

#### Scenario: 節をまたいで移る
- **WHEN** 待ちのissueが、次の一覧で実行中になる
- **THEN** その行は、返答待ちの節の位置から実行中の節の位置へ動く

#### Scenario: 動きを減らす設定
- **WHEN** OSで動きを減らす設定をした状態で、行の位置が変わる
- **THEN** 行は動かず、すぐ新しい位置で表示される

## MODIFIED Requirements

### Requirement: タブのタイトル
WUIは、ブラウザのタブのタイトルを、画面の名前と「SwitchBoard Inbox」を ` - ` でつないだものにしなければならない（MUST）。画面の名前は、1件の画面ではissueのタイトル、設定の画面では「設定」とする。一覧だけの画面では、名前を付けずに「SwitchBoard Inbox」とする。
待ちのissueが1件以上ある間、WUIは、タブのタイトルの先頭に`(N) ` の形で待ちの件数を付けなければならない（MUST）。待ちの件数は、処理中の印を反映した節で数える。返答して処理中の印が付いたissueは、待ちに数えない。

#### Scenario: 一覧の画面
- **WHEN** 待ちのissueが1件ある状態で一覧の画面を開く
- **THEN** タブのタイトルは`(1) SwitchBoard Inbox`になる

#### Scenario: 1件の画面
- **WHEN** 待ちのissue「Add a flag」を開く
- **THEN** タブのタイトルは`(1) Add a flag - SwitchBoard Inbox`になる

#### Scenario: 設定の画面
- **WHEN** 待ちのissueが無い状態で設定の画面を開く
- **THEN** タブのタイトルは`設定 - SwitchBoard Inbox`になる

#### Scenario: 返答したissue
- **WHEN** 待ちのissueが1件だけある状態で、そのissueに返答を送る
- **THEN** 次の一覧が届く前に、タブのタイトルは`SwitchBoard Inbox`になる

### Requirement: ヘッダの件数の読み上げ
WUIのヘッダは、件数を、画面に出す短い表記とは別に、読み上げ用の文として持たなければならない（MUST）。文は「待ちN件、実行中N件」とし、順番待ちと完了は1件以上のときだけ「、順番待ちN件」「、完了N件」を足す。件数は、処理中の印を反映した節で数える。
画面に出す短い表記は、読み上げさせてはならない（MUST NOT）。

#### Scenario: 4種類の件数がある
- **WHEN** 待ち、実行中、順番待ち、完了のissueが1件ずつある状態で一覧を開く
- **THEN** ヘッダに「待ち1件、実行中1件、順番待ち1件、完了1件」の読み上げ用の文がある

#### Scenario: 返答したissueを数える
- **WHEN** 待ちのissueが1件だけある状態で、そのissueに返答を送る
- **THEN** 次の一覧が届く前に、ヘッダの読み上げ用の文は「待ち0件、実行中1件」になる
