# Design

## Context

新規issueは、ブラウザが開始ラベルの種別を送り、受信箱のサービスが設定のラベル名に置き換えて付ける（ADR-040）。種別の検査は「一覧で返す種別に含まれるか」で行い、空や未知の種別は `invalid` で拒む。フォージの層（`forge.Issues` の `CreateIssue`）は、ラベルの空の一覧をすでに受け付ける。エージェントは開始ラベルを契機に着手するので、ラベルの無いissueには着手しない。

## Goals / Non-Goals

**Goals:**
- 種別の検査を緩めずに、ラベルなしのissueを作れるようにする。

**Non-Goals:**
- フォージの層とエージェントの着手の条件は変えない。
- 作ったあとでWUIから開始ラベルを付ける操作は作らない。

## Decisions

- **ラベルなしを種別 `none` で表す。** 空文字で表すと、種別の送り忘れがラベルなしのissueとして通ってしまう。`none` を一覧の種別の1つにすれば、今の「一覧に含まれるか」の検査をそのまま使え、空の種別は今までどおり拒める。
- **`none` は設定に関係なく、一覧の最後に常に出す。** ラベル名を持たないので、設定でラベル名が空の種別を一覧から除く規則とは別に、最後に足す。最後に置けば、初期値の `ready` とその並びも変わらない。
- **作成では、種別の検査と付けるラベルを分けて判定する。** 種別が一覧に見つからなければ拒む。見つかった種別のラベル名が空なら、ラベルの空の一覧でフォージを呼ぶ。
- **WUIでは、ラベル名が空の選択肢に括弧とラベル名を出さない。** 種別の名前で分けず、ラベル名の有無で決める。
- **記録はADR-049に残す。** AGENTS.mdは、既に決まったことを改めるときに新しいADRを求める。ADR-040の該当の行には「ADR-049で改めた」と注記する。計画の時点ではADR-047の予定だったが、先にmainへ入ったAndroidのアプリの決定がADR-047を使い、自動マージの決定がADR-048を使ったので、ADR-049にした。
- **ラベルなしのissueには処理中の印を付けない。** mainに入った処理中の印（`show-pending-actions`）は、作ったissueが一覧に現れるまで実行中の仮の行を出す。ラベルなしのissueにはエージェントが着手せず、一覧に現れないので、印を付けると10分のあいだ偽の行が残る。

## Risks / Trade-offs

- ［ラベルなしのissueは受信箱にも出ず、放っておかれやすい］→「後で作りたい」ものを置いておくのが目的なので受け入れる。着手させたいときは、フォージで開始ラベルを付ければよい。
- ［古いWUIが `none` を知らない］→WUIは同じバイナリに入っているので、一緒に更新される。
