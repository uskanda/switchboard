## ADDED Requirements

### Requirement: 1件の詳細と一覧の食い違い
APIは、1件の詳細を読んだあと、その状態を最後に配った一覧の同じissueの行と比べなければならない（MUST）。状態は、実行中、順番待ち、完了、待ち、一覧に載らない、の5つに分けて比べる。理由は比べない。
次のどれかのとき、APIは一覧をすぐ読み直すよう頼まなければならない（MUST）。読み直した一覧が前と違えば、変化の知らせで届く。

- 行があり、状態が違う
- 行が無いのに、詳細は一覧に載る状態である
- 行があるのに、詳細は一覧に載らない状態である

配った一覧がまだ無いとき、APIは読み直しを頼んではならない（MUST NOT）。
APIは、返す詳細の形を変えてはならない（MUST NOT）。

#### Scenario: 一覧が古い
- **WHEN** 最後に配った一覧で順番待ちのissueが、フォージでは待ちになっていて、その詳細を求める
- **THEN** 詳細はそのまま返り、一覧の読み直しが頼まれる

#### Scenario: 一覧と同じ
- **WHEN** 最後に配った一覧で待ちのissueの詳細を求め、フォージでも待ちである
- **THEN** 一覧の読み直しは頼まれない

#### Scenario: 一覧にまだ無い
- **WHEN** 最後に配った一覧に無いissueが、フォージでは待ちになっていて、その詳細を求める
- **THEN** 一覧の読み直しが頼まれる

#### Scenario: 配った一覧が無い
- **WHEN** 一覧をまだ配っていないときに詳細を求める
- **THEN** 一覧の読み直しは頼まれない
