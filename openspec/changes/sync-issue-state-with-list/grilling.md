## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 一覧と1件の状態の食い違いをどう解消するか | A：受信箱のサービスの`/v1/issue`が、読んだ1件の状態を最後に配った一覧と比べる。違えば`readAgain()`で一覧をすぐ読み直し、SSEで届ける。ブラウザで一覧の行に状態を重ねることはしない | issue #82の計画の質問Q1（comment 6659638111）、回答はcomment 6659669606 |
| ずれのあいだ、1件の画面で何か示すか | A：1件の状態が一覧の行と違い、読み直しが終わっているあいだだけ、状態の横に「フォージから今読んだ状態です。一覧は更新を待っています」と出す。一覧が追いつけば消える | 同Q2、回答はcomment 6659669606 |
| 比べるもの | 「実行中・順番待ち・待ち・完了」の4つの状態だけ。理由（計画か質問かなど）は比べない | 計画（comment 6659698996）、承認はcomment 6659741242 |
| 読み直しを頼む場合 | 行があり状態が違う、行が無いのに詳細が一覧に載る状態、行があるのに詳細が一覧に載らない状態。配った一覧がまだ無ければ何もしない | 同上 |
| 知らせを出す条件 | 状態が違い、今回読んだ詳細で（キャッシュでなく）、読み直しの最中でなく、一覧に行があるとき | 同上 |
