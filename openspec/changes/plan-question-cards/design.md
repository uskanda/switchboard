# Design

## Context

最新の質問のコメントは、`IssuePane` が `parsePlanQuestions` で読む。読んだ問いは `PlanQuestions` が `Thread` のカードの中に描く。選択の状態（`Answer`）は `IssuePane` が持ち、issueごとの書きかけ（`lib/drafts.ts`）にも残す。送る文は `composeReply` が組み立てる。核の受信箱のAPIの `Comment` が持つのは、書いた人と時刻と本文、エージェントの投稿かどうか、マーカーの状態だけである。動機はproposal.mdの「Why」を参照する。

## Goals / Non-Goals

**Goals:**

- 問いの読み取り（`parsePlanQuestions`）と送る文の形（`composeReply`）を変えずに、描き方と状態だけを変える
- 新しく読み取るもの（冒頭の分割、問いの状態、前のラウンドの答え）は、`lib/planQuestions.ts` の純粋な関数にして、単体で試せるようにする

**Non-Goals:**

- エージェントのコメントの形、プロンプト、核の受信箱のAPIは変えない（#190、#191）
- 前のラウンドの質問のコメントは、開いても今のままMarkdownで描く

## Decisions

### 「補足だけ」は `Answer` のフラグで持つ

`Answer` に `noteOnly`（チェックボックスの状態）と、入れる前の選択 `before` を足す。入れたときは `choices` をすべて `null` にし、`before` に元の選択を残す。外したときは `before` を `choices` に戻す。送る文は、全部の組が `null` のときに補足だけを答えにする今の `composeReply` のまま組み立てられる。書きかけの保存は `Answer` をそのままJSONにするので、足した欄も残る。古い書きかけには欄が無いが、無いときは入れていない状態として扱う。

ほかの案として、`choices` に「選ばない」を表す特別な値を入れる形があった。この形では、外したときに戻す選択の置き場が別に要り、`composeReply` にも分岐が増えるため採らない。

### 問いの状態は1つの関数で決める

`questionState(q, answer)` は、仕様の「問いの状態のチップ」に書いた順で状態を決めて返す。「＋補足」を付けるかも合わせて返す。「補足だけ」のチェックボックスを入れても、補足が空なら「未回答」とする。その問いの送る文は `回答なし` となるので、送る前の確認のために未回答として示す。grillingの第2ラウンドQ9の「補足だけ」の定義を、実装のときにこう絞った。推奨のラベルは `defaultAnswers` と同じ規則で求める。チップの文言は、この状態を言語ごとの文言に当てるだけにする。

### 前のラウンドの答えはスレッドのコメントから組み立てる

`decidedBefore(comments, latest, word)` が、最新の質問のコメントの位置 `latest` より前の、今の周期の質問のコメントを集める。周期の境目は、最初の問いがQ1の質問のコメントとする。マーカーの `mode` を読めば境目をより正確に分けられるが、Web表示はマーカーを読まない作りなので、番号で分ける。

各ラウンドの返答は、質問のコメントのあと、エージェントの次の投稿までの人のコメントとする。返答の行は `Q<番号> <題>: ` で始まる行として、問いの題を知ったうえで照らし合わせる。題に `: ` を含む問いでも、答えの始まりを誤らないためである。答えの頭が選択肢のラベル1つで、そのラベルを持つ組が1つだけのとき、ラベルのあとに選択肢の文を足す。返答の行の無い問いは、一覧に出さない。

承認の語だけのコメントでは、`defaultAnswers` の推奨のラベルを答えとする。推奨にラベルの無い問いは「推奨どおり」と出す。どちらの形も無いラウンドは、最初の人のコメントの1行目をそのラウンドの1項目にする。

### 冒頭は段落で分ける

`splitHead(head)` が、冒頭を空行で段落に分け、`**計画：**` か `**Plan:**` で始まる段落までを出す部分、その後ろを畳む部分にする。エージェントの言語は受信箱の表示の言語と別に決まるので、両方の言語の題の行を探す。

### チップは返答の欄に、状態の計算は描く側に置く

チップは `IssuePane` の返答の欄で、送る文の上に置く。押すと、問いのカードの `scrollIntoView` で動かし、カードの題（`tabIndex=-1` のh3）にフォーカスを移す。固定の見出しの下で止めるため、問いのカードにもスレッドのカードと同じ `scroll-margin-top`（`--header-h` と `--pane-head-h`）を付ける。

### 推奨の理由は組の部品に渡す

組が1つで推奨のラベルがある問いでは、`Choices` に推奨の文を渡し、推奨の選択肢の行のすぐ下に、選択肢の文の位置にそろえて描く。それ以外の問いでは、最後の組の下（組の無い問いでは本文の下）に描き、補足の欄はその下に置く。

## Risks / Trade-offs

- 返答の行を手で書き換えた返答では、決まったことの一覧に出ない問いが残る → 一覧は読むための助けにとどめる。全文は前のラウンドを開けば読めることを、DESIGN.mdに書く
- 信頼済みでない人の返答も、決まったこととして並ぶ → grillingで受け入れた（第2ラウンドQ12）。受信箱のAPIがコメントごとの信頼の情報を持つようになったら見直す
- カードの中のカードで、スマホの幅では1行の字数が減る → 問いのカードの内側の余白を `md` にとどめ、外のカードの余白は変えない
- 1問の中で一部の組だけを選ばない答え方ができなくなる → grillingで受け入れた（第1ラウンドQ4）。補足に書けば伝えられる

## Migration Plan

Web表示の静的ファイルだけが変わる。`switchboard-web` を入れ替えれば反映され、戻すときは前の版に入れ替える。古い書きかけは、`noteOnly` の無い `Answer` として読める。
