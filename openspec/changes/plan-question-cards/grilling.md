# grilling 記録: plan-question-cards

計画の質問の待ち（`plan-questions`）のWeb表示で、問いの境目を分かりやすくし、読む量を減らす計画である（issue `gh:uskanda/switchboard` #189）。変えるのはWeb表示（`web/ui`）、DESIGN.md、`web` の仕様だけで、エージェントのコメントの形とプロンプトは変えない。`add-web-plan-answers` の第1ラウンドQ6（問いの中の並び）と第2ラウンドQ13（組ごとの「選ばない」）は、この変更で決め直す。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| カードの組み方 | 最新の質問のカード（`primary` の2pxの枠）を残し、その中の問いを1つずつ `outline` の1pxの枠のカードにする | 第1ラウンド Q1 |
| 問いの頭の書き方と題の大きさ | 題は `body-md` の太字のままにする。題の前に、番号とラウンドの中の位置（例：`Q5 1/2`）を `mono-sm` で付ける | 第1ラウンド Q2 |
| 推奨の理由の置き場所 | 推奨の選択肢の行のすぐ下に、`body-md` の `muted` で出す。組が2つ以上ある問いと、推奨にラベルの無い問いでは、最後の組の下に出す | 第1ラウンド Q3 |
| 組ごとの「選ばない（補足で答える）」 | ラジオボタンをやめる。補足の欄に「選択肢を選ばず、補足だけで答える」のチェックボックスを置き、入れるとその問いの全部の組の選択を外す | 第1ラウンド Q4 |
| 問いの一覧（チップ）の置き場所 | 返答の欄の、送る文の上に置く | 第1ラウンド Q5 |
| 前のラウンドで決まったことの表示 | 前のラウンドの質問のコメントと人の返答から、Web表示が「Qn 題：答え」を組み立てて一覧で出す | 第1ラウンド Q6 |
| 冒頭の「調べたこと」の段落 | 計画の題の行は出したままにし、そのあとの段落を「エージェントが調べたこと」の折りたたみに入れる | 第1ラウンド Q7 |
| 開いた前のラウンドの描き方 | 今のままMarkdownとして描く | 第1ラウンド Q8 |
| チップに出す状態 | 「推奨どおり」「推奨と違う」「補足だけ」「未回答」の4つ。補足を書いた問いには「＋補足」を付ける。色は「未回答」だけに `attention` の文字色を使う | 第2ラウンド Q9 |
| チップを押したときの動き | その問いのカードを固定の見出しのすぐ下までスクロールし、カードの題（h3）にフォーカスを移す | 第2ラウンド Q10 |
| 決まったことの一覧の置き場所と見た目 | 最新の質問のカードの先頭（計画の題の行より上）に「これまでに決まったこと」として置き、常に開いておく。1行に1問ずつ「Q1 題：C　選択肢の文」の形で出し、2行を超える分は「…」で切る | 第2ラウンド Q11 |
| 決まったことを組み立てる規則 | 人の返答の `Qn 題: 答え` の行を読み、同じ問いの行が複数あれば最後の行を採る。承認の語だけの返答では、そのラウンドの全部の問いを「推奨どおり」とする。どちらの形でもない返答は、ラウンドの1項目として返答の冒頭を出す。返答した人が信頼済みかどうかは見分けない | 第2ラウンド Q12 |
| 推奨の印と理由の並べ方 | 推奨の選択肢の文の後ろの「（推奨）」の印を残し、その下に選択肢の文の位置にそろえて理由を出す。ほかの選択肢を選んでも、理由は推奨の選択肢の下に残す | 第2ラウンド Q13 |
| 「補足だけで答える」のチェックボックスの動き | 補足の欄を開くボタンを「Qnに別の答えや補足を書く」にする。チェックボックスを入れると、その問いのラジオボタンの選択を外して押せなくする。外すと入れる前の選択に戻す。推奨にラベルの無い組がある問いは、選択の無い状態から始め、補足の欄を開いておく | 第2ラウンド Q14 |
| 畳む「調べたこと」の範囲 | 計画の題の行より後ろで、最初の問いより前の段落をすべて畳む。題の行の無い古い形のコメントでは、何も畳まない | 第2ラウンド Q15 |
| 推奨にラベルの無い問いのチップの状態 | 推奨にラベルのある組だけを比べる。どの組にも推奨のラベルが無い問いで全部の組を選んだときは「選択済み」と出す | 第3ラウンド Q16 |
| 決まったことの一覧に含めるラウンドの範囲 | 今の周期のラウンドだけを含める。周期の境目は、最初の問いがQ1のラウンドとする | 第3ラウンド Q17 |

## 後回しにしたもの

- 選択肢を構造として持つことと、問いごとの図（#190）
- 問いを「判断が要る」と「確認だけ」に分けることと、範囲の問いを先に聞くこと（#191）
- 1問の中で一部の組だけを選ばない答え方（第1ラウンドQ4で、できなくなることを受け入れた）
- 返答した人が信頼済みかどうかを、決まったことの一覧に反映すること（核の受信箱のAPIに、コメントごとの信頼の情報が要る。第2ラウンドQ12）
