# Spec Delta

## MODIFIED Requirements

### Requirement: 画面
WUIの画面は、ヘッダと本体からなり、ヘッダには、名前、待ちと実行中の件数、自動更新の状態、設定の画面へのリンクを表示しなければならない（MUST）。
幅1024px以上のとき、WUIは、左のペインに一覧を、右のペインに選んだissueの1件を並べて表示しなければならない（MUST）。
幅1024px未満のとき、WUIは、一覧と1件を別の画面として表示しなければならない（MUST）。
選んだissueは、`/issue/<ref>` のURLで表さなければならない（MUST）。issueを選んでいないとき、右のペインは、一覧から選ぶよう示す。
一覧は、`switchboard inbox` と同じ項目を表示しなければならない（MUST）。届かなかったフォージがあれば、そのことも示す。
プロジェクトでまとめない間、一覧は、各節の行を待ちが始まった古い順に表示しなければならない（MUST）。
プロジェクトでまとめる間、一覧は、各サブグループの中の行を古い順に表示しなければならない（MUST）。
プロジェクトでまとめる間、一覧は、各節のサブグループを、それぞれの最も古い行の古い順に並べなければならない（MUST）。
1件の表示は、エージェントの最後の投稿の全文、拒否された操作、フォージのissueへのリンク、返答の欄を表示しなければならない（MUST）。
画面は、デスクトップとスマホのどちらの幅でも、横へのスクロール無しで使えなければならない（MUST）。
issueから来た文字列（タイトル、本文、コメント）を、HTMLとして解釈させてはならない（MUST NOT）。
画面の静的ファイルは、すべて `<switchboard-web>` に埋め込み、外のCDNから読み込んではならない（MUST NOT）。

#### Scenario: デスクトップの幅で選ぶ
- **WHEN** 幅1280pxのブラウザで一覧の行を選ぶ
- **THEN** URLが `/issue/<ref>` になり、左に一覧を残したまま、右にそのissueと返答の欄が出る

#### Scenario: スマホの幅で開く
- **WHEN** 幅360pxのブラウザで一覧と1件の画面を開く
- **THEN** 一覧と1件は別の画面に出て、横へのスクロール無しで、返答を書いて送れる

#### Scenario: タイトルにHTMLが含まれる
- **WHEN** タイトルが `<script>` を含む待ちのissueを一覧に出す
- **THEN** その文字列がそのまま表示され、スクリプトは動かない

#### Scenario: まとめない一覧の順
- **WHEN** プロジェクトでまとめない状態にして、2つのプロジェクトの待ちのissueがある一覧を開く
- **THEN** 返答待ちの節に、プロジェクトに関わらず、待ちが始まった古い順で行が出る

## ADDED Requirements

### Requirement: 一覧の節のプロジェクトのサブグループ
プロジェクトでまとめる間、一覧は、4つの節（返答待ち・実行中・順番待ち・完了）の行を、節ごとにプロジェクトのサブグループに分けて表示しなければならない（MUST）。
各サブグループは、プロジェクトの参照、フォージのバッジ、行の件数からなる見出しを持たなければならない（MUST）。
節の中のプロジェクトが1つだけのときも、一覧は、サブグループの見出しを表示しなければならない（MUST）。
サブグループの中の行は、今までどおりissueの参照とフォージのバッジを表示しなければならない（MUST）。
フォージが違う同名のリポジトリの行を、一覧は、同じサブグループにまとめてはならない（MUST NOT）。

#### Scenario: 2つのプロジェクトの待ちがある
- **WHEN** `o/a` の待ちが始まって5分、`o/b` の待ちが始まって10分と1分のissueがある一覧を開く
- **THEN** 返答待ちの節に、`o/b`［GitHub］2件の見出しが先、`o/a`［GitHub］1件の見出しが後に出て、`o/b` の下には10分のissue、1分のissueの順で行が出る

#### Scenario: プロジェクトが1つだけ
- **WHEN** 実行中のissueが1つのプロジェクトの1件だけの一覧を開く
- **THEN** 実行中の節に、そのプロジェクトの参照、バッジ、1件の見出しが出て、その下に行が出る

#### Scenario: GitHubとGitLabの同名のリポジトリ
- **WHEN** `gh:o/r` と `gl:o/r` のそれぞれに待ちのissueがある一覧を開く
- **THEN** 返答待ちの節に、`o/r`［GitHub］と`o/r`［GitLab］の2つのサブグループが出る

### Requirement: まとめる表示の切り替え
一覧は、ペインの先頭に、プロジェクトでまとめるかどうかを切り替えるトグルボタンを表示しなければならない（MUST）。
トグルボタンは、オンかオフかを支援技術に伝えなければならない（MUST）。
一度も切り替えていないブラウザで開いたとき、一覧は、プロジェクトでまとめて表示しなければならない（MUST）。
トグルボタンを押したとき、一覧は、4つの節をそろえて切り替えなければならない（MUST）。
トグルボタンを押したとき、WUIは、選んだ状態をそのブラウザに保存しなければならない（MUST）。
保存した状態があるとき、WUIは、開き直した一覧にその状態を使わなければならない（MUST）。

#### Scenario: 初めて開く
- **WHEN** 一度も切り替えていないブラウザで一覧を開く
- **THEN** 各節がプロジェクトのサブグループにまとまって出て、トグルボタンは押された状態になっている

#### Scenario: まとめない表示に切り替える
- **WHEN** 待ちと実行中のissueがある一覧で、トグルボタン「プロジェクトでまとめる」を押す
- **THEN** 4つの節のサブグループの見出しが消えて、行が古い順で出て、トグルボタンは押されていない状態になる

#### Scenario: 開き直しても残る
- **WHEN** トグルボタンでまとめない表示に切り替えてから、ページを再読み込みする
- **THEN** 一覧はまとめない表示のまま出る
