# Design

## Context

受信箱のサービスは、一覧の項目を状態ごとに古い順で返す。WUIの`InboxList`は、受け取った項目を状態で4つの節に分け、節ごとに受け取った順のまま描く。640〜1024pxでは表、それ以外（640px未満と左のペイン）ではカードの`ul`にする。一覧の幅は`lib/paneWidth.ts`がlocalStorageに覚えさせている。

## Goals / Non-Goals

**Goals:**
- 各節の中をプロジェクトのサブグループにまとめ、見出しに参照、バッジ、件数を出す
- まとめるかどうかを一覧全体で1つのトグルで切り替え、ブラウザに覚えさせる

**Non-Goals:**
- サブグループの折りたたみ
- 受信箱のサービス、API、CLIの並べ方を変えること

## Decisions

### プロジェクトは`ref`から取る
一覧の項目の`project`にはフォージのプレフィックスが無く、`gh:o/r`と`gl:o/r`を見分けられない。そこで`projectRef(ref)`は、`ref`の最後の`#`より前を返す（`gh:o/r#12` → `gh:o/r`）。APIに項目を足す案は、Q7で決めた「APIは変えない」に反するので採らない。

### サブグループの順は「最初に出てきた順」
`groupByProject(items)`は、受け取った順を保ち、各プロジェクトが最初に出てきた順にまとめる。サービスは節ごとに古い順で返すので、最初に出てきた順が、そのまま各サブグループの最も古い行の順になる。WUIで時刻を読み直して並べ直す案は採らない。状態ごとに時刻の項目が違い（`waiting_since`、`running_since`、`queued_since`、`done_since`）、サービスの並べ方と食い違う恐れがあるからである。

### 切り替えの状態は`lib/paneWidth.ts`と同じ形で覚える
`web/ui/src/lib/groupPref.ts`に、保存した文字列を読む純粋な関数`readGroupByProject`と、フック`useGroupByProject`を置く。値が`"false"`のときだけオフとし、無いときと読めない値はオンにする。ストレージが使えないブラウザでは、ページを開いている間だけ覚える。

### 表ではサブグループごとに`tbody`を分ける
640〜1024pxの表は、theadを1つのまま、サブグループごとに`tbody`を分け、先頭の行に`colSpan=4`のセルで見出し（h3）を置く。列の幅は今と同じなので、横スクロールは増えない。

### トグルは`aria-pressed`と印で示す
「プロジェクトでまとめる」は`button-secondary`のまま、`aria-pressed`を付ける。オンのときはチェックの印（✓）を文言の前に出し、枠を`primary`にする。色だけに頼らずに状態が分かるようにするためである。オフのときも印の場所は空けておき、ボタンの幅を変えない。`NewIssue`は外側の`flex justify-end`の囲みを外し、`InboxList`の先頭の行でトグルと並べる。

## Risks / Trade-offs

- ［見出しが増えて、既存のテストが行やリンクを数え違える］→ 既存のテストを初めの状態（オン）で走らせ、通らないものは確かめる中身を変えずに直す
- ［サービスの並べ方が将来変わると、サブグループの順もそれに従う］→ このことをこの文書に記録する。受け取った順を保つことは`web/ui/src/lib/group.test.ts`で確かめる
