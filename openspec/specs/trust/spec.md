# trust Specification

## Purpose

issueから読んだ入力のうち、エージェントへの指示として採用してよいものと、エージェント自身の投稿を見分ける。

## Requirements

### Requirement: ユーザーIDによる判定
`switchboard` は、`trusted_authors` と `agent_identity` をログイン名からユーザーIDに解決し、IDで判定しなければならない（MUST）。
解決したIDは、状態ディレクトリに記録しなければならない（MUST）。
記録したIDと、同じログイン名を新たに解決したIDが異なるとき、`switchboard agent run` は起動してはならない（MUST NOT）。

#### Scenario: ログイン名の持ち主が変わった
- **WHEN** `trusted_authors` のログイン名が、記録時とは別のユーザーIDに解決される
- **THEN** `switchboard agent run` は0以外の終了コードで終わり、IDが変わったログイン名を報告する

### Requirement: 着手の許可
`agent:ready` が付いたissueについて、そのラベルを最後に付けたユーザーが信頼済みでないとき、エージェントは実行を始めてはならない（MUST NOT）。

#### Scenario: 第三者がラベルを付けた
- **WHEN** 信頼済みでないユーザーが、issueに `agent:ready` を付ける
- **THEN** 実行は始まらず、判定と理由が監査ログに記録される。issueにはコメントもラベルの変更もされない

### Requirement: issue本文の採用
issue本文の作成者が信頼済みでないとき、エージェントは実行を始めてはならない（MUST NOT）。
issue本文が編集されていて、最後の編集者が信頼済みでないとき、エージェントは実行を始めてはならない（MUST NOT）。

#### Scenario: 第三者が本文を編集した
- **WHEN** 信頼済みのユーザーが作ったissueの本文を、信頼済みでないユーザーが編集し、その後に `agent:ready` が付く
- **THEN** 実行は始まらず、判定と理由が監査ログに記録される

### Requirement: コメントの採用
エージェントは、作成者が信頼済みのコメントだけを指示として採用しなければならない（MUST）。
コメントが編集されていて、最後の編集者が信頼済みでないとき、エージェントは、そのコメントを指示として採用してはならない（MUST NOT）。

#### Scenario: 第三者のコメント
- **WHEN** 待ちのissueに、信頼済みでないユーザーがコメントする
- **THEN** 実行は始まらず、そのコメントはプロンプトに含まれない

### Requirement: 非信頼コメントの除外
エージェントは、指示として採用しないコメントを、既定ではプロンプトに含めてはならない（MUST NOT）。
プロジェクトの設定 `include_untrusted` が `true` のとき、エージェントは、非公開リポジトリに限り、そのコメントを参考データとしてプロンプトに含めなければならない（MUST）。
参考データは、指示と区別できる区切りで囲む。
公開リポジトリで `include_untrusted` が `true` のとき、エージェントは実行を始めずに設定の誤りを報告しなければならない（MUST）。

#### Scenario: 公開リポジトリでの設定
- **WHEN** 公開リポジトリのプロジェクトに `include_untrusted: true` が設定されている
- **THEN** そのプロジェクトのissueは実行されず、設定の誤りが報告される

### Requirement: エージェントの投稿の識別
エージェントは、作成者が `agent_identity` のユーザーIDと一致し、末尾の単独の行にマーカーを持つコメントだけを、エージェント自身の投稿として扱わなければならない（MUST）。
引用ブロックの中のマーカーは、エージェント自身の投稿の印として扱ってはならない（MUST NOT）。

#### Scenario: 人間が引用したマーカー
- **WHEN** 信頼済みのユーザーが、エージェントのコメントを引用ブロックで引用して返答する
- **THEN** その返答は人間の指示として扱われ、エージェント自身の投稿としては扱われない

### Requirement: 監査ログ
エージェントは、信頼判定ごとに、対象、判定者のユーザーID、採否、理由、本文のハッシュを、状態ディレクトリの監査ログに記録しなければならない（MUST）。

#### Scenario: 判定の記録
- **WHEN** エージェントが1件のコメントを指示として採用する
- **THEN** 監査ログに、そのコメントのID、作成者のユーザーID、採用、本文のSHA-256が1行で記録される
