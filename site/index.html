How it works

  1. Add a label

    Put agent:ready or agent:plan on an issue.

  2. A host runs it

    The agent on the project's host runs claude -p in a worktree of its own for the issue.

  3. It stops on a question

    The agent posts the question as an issue comment. It labels the issue agent:waiting, and you get a notification.

  4. Reply from the inbox

    Reply from the CLI, a browser, or the app. The run resumes on the same issue.

  5. It becomes a PR

    The agent pushes a branch that passed the checks and opens a draft pull or merge request. You can merge it from the inbox.

Features

Plan first

Before writing code, the agent comments its questions and plan. It starts the work after you approve with a /ok reply.

Both forges

Waiting issues from GitHub and GitLab, self-hosted included, share one list, oldest first.

Several hosts

Each project has one host that runs it. Two hosts never run the same issue at once.

Fix runs

On a CI failure, a rejected push, or a conflict with the base branch, the agent starts a run that fixes it in the same pull or merge request.

Notifications and app

Telegram and Android push notifications tell you when an issue is waiting or done. You can approve a plan from the notification.

Run limits

Set how many runs go at once, queue the rest, pause at the usage limit, and cap the API cost.

Security model

  • Text read from issues is data. Only comments by trusted_authors count as instructions.
  • claude gets no forge credentials. The agent pushes, opens pull or merge requests, and posts comments.
  • A run's shell commands run in a sandbox. They can write only to the worktree and cannot reach the network.
  • Hosts open no listening ports. The one exception is the web inbox, and only on LAN addresses.
  • The relay passes on only issue IDs and event types. It holds no issue text and no tokens.

Assumptions and limits

switchboard was built and tested on its author's own setup. Before you use it, check that your setup fits the points below.

  • It is for one user and targets private repositories. By default, the agent posts as your own account.
  • Hosts run Linux with systemd, Secret Service, bubblewrap, and socat. It has not been tested on macOS.
  • The web inbox does not authenticate users. Use it only inside your LAN.
  • On GitHub, only github.com is supported. Its webhooks cannot reach the relay, so switchboard polls it.
  • No binaries are published; you build switchboard from source. You build the Android app with your own Firebase project.
  • The UI is in English and Japanese only. The web inbox picks the language from the browser, and you can change it in its settings. The Android app follows the device language.

Get started

Install Go 1.24 or later, Node.js 24, pnpm 12, and the Claude Code CLI. Then clone the repository and build it.

git clone https://github.com/uskanda/switchboard.git && cd switchboard
make install
mkdir -p ~/.config/switchboard && cp config/switchboard.example.yaml ~/.config/switchboard/config.yaml
switchboard doctor
switchboard labels sync
switchboard agent run

The guide covers registering tokens, running the agent as a service, and setting up the relay, notifications, and the web inbox.
