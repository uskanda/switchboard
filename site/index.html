switchboardは、GitHubとGitLabのissueから、Claude Codeの自動の実行を複数の端末とリポジトリで動かす個人用ツールです。質問を残して止まった実行を「待ち」として集め、CLI、ブラウザ、Androidのアプリから返答できます。

ヘルプの文言を直す

動き方

  1. ラベルを付ける

    issueに agent:ready か agent:plan を付けます。

  2. 端末が実行する

    担当の端末のエージェントが、issueごとのworktreeで claude -p を動かします。

  3. 質問で止まる

    質問はissueのコメントになり、agent:waiting と通知が届きます。

  4. 受信箱で返す

    CLI、ブラウザ、アプリのどこから返答しても、同じissueで実行が再開します。

  5. PRになる

    検証を通したブランチをpushし、draftのPR/MRを作ります。受信箱からマージできます。

主な機能

計画を先に立てる

実装の前に質問と計画をコメントし、/ok の返答で承認してから実装します。

両フォージを横断

GitHubとGitLab（セルフホストを含む）の待ちを、1つの一覧に古い順で並べます。

複数の端末

プロジェクトごとに担当の端末を決めます。2台が同じissueを重ねて実行することはありません。

直す実行

CIの失敗、pushの拒否、baseとの衝突を見つけると、同じPRで直す実行を自動で始めます。

通知とアプリ

待ちと完了をTelegramとAndroidのプッシュ通知で知らせます。計画は通知から承認できます。

実行の制御

同時に動かす数、順番待ち、利用上限での一時停止、APIの費用の上限を設定できます。

安全のための前提

  • issueから読んだ文字列はデータとして扱います。指示として採るのは trusted_authors のコメントだけです。
  • claude にはフォージの資格情報を渡しません。push、PRの作成、コメントはエージェントが行います。
  • 実行のシェルのコマンドはsandboxで動き、書き込めるのはworktreeだけで、ネットワークには出られません。
  • 端末は受信ポートを開きません。例外は受信箱のWeb表示で、LANのアドレスに限ります。
  • 中継が配るのはissueのIDとイベントの種類だけで、本文とトークンは持ちません。

前提と制約

作者1人の環境で作り、確かめてきました。使う前に、次の前提に合うかを確かめてください。

  • 利用者は1人です。対象は非公開のリポジトリで、エージェントも既定では自分のアカウントで投稿します。
  • 端末はLinuxで、systemd、Secret Service、bubblewrap、socat が要ります。macOSでは確かめていません。
  • 受信箱のWeb表示は利用者を認証しません。LANの中だけで使います。
  • GitHubはgithub.comだけに対応します。GitHub.comのwebhookは中継に届かないので、ポーリングで扱います。
  • 配布するバイナリは無く、ソースから作ります。Androidのアプリは、自分のFirebaseのプロジェクトで作ります。
  • 画面の文言は日本語だけです。

はじめ方

Go 1.24以上、Node.js 24、pnpm 12、Claude Code CLIを入れてから、クローンして作ります。

git clone https://github.com/uskanda/switchboard.git && cd switchboard
make install
mkdir -p ~/.config/switchboard && cp config/switchboard.example.yaml ~/.config/switchboard/config.yaml
switchboard doctor
switchboard labels sync
switchboard agent run

トークンの登録、常駐、中継、通知、Web表示の設置は 運用ガイド にあります。
